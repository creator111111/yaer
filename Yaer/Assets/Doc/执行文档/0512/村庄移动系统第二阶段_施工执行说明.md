## 1. 本阶段要做什么（任务卡原文归纳）

| 范围 | 说明 |
|------|------|
| **对接移动动画** | 仅按 **W/S（纵深 Y）** 移动时，也应能进入与横移一致的**跑步/走路**表现 |

## 2. 硬性约束（不做项 — 合入前自检）

| 禁止 | 执行口径 |
|------|----------|
| **禁止重构整个移动系统** | 不在 `MoveComponent` 内堆村庄主逻辑；不替换整套 Player 移动管线 |
| **禁止修改输入系统** | 不改编 `InputActions` 资源、键位映射表、指令队列模型；**纵深仍由 `TownPlayerLocomotion` 内 `Input.GetAxisRaw("Vertical")` 读取**。若必须扩展「是否算移动」的判定，优先改 **Home 脚本状态机 Idle 分支**或 Animator 条件，**慎动** `PlayerInputComponent`（避免被认定为「改输入系统」） |
| **禁止修改剧情系统** | 不碰 `StoryComponentGSM`、NodeCanvas 驱动链 |
| **禁止新增复杂状态机** | 不新建 `PlayerHomeSM` 级状态机；仅允许在现有 `HomeIdleState` / `HomeBinkState` 等增加**极小条件**（例如村庄模式下根据纵深速度切 `HomeWalkState`） |

## 3. 架构快照（施工员必读）

### 3.1 坐标与组件分工（与 `02_SYSTEM_SPEC.md` 一致）

- 村庄 **纵深 = 世界 Y**；根 **Z** 进村冻结；`Rigidbody2D` + 2D 物理。
- **`TownPlayerLocomotion`**：纵深惯性、摩擦、Clamp、写回 `Rigidbody2D.position.y` 与根 `transform`，并与 `MoveComponent` 协调 `velocity.y` / `moveSpeedY`（见脚本内注释及迁移方案 §3.5）。

### 3.2 进村门控（单一事实来源：场景名）

- **`PlayerLogic.SetVillageExplorationMode(bool)`**：切 `PlayerInputComponent` 的 `LocomotionMode`，并调用 `TownPlayerLocomotion.ApplyVillageMode`。
- **`PlayerLogic.RefreshVillageExplorationFromActiveScene()`**：`SceneManager.GetActiveScene().name == SceneName.Village_KenMuNi1` 时启用村庄规则；在 **`LoadingSceneEndHandle`** 与 **`PlayerLogic` 初始化**中均有调用，**换场后**会重绑模式。

### 3.3 动画断层（第二阶段核心问题之一）

- **`TownPlayerLocomotion.SyncWalkAnimatorParameter`**（`Update`）：已用 `|moveSpeedX| + |depthVelocity|` 与死区驱动 **`animator.SetBool("Walk", …)`**。
- **`PlayerInputComponent.HasMoveInput()`**：当前**仅**识别 `Left` / `Right`，**不**含 Vertical。因此纯 W/S 时 **`HomeIdleState`** 往往**不会**切到 **`HomeWalkState`**（该态 `Enter` 会 `SetWalkSpeed()`、驱动脚步音效等），易出现「Animator 参数与脚本状态机/音效不一致」。

**施工结论**：除核对 Animator 过渡条件外，需在 **不大改状态机** 前提下，让纯纵深也能进 **`HomeWalkState`** 或等价表现（见下文 §5.2）。

## 5. 推荐施工顺序（与任务卡验收强相关）

### 5.1 第一步：Y 轴边界（对应「策划可自定义移动范围」+ AC-05）

**目标**：Prefab 上 `depthYMinWorld` / `depthYMaxWorld` 仅作兜底；**进入 `Village_KenMuNi1` 后**必须用场景或配置写入真实可走带。

**建议实现（任选其一，保持薄侵入）**：

1. **场景标尺**：在 `Village_KenMuNi1` 放两个空物体（如 `VillageDepthY_Min` / `VillageDepthY_Max`），策划只调其世界 **Y**。加载完成后由 **`PlayerLogic.SetVillageExplorationMode(true)`** 或 **`RefreshVillageExplorationFromActiveScene`** 路径中查找并调用 **`TownPlayerLocomotion.SetDepthYBounds(minY, maxY)`**（若 `min > max` 已有交换逻辑，见 `SetDepthYBounds` 实现）。
2. **ScriptableObject**：每村一对 `minY/maxY`，场景挂引用，同样在进村时注入。

**注意**：`ApplyVillageMode(true)` 会用当前边界 Clamp 初始 `_villageWorldY`；注入边界的调用顺序建议在 **`ApplyVillageMode` 之后**再 `SetDepthYBounds` 一次，或保证一次调用内边界已是最新（以实机为准，避免首帧穿出）。

**验证**：拖动场景边界物体，角色不可越界；`Assets/Scripts/Debug/VillageMovementInputDebug.cs` 日志中的 `YBounds` / `authY` 与策划摆放一致。

---

### 5.2 第二步：移动动画（对应「上下移动也可跑步动画」）

**建议子顺序**：

1. **Animator 取证**：Home 控制器中 **`Walk` bool** 是否足以进入跑步/走路 Blend；是否还依赖 **Speed** 等参数。
2. **参数与死区**：微调 `TownPlayerLocomotion` 的 **`walkAnimatorDeadZone`**，使纯纵深达到阈值后 `Walk == true`。
3. **状态机对齐（推荐主路径）**：在 **`HomeIdleState` / `HomeBinkState`**（`Assets/Scripts/Game/GameRuntime/Entities/Player/Components/CsAnimator/Home/`）中，当 **`LocomotionMode == Village2_5D`** 且纵深速度超过小死区时，`ChangeState<HomeWalkState>()`，使 **`SetWalkSpeed()`**、脚步逻辑与横移一致。**不新增状态机文件**。
4. **备选（需主程确认）**：扩展 **`HasMoveInput()`** 在村庄下识别 Vertical —— 可能与「禁止修改输入系统」冲突，**默认不采用**。

---

### 5.3 第三步：移动手感

在边界与动画正确后，由策划在 Inspector 调：

- `depthAcceleration`、`depthMaxSpeed`、`depthFriction`、`verticalInputScale`（均在 `TownPlayerLocomotion`）。

避免在边界未注入时把「顶边滑不动」误判为手感 bug。

## 8. 风险与回归（合入前自测）

| 风险 | 自测建议 |
|------|----------|
| 边界未注入与场景可走带不一致 | 顶边「按 W 无效」、穿帮；用日志 `CLAMP_AT_YMAX` 等提示排查 |
| `Walk` bool 与 Home 子状态机冲突 | 纯横移、纯纵深、斜向各测 30 秒；对话中是否误触（不在本任务扩展剧情） |
| `MoveComponent` 与纵深 Y 写入顺序 | 快速左右 + W/S 交替，无单帧弹出边界 |
| `GroundLayerMask` / 落地 | 迁移方案 §3.3、AC-07；改 Y 边界后复测脚底检测 |
