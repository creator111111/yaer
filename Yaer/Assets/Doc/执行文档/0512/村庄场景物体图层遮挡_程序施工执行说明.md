## 1. 村庄「移动方式」摘要（与遮挡任务的关系）

以下结论来自 `02_SYSTEM_SPEC.md` 与当前实现 **`TownPlayerLocomotion`**，是任务卡中「比较玩家 Y 与场景物体 Y」的**语义基础**。

| 要点 | 说明 |
|------|------|
| **纵深轴** | 村庄探索模式（`PlayerLocomotionMode.Village2_5D`）下，**纵深 = 世界坐标 Y**；**禁止**把纵深主位移写到世界 **Z**（规范 §1）。 |
| **驱动方式** | **W/S（Vertical）** → `TownPlayerLocomotion` 在 **`FixedUpdate`** 内对权威纵深 **`_villageWorldY`** 做惯性积分 → **`WriteRootTransformWithAuthoritativeDepthY()`** 写回 **`Rigidbody2D`**；可走区可由 **`PolygonCollider2D`**（WalkArea）几何修正（第三阶段文档）。 |
| **横向** | **A/D** 仍走既有 **`PlayerMoveComponent` / `MoveComponent`** 与 Home 状态机链路。 |
| **动画契约** | 村庄下 **`TownPlayerLocomotion` 只同步 Animator 上的 `Walk`（若存在）**，**不得**每帧写 **`Run`**，否则会与 Combat 的 `CombatRunState` 抢参导致状态机与 `IsName` 错位卡死（`02_SYSTEM_SPEC` §4、`TownPlayerLocomotion.SyncWalkMotionBoolIfPresent` 注释）。 |
| **玩家渲染排序（已有）** | 村庄模式下，若 Inspector 配置了 **`spriteForDepthSort`**，则 **`OnUpdate`** 中调用 **`ApplyDepthSortingFromWorldPosition()`**：按 **`spriteForDepthSort.transform.position.y`** 计算 **`sortingOrder`**，规则与 **`DepthComponent`** 一致（Y 越低 → order 越高，越靠前）。**当前实现未切换玩家的 Sorting Layer 名称**。 |

**任务卡增量**：除 `sortingOrder` 外，希望场景物体在 **`Default`** 与 **`SceneObject`** 等 **Sorting Layer** 间切换，使「玩家在物体后 / 前」的遮挡关系符合 DNF 式观感；并允许在**本任务新增脚本**上配置**判定锚点**（用于与玩家比较前后关系）。

## 2. 现状溯源（代码与资源）

### 2.1 玩家侧（村庄）

| 位置 | 职责（与遮挡相关） |
|------|---------------------|
| `Assets/Scripts/Game/GameRuntime/Entities/Player/Components/TownPlayerLocomotion.cs` | 纵深移动、Walk 同步、**可选** `spriteForDepthSort` 的 **`sortingOrder`** 刷新（**不**改 Sorting Layer）。 |
| `PlayerLogic.SetVillageExplorationMode` | 进村/离村时开关村庄模式、WalkArea 绑定等入口（详见二/三阶段执行说明）。 |

### 2.2 场景物体侧（通用）

| 位置 | 职责（与遮挡相关） |
|------|---------------------|
| `Assets/Scripts/Game/GameRuntime/Entities/Component/Physics/DepthComponent.cs` | 每 **`Update`** 用 **`transform.position.y`** 更新挂载对象的 **`SpriteRenderer.sortingOrder`**；若 **`isLower` / `isUpper`** 为真则走固定大偏移分支。`Init` 里将 **`LayerID`** 设为 **`SceneObject_Other`** ——此处为 **Unity 物理 Layer**，**不是** Sprite 的 **Sorting Layer**。 |
| `Assets/Scripts/Game/GameRuntime/GameSceneManager/SubManager/DepthManager.cs` | 分层注册逻辑**大量注释**，运行时**未启用** `UpdateLayer()`；**不要假设**依赖它即可完成 Sorting Layer 切换。 |
| `Assets/Scripts/Game/Static/Name/Settings/LayerName.cs` | 字符串常量：`SceneObject`、`SceneObject_Other` 等，多用于 **Layer** 或逻辑命名；**Sorting Layer 名称**以 **`ProjectSettings/TagManager.asset`** 为准。 |
| `ProjectSettings/TagManager.asset` → `m_SortingLayers` | 顺序（节选）：**`Default` → … → `Player` → … → `SceneObject`**。同一 **`sortingOrder`** 下，**列表中靠后的 Sorting Layer 会绘制在更上层**（Unity 规则）。因此任务卡所述「`Default` 在玩家后、`SceneObject` 在玩家前」与当前表顺序**方向一致**，但仍须在目标相机上做一次**实机验证**（同层多 Sprite 时以 Order 再细分）。 |

### 2.3 与任务卡的差距

- 任务卡要求：**动态切换目标的 Sorting Layer**（`Default` ↔ `SceneObject`）+ 可选 **Sorting Order** 微调 + **脚本内可配锚点**。
- 现状：**玩家**在村庄内可能仅改 **Order**；**场景物体**常见为 **`DepthComponent` 只改 Order**，**未**按「相对玩家 Y」切换 **Sorting Layer**。

## 3. 目标行为与验收建议（对齐任务卡）

| ID | 验收项 | 建议通过条件 |
|----|--------|----------------|
| OC-01 | 纵深语义 | 前后判定使用的 **玩家 Y** 与 **物体锚点 Y** 均为**世界 Y**（与村庄纵深一致），**不把 Z 当纵深主比较量**。 |
| OC-02 | 遮挡正确性 | 玩家在物体「后方」（按策划定义的锚点比较）时，物体视觉上**遮挡**玩家；移到「前方」时玩家**盖住**物体。 |
| OC-03 | Sorting Layer | 状态切换时 **`SpriteRenderer.sortingLayerName`**（或 ID）在 **`Default`** 与 **`SceneObject`**（或团队书面约定的等价层）之间变化，且**不引入** UI/特效层误切。 |
| OC-04 | 策划可配 | **每个场景物体**可在 Inspector 配置 **锚点 Transform**（或本地偏移）；缺省时可用物体根或 **`DepthComponent` 的 foot 碰撞盒中心**等明确回退策略（须在脚本注释中写明）。 |
| OC-05 | 村庄回归 | 进村/出村、纯 A/D、纯 W/S、斜向移动、WalkArea 边界：**无新增卡死、无输入/剧情回归问题**（见下文禁止项）。 |
| OC-06 | 性能 | 物体数量大时避免 **O(n²)** 全图扫描；优先 **触发器 / 距离剔除 / 注册表**（实现阶段由施工员选型并在 PR 说明）。 |

## 4. 推荐施工顺序（最小侵入）

以下顺序满足 `00_MASTER_PROMPT`：**先可运行、小步合入、每次说明文件与验证步骤**。

1. **新建**场景物体侧组件（建议名由团队定，例如 `VillageSceneObjectDepthSort`）：序列化字段包括 **目标 `SpriteRenderer`（可多选时列表）**、**前后判定用 `Transform` 锚点**、**玩家引用获取方式**（`GameObject.FindGameObjectWithTag("Player")` / 单例 / 由场景管理器注入 —— **禁止**在 `Update` 里无缓存地全场景 `Find`）。  
2. **每帧或固定频率**读取 **玩家比较点 Y**（建议与 `TownPlayerLocomotion` / `spriteForDepthSort` 的采样策略对齐，例如玩家 **`Rigidbody2D.position.y`** 或 **`spriteForDepthSort.transform.position.y`**，**二选一写死并在注释说明原因**）与 **物体锚点世界 Y**。  
3. 根据 **`playerY` vs `anchorY`** 设置 **`sortingLayerName`**（及必要时 **`sortingOrder`** 常量偏移），避免与 **`DepthComponent` 每帧写 Order** **双写打架**：  
   - **推荐**：该物体**不挂 `DepthComponent`**，或 **`DepthComponent` 禁用**后改由新脚本统一管理；  
   - **次选**：改 **`DepthComponent`** 增加「外部托管」开关（**触及共用组件**，PR 与回归面更大）。  
4. **仅村庄场景启用**：用 **`PlayerInputComponent.LocomotionMode == Village2_5D`** 或 **`SceneManager.GetActiveScene().name`** 与任务约定场景名一致时启用逻辑，避免战斗场景误切层。  
5. 策划摆场景：在 **`Default` / `SceneObject`** 上配置若干测试桶、栅栏，**截图 + 日志标签**（如 `[VillageOcclusion]`）验收 OC-01～05。

## 5. 边界：哪些代码**可以改**、哪些**禁止改**（执行口径）

### 5.1 鼓励修改 / 新增（首选战场）

| 范围 | 说明 |
|------|------|
| **新建脚本** | 专责「玩家—物体 Y 比较 → 切换 `SpriteRenderer` 的 Sorting Layer / Order」的组件；**锚点 SerializeField**、`Tooltip`、**详细注释**写清比较点与回退策略。 |
| **新建或任务相关 Prefab / 场景** | 为测试物体挂载新脚本、配置锚点与子渲染器；**不**强制改玩家 Prefab。 |
| **项目内常量** | 若需避免魔法字符串，可在 **`LayerName` 旁新增 `SortingLayerName` 静态类**（仅常量，不改运行逻辑）— **须与 `TagManager` 中名称一字不差**。 |

### 5.2 谨慎修改（需充分理由 + 回归清单）

| 范围 | 说明 |
|------|------|
| **`TownPlayerLocomotion.cs`** | 若必须统一「玩家用于遮挡比较的 Y」，可**极小**扩展（例如公开只读 **比较用世界 Y** 或可选 **锚点 Transform**）；**禁止**在此加入大量遮挡业务、**禁止**引入 **`Run`** 写入、**禁止**改动纵深积分与 WalkArea 主流程结构。 |
| **`DepthComponent.cs`** | 仅当多数物体需共用逻辑时考虑；改动会影响**非村庄**物体表现，**回归面大**。优先 **新组件 + 单物体禁用 DepthComponent** 替代。 |
| **`PlayerLogic.cs` / `MoveComponent` 系** | 非遮挡任务必要**不要**改；避免与重力、`Velocity.y` 协调再次冲突（迁移方案 §3.5）。 |

### 5.3 禁止修改（与 `02_SYSTEM_SPEC`、二/三阶段执行说明一致）

| 禁止项 | 原因 / 口径 |
|--------|-------------|
| **输入系统** | 不改 `InputActions`、键位映射、指令队列结构（三阶段 §2）。 |
| **剧情与 NodeCanvas 驱动链** | 不私自加 `isTalking` 等锁；剧情须走 **`StoryComponentGSM.TriggerStory`** 等既有契约（规范 §2）。 |
| **村庄纵深改 Z** | 规范 §1：村庄位移**不用 Z 作主纵深**。 |
| **在 `TownPlayerLocomotion` 或村庄脚本中写 `Run`** | 规范 §4.2：与 Combat 抢参 → 状态机卡死。 |
| **整体重写移动 / NavMesh 替换 `Rigidbody2D` 村庄管线** | 与已定「方案 C + WalkArea」冲突。 |
| **`DepthManager` 大规模启用未评审逻辑** | 当前多为注释代码；贸然开启需全场景深度回归。 |
| **用固定 `Wait` 对齐摄像机** | 规范 §3：须用 **`CameraComponent.SetFollow`** 与回调衔接。 |

### 5.4 架构侦探阶段说明

- 若当前迭代角色为 **【架构侦探】**：**只产出**本类文档与索引，**不提交** gameplay 代码变更。  
- 转 **【施工员】** 后再按 §4 实施，并遵守 `00_MASTER_PROMPT` 的提交说明与 `OPEN_QUESTIONS` 记录原则。

## 6. 替代方案说明（文档级）

| 方案 | 适用 | 缺点 / 风险 |
|------|------|-------------|
| **A. 新脚本只切 Sorting Layer，Order 固定** | 任务卡明确要 Layer 切换 | 同层多个物体仍需 Order 微调；与 `DepthComponent` 并存时需协调。 |
| **B. 仅调 `sortingOrder`、不切 Layer** | 物体始终与玩家同层 | **不满足**任务卡「Default / SceneObject」明确要求。 |
| **C. Material / Shader 透明度** | 特殊艺术效果 | 成本高、易与 URP/批处理冲突；非首选项。 |
| **D. 子节点「视觉 Y」与刚体 Y 分离** | 跳跃与排序需解耦（迁移方案 §3.6） | 村庄若未开跳跃，通常**不必**为上遮挡任务引入。 |
