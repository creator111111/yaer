## 1. 需求摘要（任务卡 → 工程语义）

任务卡要求实现 **DepthZone**：当 **玩家脚点（player foot）** 进入不同区域时：

1. **自动切换玩家 Sprite 的 Sorting Layer**（树屋前后景、楼梯上下层表现）。
2. 玩家**不在**任何特殊深度区域时，恢复默认 Sorting Layer：**`Player`**（与 `TagManager` 中 Sprite Sorting Layers 顺序一致即可）。
3. **硬约束**：**禁止修改玩家移动脚本**；**禁止修改场景里「变化图层」的既有脚本**（与村庄遮挡文档中的 `VillageSceneObjectDepthSort` 等已有实现解耦）。

**与 `02_SYSTEM_SPEC.md` 的对齐要点**：

- 村庄探索下 **纵深 = 世界坐标 Y**，**Rigidbody2D**、`Gravity Scale = 0`；纵深位移由 `TownPlayerLocomotion` 等链路维护（规范 §1）。
- **动画契约**：村庄侧 **`Walk` 独占补充**，**禁止**在村庄脚本中每帧抢写 **`Run`**（规范 §4），本任务若新增「每帧逻辑」须避免堆在无关 `Update` 里驱动动画参数。

**与《村庄探索…遮挡与障碍》的关系**：

| 维度       | 已有技术文档侧重                                                                       | 本任务卡侧重                                                      |
| -------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| **改谁**   | 场景物体 `SpriteRenderer`：`Default` ↔ `SceneObject`（`VillageSceneObjectDepthSort`） | **玩家自身** `SpriteRenderer`：进入区域后切到策划指定层，离开特殊区回 **`Player`**  |
| **判定**   | 玩家 Y vs 物体**锚点** Y（每帧或等价刷新）                                                    | **触发器区域** + **脚点** 进入/离开（事件驱动为主）                            |
| **纵深阻挡** | `TownPlayerLocomotion` + `VillageWalkObstacle` + `PlayerFoot` Cast             | 本任务**不要求**改该链路；楼梯「层」若需物理挡位，应复用 Walk 区内障碍策略，**不要**为表现单独改移动脚本 |

结论：**场景遮挡脚本**解决「物与物、物与玩家」的 **Y 比较排序**；**DepthZone** 解决「策划划定体积内，**玩家整体贴图层级**切换」——二者可并存，但必须约定**谁写玩家的 `sortingLayerName`**，避免双写（见 §4）。

## 2. 现状溯源：玩家 Sorting 相关代码入口

以下路径便于【施工员】定位，**不在此任务中擅自改动移动脚本**的前提下阅读契约。

| 路径 | 与 DepthZone 的关系 |
|------|---------------------|
| `TownPlayerLocomotion.cs` | 村庄模式下对 **`spriteForDepthSort`** 调用 **`ApplyDepthSortingFromWorldPosition()`**，按世界 **Y** 刷新 **`sortingOrder`**；**当前实现不切换 `sortingLayerName`**（见技术文档 §3 与遮挡执行说明）。 |
| `SortingLayerName.cs` | 当前常量仅有 **`Default`**、**SceneObject`**；任务卡默认层名为 **`Player`**，**常量类中尚无 `Player` 字符串封装**——施工时要么**扩展常量类并与 TagManager 一致**，要么在新脚本内使用与 `TagManager` 完全一致的字面量并在注释中写明依据。 |
| `VillageSceneObjectDepthSort.cs` | **场景物体**在村庄模式下切换 Sorting Layer；任务卡**禁止修改**此类「场景变化图层」脚本，DepthZone 应**新建脚本**，通过组件引用或事件驱动玩家渲染体，而非改该类源码。 |
| `DepthComponent.cs` | 主要改 **`sortingOrder`**，且与 `VillageSceneObjectDepthSort` **同开可能打架**（技术文档 §3.2）；与**玩家** DepthZone 的冲突面较小，但若策划把同一 Renderer 又挂深度排序组件，需个案排除。 |
| `LayerName.PlayerFoot` / `VillageWalkObstacle` | **物理 Layer**（非 Sorting Layer）；脚点检测可用 **PlayerFoot** 层上的 **Collider2D** 进入 **Trigger**，与障碍碰撞文档中的「脚点」语义一致，便于和现有 Prefab 对齐。 |

**重要逻辑链（不写代码，只记结论）**：

- 玩家「被画在第几层」在现有村庄链路里，**Order 已由纵深 Y 驱动**；任务卡新增的是 **`Sorting Layer` 名称**在 **区域规则**下的覆盖。
- 若 DepthZone 在区域内把玩家切到某层，**`TownPlayerLocomotion` 仍可能每帧写 `sortingOrder`**：通常**不冲突**（Layer 与 Order 正交），但若未来有人在移动脚本里扩展写 Layer，会与此任务**冲突**——故任务卡禁止改移动脚本是合理隔离。

## 3. DepthZone 推荐架构（满足「两禁止」）

以下为满足任务卡约束的**推荐拆分**；具体类名由施工 PR 决定。

### 3.1 组件职责

| 组件（建议新建） | 职责 |
|------------------|------|
| **`VillagePlayerDepthZone`**（挂载在体积上） | 带 **`Collider2D.isTrigger = true`**；配置 **目标 `SortingLayerName`**（或枚举映射到 `TagManager` 合法名）；可选 **优先级**（多区重叠时谁生效）。 |
| **`VillagePlayerDepthZoneListener`**（可选，挂在玩家根或表现根） | **仅当任务卡允许「非移动脚本」的玩家侧组件时**使用：缓存 **`SpriteRenderer[]`** 或策划指定的身体 Renderer；提供 **`SetDepthZoneOverride(layer, priority)`** / **`ClearOverride(zoneId)`** API，由 Zone **发消息**或 **Find** 一次后缓存引用调用。**若策划坚持玩家零脚本**，则 Zone 侧通过 `OnTriggerEnter2D` 直接 `GetComponentInParent<PlayerLogic>()` 再向下找 Renderer（注意性能：进入离开事件内执行，禁止每帧全树查找）。 |

**脚点判定**：与任务卡一致，以 **`PlayerFoot` 物理层** 上的碰撞体进入 Trigger 为准（与 `村庄探索_场景遮挡与Walk区内障碍碰撞.md` 中脚点语义一致）；**不要用**未约定的 Tag 硬编码，除非与 Prefab 现状统一。

### 3.2 进入 / 离开与「回到 Player」

1. **进入**：记录「当前生效区」；若新区 **优先级 ≥** 旧区，则切换玩家目标 Sorting Layer。
2. **离开**：从栈或集合移除该区；若集合为空，将玩家 Sorting Layer **恢复为 `Player`**（及可选：恢复进入村庄前缓存的 `sortingOrder` 基准——**仅当**施工方案曾改过 Order 时才需要；默认只恢复 Layer 即可）。
3. **多区嵌套**：必须用 **优先级 + 栈** 或 **「取最高优先级区域」** 的确定性规则，并在 Inspector 注释中写清，避免楼梯与树屋门口重叠时闪烁。

### 3.3 仅村庄模式生效

与 `VillageSceneObjectDepthSort` 一致：建议仅在 **`PlayerInputComponent.LocomotionMode == Village2_5D`**（或项目统一的「村庄探索」判定）下应用 Zone 覆盖；离开模式时**恢复**进入前的 Layer（避免战斗/家里误切层）。

## 4. 与现有系统的冲突与协作矩阵

| 风险 | 说明 | 缓解 |
|------|------|------|
| **双写 Sorting Layer** | Zone 改玩家 Layer，移动或其它脚本若未来也改 Layer | 本任务不改移动脚本；新增 Zone 独占「Layer 覆盖」语义，并在文档/代码注释声明**唯一写口** |
| **双写 sortingOrder** | `TownPlayerLocomotion` 持续按 Y 写 Order | **保留**其行为；Zone **只改 Layer**；若楼梯需要「同层内再微调 Order」再在 Zone 上增加可选 Order 偏移字段，并评估与 Y 排序的合成公式 |
| **与 `VillageSceneObjectDepthSort` 观感打架** | 物体在 `SceneObject`，玩家被 Zone 切到更前/更后 | 属**策划摆关与层顺序表**问题：以 `TagManager` 中 Sorting Layers **全局顺序**为准做验收表，不在代码里硬猜 |
| **Trigger 与物理步** | `OnTriggerEnter2D` 可能在同一 FixedUpdate 多次或顺序不稳定 | 使用 **优先级** 与 **惰性应用**（Enter/Exit 后统一算一次目标 Layer），避免一帧内抖动 |

## 5. 任务卡「禁止」条款的执行解读

| 条款 | 架构解读 |
|------|----------|
| **禁止修改玩家的移动脚本** | **`TownPlayerLocomotion`、`MoveComponent`、输入驱动的位移状态机相关文件**均不得为 DepthZone 打补丁。脚点检测应发生在 **Zone 的 Trigger 回调**或**独立非移动**组件中。 |
| **禁止修改场景里的变化图层脚本** | **`VillageSceneObjectDepthSort` 等已用于「场景物体图层」的脚本**不改源码；DepthZone **新建文件**实现玩家侧需求。若必须复用工具方法，优先 **复制小工具到新建静态类** 或 **委托给通用模块**（评估重复度后再提取，避免大范围重构）。 |

**替代方案说明（文档级）**：

| 方案                         | 优点                  | 缺点                                                                 |
| -------------------------- | ------------------- | ------------------------------------------------------------------ |
| **A. 纯 Trigger Zone（推荐）**  | 与任务卡「区域检测」一致；不改移动代码 | 体积需策划仔细摆；嵌套要优先级规则                                                  |

## 6. 验收清单（建议 PR / 自测）

| ID | 项 | 通过条件 |
|----|-----|----------|
| DZ-01 | 默认层 | 无特殊区时，玩家主体 Sprite 的 **`sortingLayerName == Player`**（与 `TagManager` 一致） |
| DZ-02 | 进入切换 | 脚点（**PlayerFoot** Collider）进入 Zone A 后，Layer 变为配置值；离开且无其它区时回 **`Player`** |
| DZ-03 | 嵌套 / 重叠 | 多区重叠时行为符合配置的 **优先级** 规则，无单帧来回切换 |
| DZ-04 | 模式隔离 | **非 `Village2_5D`** 时不应用 Zone，或立即恢复入村前缓存，无战斗场景误切 |
| DZ-05 | 规范回归 | 进村 **A/D、W/S、斜向** 无新增卡死；**无人**在村庄链路每帧写 **`Run`**（`02_SYSTEM_SPEC` §4） |
| DZ-06 | 与遮挡文档一致 | 场景物体仍由 **`VillageSceneObjectDepthSort`** 等既有脚本驱动；本任务**未改**这些脚本源码 |

**建议日志标签**（供【验收员】）：`[VillageDepthZone]`，在 Layer 实际发生变化时打印（可开关），避免刷屏。

## 7. 待澄清问题（建议写入 `Docs/OPEN_QUESTIONS.md` 若尚无定论）

1. **玩家多个 `SpriteRenderer`**（头发、披风、武器）：是「全部切层」还是「仅 `animaSr` / `spriteForDepthSort`」？须策划书面列表。答：全部切层统一管理
2. **`Player` Sorting Layer 在 `SortingLayerName` 是否收录**：便于全工程统一字符串，避免拼写错误。答：就是Player
3. **楼梯「上层」是否需要 `VillageWalkObstacle` 几何**：若需要挡纵深，应走技术文档 §4，**独立摆关**，不倒逼修改 `TownPlayerLocomotion` 外禁止文件。答：不需要
