# 场景切换与对话触发跳转 — 架构溯源报告

**文档性质**：架构/策划向逻辑定位说明，供程序排查与对齐设计；**不包含代码修改方案**，仅描述现有调用链与已观察到的配置事实。

**关联问题背景**：序章 `WestRappRoad` 流程结束后，预期进入「村庄/下一区域」场景时未发生跳转。本文档汇总换场核心类、对话侧如何触发换场、以及与本场景相关的预制体与场景文件观察结论。

---

## 1. 场景跳转总览（程序员速查）

```
[业务入口：门 / UI / NodeCanvas 对话节点 / GM 流程]
        │
        ▼
LoadSceneComponentGSM.LoadScene(sceneName, stayAction, blackFade)
        │  黑幕 FadeShow → onShowEnd 内：OnExitScene + OnShutDown
        ▼
ChangeSceneComponentGM.LoadScene(LoadSceneArgs)
        │  非 InitScene：先 UnloadScene(当前)，回调里 LoadScene(目标)
        ▼
GameFramework SceneComponent.LoadScene(资源路径, userData)
```

- **游戏内统一入口（含黑幕）**：`LoadSceneComponentGSM`  
- **全局场景名与卸载顺序**：`ChangeSceneComponentGM`  
- **底层加载**：`GameFramework.UnityRuntime.Scene.SceneComponent`（通过 `GameManager.GetGFComponent<SceneComponent>()`）

## 2. 核心类与职责

### 2.1 `LoadSceneComponentGSM`

| 项目 | 说明 |
|------|------|
| **路径** | `Assets/Scripts/Game/GameRuntime/GameSceneManager/Component/LoadSceneComponentGSM.cs` |
| **职责** | 触发 `onStartLoadingSceneEvent`；可选打开 `BlackPanel`；黑幕完全显示后执行 `stayAction`；调用当前 `IGameSceneManager` 的 `OnExitScene` / `OnShutDown`；订阅 `GameManager.Instance.onGameSceneManagerReady` 以在新场景 `BaseGameSceneManager` 就绪后执行 `OnSceneManagerInit`、`OnBlackFadeEnd`（后者会触发 `onEndLoadingSceneEvent`）；最终调用 `ChangeSceneComponentGM.LoadScene(new LoadSceneArgs { sceneName = ... })`。 |
| **对外 API** | `LoadScene(string sceneName, Action stayAction = null, bool blackFade = true)` |

### 2.2 `ChangeSceneComponentGM`

| 项目 | 说明 |
|------|------|
| **路径** | `Assets/Scripts/Game/GameMgr/Component/ChangeScene/ChangeSceneComponentGM.cs` |
| **职责** | 维护 `NowSceneName`、`LastSceneName`；监听 GF 的 `LoadSceneSuccessEventArgs` / `UnloadSceneSuccessEventArgs` 执行回调；在「非 InitScene」路径下先卸载当前场景再加载目标场景。 |
| **对外 API** | `LoadScene(LoadSceneArgs args)` |

### 2.3 `BaseGameSceneManager` 与各场景 Manager

| 项目 | 说明 |
|------|------|
| **路径** | `Assets/Scripts/Game/GameRuntime/GameSceneManager/Base/BaseGameSceneManager.cs` |
| **职责** | 挂载并初始化各 `BaseComponentGSM` 模块（含 `LoadSceneComponentGSM`、`MapControlComponentGSM`、`StoryComponentGSM` 等）。 |
| **序章场景** | `WestRappRoadSceneMgr`：`Assets/Scripts/Game/GameRuntime/GameSceneManager/Scene/WestRappRoad/WestRappRoadSceneMgr.cs` — 主要做 `SetNowPlace(SceneName.WestRappRoad)` 与退出时虫子实体回收等，**未发现**在此处直接调用换场 API。 |

### 2.4 场景内交互门：`SceneChangeDoor`

| 项目 | 说明 |
|------|------|
| **路径** | `Assets/Scripts/Game/GameRuntime/Entities/SceneEntities/CommonEntity/SceneChangeDoor.cs` |
| **职责** | 通过 `InteractiveComponent` 的点击或进入事件调用 `SceneManager.GetModule<LoadSceneComponentGSM>().LoadScene(NextSceneName, ...)`；可选 `ShowLoadingUI` 先打开 Loading 再无黑幕换场。 |
| **注意** | `NextSceneName` 为空时 `EnterDoor` 会打错误日志；`CheckNextSceneUnlock` 可拦截是否允许进入。 |

### 2.5 地图与门的解锁条件：`MapControlComponentGSM`

| 项目 | 说明 |
|------|------|
| **路径** | `Assets/Scripts/Game/GameRuntime/GameSceneManager/Component/MapControlComponentGSM.cs` |
| **职责** | `SetSceneUnlockCondition(Func<bool> left, Func<bool> right)` 分别赋给 `Map.LeftDoor` / `Map.RightDoor` 的 `CheckNextSceneUnlock`。 |
| **引用示例** | `HomeScene1Manager` 中调用了 `SetSceneUnlockCondition`；**`WestRappRoadSceneMgr` 中未发现**对该 API 的调用。 |

## 3. 对话系统如何「拉起」场景跳转

### 3.1 进入对话：`StoryComponentGSM.TriggerStory`

| 项目 | 说明 |
|------|------|
| **路径** | `Assets/Scripts/Game/GameRuntime/GameSceneManager/Component/StoryComponentGSM.cs` |
| **关键方法** | `TriggerStory(string storyPrefabName, bool ignoreCurrentRunningStory = false)` |
| **行为** | 通过 `ResComponentGM.LoadAsset` 加载 `DialoguePath` 下的对话预制体；打开或复用 `NormalDialogueNewPanel`，在回调中调用 `NormalDialogueFormNewLogic.StartDialogue(go)`。 |

**序章 Boss 战后触发对话的代码位置**（供对照存档/时间线）：

- **文件**：`Assets/Scripts/Game/GameRuntime/Entities/SceneEntities/StoryTrigger/WestRappRoadBattleStory.cs`
- **调用**：`BattleStoryStartOrEnd(false)` 分支内 `TriggerStory("WestRappRoadAfterKillBoss")`。

### 3.2 对话 UI 结束：不自动换场景

| 项目 | 说明 |
|------|------|
| **路径** | `Assets/Scripts/Game/GameRuntime/UI/FormLogic/Story/NormalDialogueFormNewLogic.cs` |
| **关键逻辑** | `OnDialogueEnd` 中调用 `StoryComponentGSM.OnStoryEnd()`、`dialogueTree.PauseDialogue()`、`CloseForm()`。**此处没有**调用 `LoadSceneComponentGSM` 或 `ChangeSceneComponentGM`。 |

**结论**：若期望「某段对话播完自动进下一场景」，必须在 **NodeCanvas 对话图** 中显式配置动作节点，或由其他系统（门、触发器、Procedure 等）在对话结束后接续。

### 3.3 对话图内执行换场：`LoadSceneTaskAction`

| 项目 | 说明 |
|------|------|
| **路径** | `Assets/Scripts/Game/GameRuntime/NodeCanvas/NodeCanvasNode/ActionTask/Common/LoadSceneTaskAction.cs` |
| **编辑器显示名** | 「加载场景」（`[Name("加载场景")]`） |
| **关键行为** | `OnExecute` 内取得 `GameManager.GetGameSceneManager().GetModule<LoadSceneComponentGSM>()`，根据 `EndActionOnFinishLoad` 决定是否在加载完成回调中 `EndAction()`。 |
| **参数** | `SceneName`（字符串，应与 `SceneAssetPath` / 资源侧场景名一致，常引用 `SceneName` 常量中的值）。 |

**参考预制体**（证明项目内已采用该模式）：

- `Assets/GameRes/Prefabs/Dialogue/NewGameStory.prefab` 的序列化图中包含 `$type":"Game.GameRuntime.Story.Node.LoadSceneTaskAction"`，且带有 `SceneName` 字段（例如 `HomeScene1`）。

### 3.4 对话图内仅链式开下一段剧情：`TriggerStoryActionTask`

| 项目 | 说明 |
|------|------|
| **路径** | `Assets/Scripts/Game/GameRuntime/NodeCanvas/NodeCanvasNode/ActionTask/Common/TriggerStoryActionTask.cs` |
| **行为** | 延迟后调用 `StoryComponentGSM.TriggerStory(StoryPrefabName.value, true)`，**不执行场景加载**。 |

## 4. 场景名常量（脚本层）

**文件**：`Assets/Scripts/Game/Static/Name/Res/SceneName.cs`

与「城郊 / 拉普路西 / 东郊」等相关的常量包括：

- `ForestScene` — 注释为「龙城郊」
- `ForestEastScene` — 注释为「龙城东郊」
- `WestRappRoad` — 「拉普路西」

**说明**：资源目录中存在 `Village_KenMuNi`、`Village_KenMuNi1` 等 Unity 场景文件，但 **`SceneName.cs` 中未列出** 与精灵村场景同名的常量；若换场目标为该类场景，程序需核对 `SceneAssetPath` 与资源实际命名是否一致。

## 5. `WestRappRoad` 专项观察（与「打完序章未进村」相关）

### 5.1 对话预制体 `WestRappRoadAfterKillBoss`

| 项目 | 说明 |
|------|------|
| **路径** | `Assets/GameRes/Prefabs/Dialogue/WestRappRoadAfterKillBoss.prefab` |
| **观察** | 在预制体 YAML 的 `_boundGraphSerialization`（NodeCanvas DialogueTree JSON）中检索 **`LoadSceneTaskAction` / `ForestScene` / `Village`**：**未发现** `LoadSceneTaskAction` 节点。对话图末尾存在 `FightingPanelVisibleActionTask` 等节点，**从序列化内容看，该段对话结束本身不会触发 `LoadSceneComponentGSM.LoadScene`**。 |

### 5.2 场景 `WestRappRoad.unity` 中的门配置（事实摘录）

以下为从场景 YAML 中读到的配置意图，便于程序在 Editor 中交叉验证：

| 物体 | 与换场相关的事实 |
|------|------------------|
| **LeftDoor** | `SceneChangeDoor` 上 `NextSceneName: ForestEastScene`，`TriggerWhenMoveIn: 1`。 |
| **RightDoor** | 同一脚本所在 `MonoBehaviour` 记录为 **`m_Enabled: 0`（组件禁用）**；**`NextSceneName` 为空字符串**。 |

**解读提示**：若设计为「Boss 战后从右侧进入村庄/下一关」，需要程序或策划确认：右侧门是否应在某事件后启用并赋值目标场景名；当前仓库内 **`WestRappRoadSceneMgr` 未调用 `MapControlComponentGSM.SetSceneUnlockCondition`**，与 `HomeScene1` 等场景的门控用法不一致。

### 5.3 其他换场入口（同项目内，便于对比）

- **其他对话**：`GoOutMapStoryLogic` 等处直接调用 `LoadSceneComponentGSM.LoadScene(SceneName.ForestScene)`（路径见工程内 `GoOutMapStoryLogic.cs`）。

## 6. 给程序员的排查清单（建议顺序）

1. **确认设计意图**：序章结束后应进入的场景资源名（`ForestScene` / `Village_KenMuNi` / 其他）及是否必须「无操作自动跳转」或「走门/触发器」。  
2. **对话图**：在编辑器中打开 `WestRappRoadAfterKillBoss`，检查是否缺少「加载场景」节点，或 `EndActionOnFinishLoad` 与后续节点衔接是否正确。  
3. **场景门**：在 `WestRappRoad.unity` 中核对 **RightDoor** 的 `SceneChangeDoor` 是否应在某存档字段或 Boss 战后启用，并填写 `NextSceneName`。  
4. **常量与路径**：若目标场景不在 `SceneName` 中，核对 `SceneAssetPath.GetSceneAssetPath` 与 GF 资源表是否已注册该场景。  
5. **日志**：`StoryComponentGSM.OnStoryPrefabLoad` 在资源为 null 时会 `Log.Error`，可辅助判断对话预制体是否加载失败。

## 7. 策划需求补充：`ButtonJingLingVillage` 直跳 `Village_KenMuNi1` 场景

### 7.1 UI 层级（与 Hierarchy 对齐）

| 层级 | 说明 |
|------|------|
| `Canvas` → `UI` → `UI Form Instances` → `UI Group - Top` | 与工程 UI 分组一致。 |
| **`MapPanel(Clone)`** | 世界地图界面根实例。 |
| **`Places` / `ButtonJingLingVillage`** | 地图上的地点按钮容器；**`ButtonJingLingVillage`** 为精灵城线入口按钮（名称须与代码常量一致，见下）。 |

### 7.2 策划需求（目标行为）

1. **触发**：玩家在 **`MapPanel`** 上点击 **`ButtonJingLingVillage`**（`Places` 下该 GameObject）。  
2. **结果**：**直接进入 Unity 场景 `Village_KenMuNi1`**（场景资源文件名/逻辑名以 **`Village_KenMuNi1`** 为准，与 `Assets/GameRes/Scenes/` 下实际 `.unity` 资源一致）。  
3. **语义**：**「点击即换场」** — 不要求先播完某段地图专有对话再换场；若当前流程为先黑幕再 `TriggerStory`，与本需求不一致时，**以实现本策划条为准**（直跳场景）。  
4. **换场通道**：与本文第 1～2 节一致，应走 **`LoadSceneComponentGSM.LoadScene("Village_KenMuNi1", ...)`**（或经 `SceneName` / `SceneAssetPath` 封装后的等价调用），由 **`ChangeSceneComponentGM`** 完成卸载与加载；**不在**本节强制规定是否保留黑幕，由程序与演出统一，但**终点必须是加载 `Village_KenMuNi1`**。  
5. **资源与常量**：`SceneName.cs` 当前**未**声明 `Village_KenMuNi1`；程序需 **在常量表或资源表中登记** 该场景名，并确认 **GF 场景资源路径** 可解析到 `Village_KenMuNi1`，否则换场会失败。

### 7.3 现状对照（便于改需求时 diff）

| 项目 | 说明 |
|------|------|
| **脚本** | `Assets/Scripts/Game/GameRuntime/UI/FormLogic/Map/MapFormLogic.cs` |
| **按钮名常量** | `JingLingVillageButtonName = "ButtonJingLingVillage"`（与 Hierarchy 中对象名一致）。 |
| **当前实现（事实）** | `OnSelectJingLingVillage()`：先开 **`BlackPanel`** 黑幕，淡出结束后 **`TryStartJingLingVillageStartDialogue()`** → `StoryComponentGSM.TriggerStory("Village_KenMuNiStart")`，即 **拉起对话预制体 `Village_KenMuNiStart`，不调用 `LoadScene("Village_KenMuNi1")`**。 |
| **与策划条差异** | 现状为 **黑幕 + 对话入口**；策划本条要求 **点击后直接换场至 `Village_KenMuNi1`**。若保留黑幕仅作转场，仍须在黑幕后执行 **`LoadScene`**，而非仅 `TriggerStory`（除非对话图内自行配置 `LoadSceneTaskAction` 且能稳定落到 `Village_KenMuNi1`，与本条「点击即直达场景」的表述不一致时需策划再确认）。 |

### 7.4 验收要点（程序自测）

- [ ] 点击 **`ButtonJingLingVillage`** 后，最终进入的场景为 **`Village_KenMuNi1`**（`SceneManager`/存档中的当前场景名与预期一致）。  
- [ ] 无资源缺失报错；若经黑幕，黑幕结束后不应停留在仅对话、未换场的状态（除非策划书面改为「对话内再跳」）。  
- [ ] 与 `MapFormLogic` 中 **`jingLingVillageBlackTransitionInProgress`** 等防连点逻辑不冲突、不卡死输入。
