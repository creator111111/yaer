## 2. 现状架构（定位用）

### 2.1 场景管理器如何挂上 `GameManager`

- 每个可玩场景根层通常有名为 **`SceneManager`** 的物体，挂载 **`BaseGameSceneManager` 子类**。
- `BaseGameSceneManager` 在 **`Awake` → `OnInit()`** 中完成模块注册与业务初始化；首帧异步就绪后在 **`Update`** 里调用 **`GameManager.Instance.OnGameSceneManagerReady(this)`**，此后全局通过 **`GameManager.GetGameSceneManager()`** 取当前管理器。
- **参考代码路径**：`Assets/Scripts/Game/GameRuntime/GameSceneManager/Base/BaseGameSceneManager.cs`（`Awake` / `OnInit` / `OnGameSceneManagerReady` 调用处）。

### 2.2 `Village_KenMuNi1` 当前事实

- 场景文件：`Assets/GameRes/Scenes/Village_KenMuNi1.unity`。
- 根物体 **`SceneManager`** 当前挂载脚本为 **`ForestSceneManager`**（与 `ForestScene` 共用同一脚本 GUID）。
- `ForestSceneManager.OnInit` 内写死 **`nowSceneName = SceneName.ForestScene`**、**`SetNowPlace(PlaceName.HomeToJingLingVillage)`**，因此在本村存档时，存档标题仍显示「龙城郊」对应字典项。
- **`SceneManager`** 上引用的 **`GameSceneManagerConfig`** 当前为 **`Assets/GameRes/Config/SceneManagerConfig/ForestScene.asset`**（与森林场景共用配置属现状，是否拆分为独立 `.asset` 由程序按风险自定；**非**任务卡硬性要求）。

### 2.3 存档标题数据链（禁止改存档系统前提下）

- 保存时：`ArchiveComponentGM` 使用 **`PlayerMapData.GetNowPlace()`** 写入 **`ArchiveInfo.currentSceneName`**（任务卡要求**不要改**这一段）。
- 读档 UI：`ButtonArchive` 使用 **`PlaceName.GetPlaceChsName(存档中的 currentSceneName)`** 显示地名。
- 因此：只要在进入 `Village_KenMuNi1` 时由**新** SceneManager 调用 **`SetNowPlace(新内部键)`**，并在 **`PlaceName`** 三语字典注册该键 → 即可达成「肯尼姆」显示，**无需**动存档组件代码。

### 2.4 新脚本建议路径（与任务卡一致）

- 目录：`Assets/Scripts/Game/GameRuntime/GameSceneManager/Scene/Village_KenMuNi/`（若不存在则新建）。
- 类名建议：`Village_KenMuNiSceneManager`（命名空间与文件组织可参考 `Scene/Forest/`、`Scene/Home1/`）。

### 2.5 仿照对象：`ForestSceneManager`

- **路径**：`Assets/Scripts/Game/GameRuntime/GameSceneManager/Scene/Forest/ForestSceneManager.cs`
- 新类应复用其**业务含义**（`ForestSceneData`、莱/林恩等实体显隐、BGM/SFX 子节点、`OnOpenFightingPanel` 等与该村场景内容物一致的部分），避免进村后剧情 / 音效逻辑回退。
- **必须差异化**的两点（相对森林原脚本逻辑）：
  1. **`nowSceneName`**：应设为 **`SceneName.Village_KenMuNi1`**（与 `SceneName.cs` 常量一致），避免逻辑上仍自报为 `ForestScene`。
  2. **`SetNowPlace(...)`**：改为任务约定的新内部键（见 §3），并在 `PlaceName` 注册中文 **「肯尼姆」** 及英 / 日。

## 3. `PlaceName` 与内部键约定

- **路径**：`Assets/Scripts/Game/Static/Enum/Map/PlaceName.cs`
- **工作**：新增 **`public const string`**（内部键字符串需稳定、唯一，建议与现有 `Home` / `HomeToJingLingVillage` 风格一致，例如 `KenMuNi` 或 `VillageKenMuNi`，由程序最终命名并在三处字典同时注册）。
- **三语字典**：`PlaceChsName`、`PlaceChsName_en`、`PlaceChsName_jp` 各增加一行 **key = 新常量**，中文 value 为 **「肯尼姆」**，英 / 日由文案提供或占位后交给策划替换。

**替代方案说明**：若坚持用「与 Unity 场景名相同」的字符串作 key（如 `Village_KenMuNi1`），也可行，但需与 `SceneName.Village_KenMuNi1` 常量区分职责（场景名 vs 地点键），避免后续表维护混淆；推荐单独地点键常量。

## 4. Unity 场景操作（必做）

1. 打开 `Assets/GameRes/Scenes/Village_KenMuNi1.unity`。
2. 选中 **`SceneManager`** 物体。
3. **移除**组件 **`ForestSceneManager`**，**添加**组件 **`Village_KenMuNiSceneManager`**。
4. **重新绑定**原 `ForestSceneManager` 上已配置的序列化字段（尤其 **`config`**、`EnterPosConfig`、`curStoryPrefab`、各类 bool 等），保证与换组件前一致，避免运行时 `config == null` 警告或进场景失败。
5. 保存场景。

## 5. 依赖与风险排雷（与任务卡「禁止改无关代码」的边界）

### 5.1 `ForestSceneLinEnStory` 与 `FindObjectOfType<ForestSceneManager>`

- **路径**：`Assets/Scripts/Game/GameRuntime/Entities/SceneEntities/ForestScene/ForestSceneLinEnStory.cs`
- **事实**：`Village_KenMuNi1.unity` 中存在 **`LinEnStory`** 等仍挂载该脚本；其中 **`OnCameraMoveEnd`** 流程里使用 **`FindObjectOfType<ForestSceneManager>()`** 获取根物体上的 `SoundToggleComponent`。
- **风险**：`SceneManager` 不再挂 `ForestSceneManager` 后，上述查找可能为 **null**，存在 **NRE** 或 BGM/SFX 切换失效。
- **建议（请主程与任务卡「禁止」条款对齐后选一条）**：
  - **方案 A（推荐）**：将该处查找改为 **`GameManager.GetGameSceneManager()`** 或 **`FindObjectOfType<BaseGameSceneManager>()`** 等非 `ForestSceneManager` 特化类型（改动文件为 **Entity 剧情脚本**，不是「原有 SceneManager 脚本」）。  
  - **方案 B**：若产品确认该村流程**永不触发**该分支，可暂不改，但需在测试用例中明确覆盖「林恩门口剧情完成 + 镜头移动结束」路径并承担风险。

**本节目的**：避免仅换 SceneManager 组件后出现隐蔽运行时错误；**不属于**存档系统修改。

### 5.2 其他 `ForestSceneManager` 特化引用

- 工程内 **`ForestSceneManager`** 字符串级引用除上述外，主要集中在 **`ForestSceneManager.cs` 自身**与 **Editor**（`ForestSceMgrInspector`）。新村管理器一般**不需要**动 Editor；若需自定义 Inspector，可另增 `Village_KenMuNi` 下 Editor 类（可选，非验收必需）。
