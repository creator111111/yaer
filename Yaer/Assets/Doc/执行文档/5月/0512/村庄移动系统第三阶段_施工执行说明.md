## 1. 本阶段要做什么（任务卡原文归纳）

| 范围 | 说明 |
|------|------|
| **Y 轴边界细节** | 村庄道路因房屋等不连续，仅靠两条全局 Y 边界不足；改为由**平面多边形**统一约束 **X + Y**（与当前 2D 刚体坐标一致） |
| **Village WalkArea 基础版** | 引入可策划配置的「可走区」数据载体；首版以 **Unity `PolygonCollider2D`** 为权威几何 |
| **区域外不可达** | 玩家位置（或用于判定的参考点）须**始终落在多边形内**（或边界上，按实现约定） |
| **不规则边界** | 多边形顶点由策划在编辑器中拖拽调整，无需代码改数 |
| **架构兼容** | **保持**现有 **`Rigidbody2D`** 管线、**不修改**输入系统与剧情系统、**保持**现有村庄纵深与 Home 动画对接方式（二阶段已打通部分） |

## 3. 架构快照（与二阶段衔接）

### 3.1 坐标与当前行为

- 村庄探索下：**纵深语义 = 世界 Y**；根 **Z** 冻结；**水平**仍主要由现有 **`Rigidbody2D` + `PlayerMoveComponent`** 驱动。
- **`TownPlayerLocomotion`**：每 **`FixedUpdate`** 对权威纵深 **`_villageWorldY`** 积分后做 **标量 Clamp**（`depthYMinWorld` / `depthYMaxWorld`），再 **`WriteRootTransformWithAuthoritativeDepthY()`** 写回刚体与 Transform。
- **`PlayerLogic.SetVillageExplorationMode(true)`**：切换 `LocomotionMode`、调用 `ApplyVillageMode`，并执行 **`TryInjectVillageDepthYBoundsFromSceneMarkers`**（仅当场景名为 `Village_KenMuNi1` 且存在两个命名空物体时注入 **Y 区间**）。

### 3.2 本阶段引入 Polygon 后的目标关系（设计意图）

| 层级 | 建议关系 |
|------|----------|
| **几何权威** | 场景中 **一块**（或按文档后续扩展多块）**`PolygonCollider2D`** 表示「可走多边形」；策划只调顶点 |
| **与旧 Y 标尺** | **`VillageDepthY_Min` / `Max` 可与 Polygon 并存或逐步废弃**：若 Polygon 启用，则 **最终合法位置应以「点在多边形内」为准**；全局 Y Clamp 可保留为**兜底**（例如防止数值异常穿出），或改为从 Polygon 包围盒推导 —— **具体取舍须在开发前写入本节或 OPEN_QUESTIONS，避免双源冲突** |
| **约束时机** | 在 **`Rigidbody2D.position`（及权威 Y）被更新之后**，或在积分步内「预测位置 → 修正」二选一；须与 **`WriteRootTransformWithAuthoritativeDepthY`** 顺序一致，避免单帧穿出 |

### 3.3 动画与输入（保持兼容）

- **`TownPlayerLocomotion.SyncWalkAnimatorParameter`**、**`HasVillageDepthMoveForHomeStateMachine`** 等二阶段链路**不因 Polygon 替换而拆除**；Polygon 只改变**允许到达的 (x, y)** 集合，不改变「如何读 W/S 与横移」。
- 若约束后角色在边界附近**反复微振**，优先用**几何修正算法**（例如沿法线回推、最近点投影）减小抖动，而非改 Animator 状态机结构。

## 4. 场景与资源规范（策划向 · WalkArea）

以下规范供施工落地时统一命名与层级，便于代码「按约定查找」或 Inspector 引用。

### 4.1 推荐场景对象结构（示例）

- 在 **`Village_KenMuNi1`**（或任务指定的村庄场景）根或统一父节点下放置空物体，例如：**`VillageWalkArea_Root`**。
- 其子物体挂 **`PolygonCollider2D`**：
  - **建议命名**：`VillageWalkArea`（或团队约定的唯一名称；若多块区域，采用编号 `VillageWalkArea_01` 等，并在执行说明或 OPEN_QUESTIONS 中约定**首版仅支持单 Polygon**）。
  - **`isTrigger`**：通常设为 **`true`**，避免与玩家刚体产生**非预期的物理挤压**；约束由脚本完成，而非依赖碰撞解析把玩家「顶回」。
  - **Layer**：使用**不与战斗逻辑冲突**的层（例如专用 `VillageWalkArea` 层），并在代码中 **`Physics2D.IgnoreLayerCollision`** 或与玩家 Layer 矩阵事先调好，避免阻挡普攻检测等（以项目现有 Layer 表为准）。

### 4.2 多边形编辑要点

- 顶点顺序须构成**简单多边形**（不自交）；Unity 编辑器中可直观检查。
- **可走区** = 多边形**内部**（含边界实现时须与 `Physics2D` 的 `OverlapPoint` / `Collider2D.OverlapPoint` 边界行为一致，并在验收中写明）。
- **与道路美术对齐**：多边形略小于可视路缘时可减少「贴图已出界但碰撞仍在内」的争议；略大时可减少「看起来能走却被挡」——由策划与程序试玩共同定稿。

### 4.3 与二阶段标尺的关系（合入前必须二选一写清）

| 策略 | 说明 |
|------|------|
| **A. Polygon 优先** | 启用 WalkArea 时，**位置约束以 Polygon 为准**；`VillageDepthY_Min/Max` 仅作备用或不再放置 |
| **B. 双重约束** | 同时满足 **点在 Polygon 内** 且 **Y 在 [min,max]**（更严）；适用于希望先保留纵向条带再裁切不规则区域的情况 |

默认建议：**策略 A**，单一事实来源，减少策划误配。

## 5. 推荐施工顺序（与任务卡验收强相关）

### 5.1 第一步：WalkArea 数据接入（无行为或只读调试）

- 在进村路径（与二阶段相同：**`PlayerLogic.SetVillageExplorationMode(true)` 之后**）或 `TownPlayerLocomotion` 初始化中，**解析场景中的 `PolygonCollider2D`**（按命名或 Serialized 引用绑定）。
- 可选：在 **`VillageMovementInputDebug`** 或同类脚本中打印 **「当前位置是否在多边形内」**、最近边界距离，便于策划摆场景。

### 5.2 第二步：位置约束算法（核心）

**目标**：每物理步结束时，**玩家参考点**（建议与现有写回刚体使用的点一致，例如 **`Rigidbody2D.position`** 或角色脚底参考点）满足 **`PolygonCollider2D.OverlapPoint`**（或等价判定）。

**常见实现思路（施工时选其一，须写注释说明取舍）**：

1. **事后修正（推荐首版）**：在现有位置积分与纵深写回之后，若 `OverlapPoint == false`，将位置**投影到多边形内最近点**（`Collider2D.ClosestPoint` 对**多边形外**点返回边界上最近点，可再沿法线微量内推 ε 避免数值落在边外）。
2. **分轴修正**：先限制 X 再 Y 或反之，可能在凹多边形**失败**；**不规则区域优先用「最近点投影」或一次性二维修正**。
3. **与纵深积分合并**：在同一 `FixedUpdate` 内先算「理想位移」，再整体 Clamp 到多边形内，减少一帧穿出。

**注意**：若仍保留 **`depthYMinWorld` / `depthYMaxWorld`**，须在代码注释与本文档中说明**与 Polygon 的先后顺序**（先 Y 后 Polygon，或先 Polygon 后 Y）。

### 5.3 第三步：横移与纵深联合边界

- **横移（X）** 与 **纵深（Y）** 在村庄模式下共同受多边形限制时，可能出现「斜向沿边滑动」；属预期行为。
- **禁止**在 `Update` 内堆砌大量业务；约束逻辑放在 **`FixedUpdate`** 或与现有 `TownPlayerLocomotion` 同步的步进中。

### 5.4 第四步：回归与动画

- 复测 **纯 A/D、纯 W/S、斜向、边界摩擦** 各 30 秒；确认 **Home Walk / Idle** 与二阶段行为一致且无新增卡死。
- 若使用 **`ClosestPoint`**，注意 **刚体与 Polygon 同物体或父子** 时的边界情况（避免自我引用错误 Collider）。

### 5.5 第五步：文档与 OPEN_QUESTIONS

- 若存在「多块 Polygon」「楼梯伪纵深」等未决需求，写入项目约定的 **`OPEN_QUESTIONS.md`**（或 `Assets/Doc` 下等价文件），**不擅自扩展范围**。

## 8. 风险与回归（合入前自测）

| 风险 | 自测建议 |
|------|----------|
| **双边界源冲突** | Polygon 与 `VillageDepthY_Min/Max` 同时存在时，角色在「条带内但多边形外」或反之的行为是否符合策划预期 |
| **Trigger 与 Layer** | 与敌人、机关、对话触发器是否误触发；Layer 矩阵逐项核对 |
| **凹多边形 + 最近点** | 凹角附近快速移动是否偶发一帧穿出；必要时加二次 `OverlapPoint` 校验 |
| **性能** | 单场景单 Polygon 通常可忽略；若未来多 Collider，需评估每 FixedUpdate 调用次数 |
| **物理顺序** | `MoveComponent` / 其他系统在 `FixedUpdate` 中与写回 Y 的顺序是否与 Polygon 修正一致 |

## 9. 替代方案说明（文档级 — 不默认采用）

| 方案 | 适用 | 缺点 |
|------|------|------|
| **纯碰撞体阻挡（非 Trigger）** | 希望完全靠物理阻挡 | 易与现有 2D 移动、挤推、战斗层冲突；与「保持 Rigidbody2D 架构、薄约束」目标易打架 |
| **NavMesh / Tilemap** | 大地图寻路 | 超出本任务「基础 WalkArea + Polygon」范围，重构面大 |
| **ScriptableObject 存顶点表** | 需版本化、多场景复用 | 策划工作流不如直接在 Scene 里拖 Polygon 直观；可作为 **Phase 3+** 导出工具链 |
