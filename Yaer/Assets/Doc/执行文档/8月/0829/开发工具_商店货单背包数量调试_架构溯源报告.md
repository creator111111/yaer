# 开发工具 · 商店货单背包数量调试 — 架构溯源报告

**文档版本**：v1.0（2026-08-29）  
**文档性质**：【架构侦探】只读溯源 + 方案拍板（**本阶段未改代码 / Prefab / 存档**）  
**Unity**：2020.3.48f1  
**产品目标**：Editor 工具按 **商店货单** 清理 / 设定背包持有量，覆盖空包可买、堆满拒买、差 1 件等购买验收  
**样板**：`Tools/Debug/Player Gold Tool…`（Play 门禁 · Save · 即时刷新）  
**反例**：`Tools/MainItem/一键添加全部主道具`（全 `EMainItemName`，**过宽**，不作本期主工具）  
**关联**：`ShopFormLogic` 堆叠预检 · `GetShopBuy/SellCandidates` · 购买 Yes/No（堆叠失败 **不**播 No）

---

## ① 结论一句话

**货单真源 = `MainItemDefProvider.GetShopBuyCandidates` ∪ `GetShopSellCandidates`（磁盘现约 Buy 8 + Sell 3；以 API 动态枚举为准，勿写死）。拍板 W1：`Tools/Debug/Shop Bag Quantity Tool…` EditorWindow；列表限商店候选；「设为 N」语义；现网无 `SetMainItemCount`——推荐在 `PlayerBagData` 补最小 Set（或 Util 内 delta=Add/Remove）；清空仅 Candidates；`MaxStackPerItem=10`；每次改后 `SaveSpcData<PlayerBagData>`；禁止用「一键全部主道具」冒充清店货。**

---

## ② 原因（通俗）

测「包满了买不了」「空包能买」得精确拧某一瓶药的数量，不能一把把全图鉴塞满。  
商店货单已经写在 Database 过滤里，调试窗只要认这张单子，就不会误清任务专属剑/项链之类。

---

## ③ 用户怎么清 / 设数量测商店（施工后）

| # | 操作 | 通过 |
|---|------|------|
| 1 | Play（InitScene 有存档）→ **`Tools / Debug / Shop Bag Quantity Tool…`** | 列出商店货，显示当前持有 |
| 2 | **清空商店货** | Candidates 内数量全 0；任务非上架道具仍在 |
| 3 | 某消耗品目标填 **10** → 应用 → 店内再买该物 | **堆叠失败**（Log）；**不**播「没钱」ShopNo |
| 4 | 该物设 **0**，Gold 够买 1（旁路可关）→ 决定 | 入包成功 / 可播 Yes |
| 5 | 设 **9** 再买 1 成功、买 2 失败 | 对齐 Max=10 |
| 6 | 未 Play | 不能改档 |

钱仍用 Gold 工具；本窗 **不管金币**。

### B. 背包读写 API

| API | 有无 | 备注 |
|-----|------|------|
| `GetMainItemCount` | ✅ | |
| `AddMainItem` | ✅ | 累加并钳 `MaxStackPerItem`；经 DefProvider 补 Icon |
| `TryRemoveMainItem` | ✅ | 不足失败；减到 0 会 Remove 键 + 调 index/快捷栏 |
| **`SetMainItemCount` / 设为 N** | ❌ **无** | **须补**或 Util 拼装 |
| `MaxStackPerItem` | ✅ **= 10** | 与商店堆叠预检一致 |
| `SaveSpcData<PlayerBagData>` | ✅ | **必须**每次应用/清空/全满后调（注意：现网「一键全部主道具」**未 Save**——本期勿学） |
| `OnDataChange` | ✅ | `DataChanged` 末尾 Invoke；但 **`IsCanUse` 早退**时材料可能不播事件 |
| 贵重物品 UI | `MenuFormProxy.UpdateItemPage` | **不**自动订 `OnDataChange`；开着菜单须 **主动** `UpdateItemPage`（P1） |

`ShopFormLogic.TryValidateBuyStackLimits`：`held + qty > MaxStackPerItem` → 整单失败、只 Log、**不播 ShopNo**。

### D. 「设为 N」算法拍板

| 规则 | 决议 |
|------|------|
| 语义 | 持有量 **正好 = N**（非再 +N） |
| N&lt;0 | 拒绝或当 0 |
| N&gt;Max | **钳到 Max + Log**（对齐 AddMainItem） |
| N=0 | 清槽（走 Remove，避免幽灵键） |
| 未持有 → N&gt;0 | `AddMainItem`（保证 Icon/Def） |

**实现比选**

| 方案 | 做法 | 倾向 |
|------|------|------|
| **S1 · `PlayerBagData.SetMainItemCount`** | 中枢：clamp → 0 则 Remove 全量；否则 delta Add/Remove 或存在则改 `num`+DataChanged | **✅ 推荐**（商店/任务以后也可复用；快捷栏走现网 Remove/Add） |
| S2 · 仅 Editor Util 拼装 | delta=`target-current`；&gt;0 Add；&lt;0 TryRemove；=0 Remove 全量 | ✅ 亦可（最小不碰运行时 API）；须详细注释 index 风险 |
| S3 · Remove 全量再 Add N | 实现简单 | ⚠️ 易打乱 index/快捷栏；次选 |

推荐伪代码（S1 或 S2 等价）：

```
target = Clamp(N, 0, MaxStack)
cur = GetMainItemCount(id)
if target == cur: return
if target == 0: TryRemoveMainItem(id, cur)
else if cur == 0: AddMainItem(id, target)
else if target > cur: AddMainItem(id, target - cur)
else: TryRemoveMainItem(id, cur - target)
SaveSpcData<PlayerBagData>()
可选：Find MenuFormProxy?.UpdateItemPage()
```

**清空商店货**：对并集每个 ID `Set(0)` 或 `TryRemove(held)`，再 **一次** Save。  
**全满**：对并集 `Set(MaxStack)`（P1）。

**禁止**：清空范围扩到全 `EMainItemName`；清金币；只改内存不 Save。
