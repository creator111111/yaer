## ① 结论一句话

**斜向变快就是两台发动机同时踩满、中间没有「合速度归一」：Combat 把左右灌到跑速 11.2，Town 把前后灌到纵深上限 5.5，写回时又把两轴原样叠到画面上，斜着走大约 12.5，比只按 D 还快一截、比只按 W 快一倍多。** 不是卡死、不是点 A 走反、也不是锚点。推荐 **方案 A**：只在村庄 Town 的 FixedUpdate **一处**，按约定目标走速做输入归一（或等价的平面合速度夹紧），让纯横、纯纵、斜向的地面欧氏速度一致。

## ② 原因（生活类比）

村里其实是两台车拼在一起。左右那台是战斗「跑步发动机」（`SetRunSpeed`，油门钉死 11.2）；前后那台是「纵深发动机」（`depthVelocity`，油门上限 5.5）。方向盘打斜时，两台都当自己是唯一司机，各自踩满。画面上人走的是两台速度的斜边，当然比单开一台更快。

只按 W/S 时，村里有一条旧规矩（0513）：**不许左右那台点火**（`villageDepthOnly` 跳过 `SetRunSpeed`，并 `StopMoveInX`）。所以纯前后不会叠横向。一旦同时按了 A/D，这条规矩关掉，两台一起满油 → 就是现在的斜向加速。

村里没有交警把「地面时速」限成同一个数：全仓库村庄位移路径上，**没有**对 `(横向速度, 纵深速度)` 做 `ClampMagnitude` / `normalized`。`WriteRootTransformWithAuthoritativeDepthY` 写权威 Y 时还**故意保留**刚体的 `velocity.x`，只清 `velocity.y`（防和重力抢轴）。两轴位移在空间上合成，从不互相打折。

## ③ 用户需要做什么

先拍两块板，再让施工员改。侦探施工默认写在 OPEN，你若不同意就改 OPEN。

### 必须拍板

| # | 问题 | 侦探建议（施工默认） | 你若改 |
|---|------|----------------------|--------|
| T1 | 「一样快」是 **八向同速**（纯 D、纯 W、D+W 三段欧氏距离接近），还是只要 **斜向不超过较快那根轴**（纯 W 仍可比纯 D 慢）？ | **八向同速**（对齐你说的「纯横、纯纵、斜向都要一样」） | 若只想「斜向别再比左右更快」，可改方案 B，纵深满速维持 5.5 |
| T2 | 目标走速用哪个数？ | **新字段** `villagePlanarMoveSpeed`，初值 **11.2**（抄现网 `runSpeed`，左右手感不变；纯 W/S 会变快） | 若怕纵深冲出 WalkArea，改初值 **5.5**（左右会变慢）或给一个中间数 |
| T3 | 村民家室内要不要同期改合速度？ | **本期不改**。家里场景名不是 `Village_KenMuNi1`，Town **关着**，没有纵深发动机，斜向叠加根本不会发生 | 若以后屋里也开 2.5D，再复用同一套 Town 公式 |

### 不要做的事

- 不要把 Prefab 里的 `runSpeed` 和 `depthMaxSpeed` 改成同一个数就当修完——斜向仍会是 \(\sqrt{2}\) 倍。
- 不要为了限速，斜向时再走 `villageDepthOnly` 把 X 清掉（斜着就不能左右了）。
- 不要回退进村点 A 的 Enter 补丁。
- 不要在 `MoveComponent.OnFixedUpdate` 里全局夹速度（跳跃/击飞会被砍）。

### 施工后验收（村街 `Village_KenMuNi1`，开场对话结束、能走之后）

按住 **足够久**（建议 ≥2 秒，等纵深加速到满速）再比距离；斜向起步那零点几秒加速曲线可以略有差别，比的是满速后的地面路程。

| # | 操作 | 期望 |
|---|------|------|
| 1 | 只按 D，计时 T | 往右位移欧氏长度 ≈ `villagePlanarMoveSpeed * T` |
| 2 | 只按 W，同样 T | 往「前/上」位移欧氏长度与 1 **接近**（允许障碍/WalkArea 截断） |
| 3 | 同时按 D+W，同样 T | 斜向欧氏长度与 1、2 **接近**，**不得**明显快于单轴 |
| 4 | 只按 W/S | 没有横向抽动（0513 不回归） |
| 5 | 先 W/S 再按与朝向同向的 D | 仍能横移（0514 不回归） |
| 6 | 对话后点一下 A | 往左，不能往右滑（0818 不回归） |
| 7 | 斜着走时松掉 W、仍按 D | 应变回「纯左右」满速，不能卡住 |
| 8 | 斜着走时松掉 D、仍按 W | 应变回「纯前后」满速，横向清掉 |
| 9 | Forest 战斗关左右跑、跳 | 与现网一致（合速度夹紧不得进战斗） |
| 10 | 龙宫左右走 | 与现网一致 |

## ④ 给程序看的补充

### 4.1 场景身份（核实）

| 项 | 现网 |
|----|------|
| `Village_KenMuNi1` Config | 复用 `ForestScene.asset`，**`isFightingScene=1`** |
| 动画轨 | **Combat**（`Run`），不是 Home `Walk` |
| `LocomotionMode` | `PlayerLogic.RefreshVillageExplorationFromActiveScene`：场景名是 KenMuNi1 则 **`Village2_5D`**，并 `TownPlayerLocomotion.ApplyVillageMode(true)` |
| 离村 / 进村民家 | 场景名不是 KenMuNi1 → Town **`enabled=false`**，`depthVelocity` 清零 |

禁止为躲这个手感把村街改成 Home，也禁止改 `ForestScene` 的 `isFightingScene`。

### 4.2 两台发动机（数字已对 Prefab）

`Player.prefab`：

| 字段 | 值 | 谁用 |
|------|-----|------|
| `PlayerMoveComponent.runSpeed` | **11.2** | `SetRunSpeed()` → `moveSpeedX = runSpeed * DirectionSign` |
| `PlayerMoveComponent.walkSpeed` | **4.2** | `SetWalkSpeed()`（Home 室内；村街 Combat 不用） |
| `TownPlayerLocomotion.depthMaxSpeed` | **5.5** | 积分后 `Clamp` 纵深速度 |
| `TownPlayerLocomotion.verticalInputScale` | **0.6** | **只乘加速度输入**，不降低满速 |

`SetRunSpeed` / `SetWalkSpeed` **从不读 Vertical**。Town 积分 **从不读 Horizontal**。两套上限独立。

合速度估算（满速、无障碍）：

| 输入 | \(v_x\) | \(v_y\)（纵深） | 地面欧氏 \(\sqrt{v_x^2+v_y^2}\) |
|------|---------|-----------------|----------------------------------|
| 只 D | 11.2 | 0 | **11.2** |
| 只 W | 0 | 5.5 | **5.5** |
| D+W | 11.2 | 5.5 | **≈12.48**（比只 D 快约 11%，比只 W 快约 **2.27 倍**） |

斜向「变怪」的观感，主要来自相对纯 W 的翻倍，而不只是相对纯 D 的那 11%。

### 4.3 斜向何时叠满

`CombatRunState.Enter`：

```csharp
bool village = inputComponent.LocomotionMode == PlayerLocomotionMode.Village2_5D;
bool villageDepthOnly = village && !inputComponent.HasVillageExploreHorizontalMoveIntent();
if (!villageDepthOnly)
{
    if (village)
        ApplyVillageCombatRunEnterHorizontalFromInput(); // 0818 点 A，禁止回退
    else
        moveComponent.SetRunSpeed();
}
```

- **纯 W/S**：`villageDepthOnly==true` → **不** `SetRunSpeed`。`Update` 里若仍按住 Vertical 且无横向意图，再 `StopMoveInX()`（0513）。这条必须保留。
- **斜向（有 A/D）**：`villageDepthOnly==false` → 满 `SetRunSpeed`（11.2）；Town 同时把 `depthVelocity` 积到 5.5。两轴都满。
- **0514** `EnsureVillageCombatRunHorizontalSpeedIfStale`：只在横向速度≈0 时补 `SetRunSpeed`，解决「没速度」。本案是**有速度且过大**，补票不能当限速，也不要删。

`HomeWalkState.Enter` 无条件 `SetWalkSpeed()`（4.2）。预扫担心「家里 walk 4.2 + 纵深 5.5 斜向叠成 ≈6.9」。**核实：村民家场景不会开 Town**，家里没有第二台发动机，本期无斜向叠加。Home 文件 **不必改**。

### 4.4 写回：合而不折

`TownPlayerLocomotion.OnFixedUpdate` 顺序（门控 `enabled && LocomotionMode==Village2_5D`）：

1. 纵深：`depthVelocity += inputDepth * depthAcceleration * dt`，再 `Clamp` 到 `±depthMaxSpeed`
2. `_villageWorldY += depthVelocity * dt`，障碍 / WalkArea 夹 Y
3. `WriteRootTransformWithAuthoritativeDepthY`：刚体 position.y = 权威 Y；**`velocity = (v.x, 0)` 保留横向、清纵向**
4. 稍后 `ApplyVillageWalkObstacleHorizontalVelocityClamp` 只按障碍截 **X**，不做平面合速度

Prefab 里 Town 排在 `PlayerMoveComponent` **之后**：同一 FixedUpdate 先 Move 把 `rb.velocity = (moveSpeedX, …)` 写进去，再 Town 改 Y、保留 x。斜向位移 = 本帧 `vx*dt` 加 `depthVelocity*dt`，几何上就是直角三角形斜边。

村庄路径上仅有的 `.normalized` 是障碍推离 / 分离步长上限，**不是**移动合速度。全 Player 脚本无 `Vector2.ClampMagnitude`。

### 4.5 方案对比与推荐

目标（与产品原文一致）：有移动时，画面单位时间走过的 **世界 XY 平面欧氏长度** 相同。DNF 若故意让纵深更慢，与「不要叠加、保持一样」冲突 → **以开发者口径为准**。

| 方案 | 做法 | 合速度 | 单轴 11.2 vs 5.5 | 风险 | 选用 |
|------|------|--------|------------------|------|------|
| **A 村庄目标走速 + 输入归一** | `Village2_5D` 下把 Horizontal/Vertical 合成 `normalized * villagePlanarMoveSpeed`，再拆给 `moveSpeedX` 与 `depthVelocity` | 最好 | 两轴都接到同一目标 | 要选数字；纵深满速/加速时间会变 | **推荐** |
| B 仅斜向 ClampMagnitude | 双轴都超死区时把 `(vx, depthVel)` clamp 到 `max(\|vx\|, depthMax)` 或固定值 | 斜向不再快于较快轴 | **纯 W 仍 5.5，纯 D 仍 11.2** | 不满足「纯前后和纯左右一样」 | 仅当 T1 改口 |
| C 斜向只打折 X（×0.707） | 有纵深时减 X | 近似椭圆 | 纯 W 仍慢 | 不圆、不对称 | 否 |
| D 纵深改用同一 Move 速度 | Town 不再独立 max | 可 | 大改 0512 架构 | 违背「纵深独立组件」 | 否 |

**推荐方案 A**，不要用 D，不要用「把两个 max 改成一样」冒充修复。

方案 A 的落地（施工员按此，避免两处各打一次折）：

1. **只改一处**：`TownPlayerLocomotion.OnFixedUpdate`，在纵深积分之后、**`_villageWorldY += depthVelocity * dt` 之前**。
2. **门控**：`enabled && LocomotionMode==Village2_5D`（现有 early-return 已满足）。
3. **新字段** `[SerializeField] float villagePlanarMoveSpeed = 11.2f`（名称可微调，语义必须是「村庄地面目标走速」）。旧 Prefab 缺序列化时 Unity 可能写成 0 → **OnInit / ApplyVillageMode 若 ≤0 则回退 11.2**，避免站桩。施工员若改 `Player.prefab`，把该字段写成 11.2。
4. **算法（建议，保惯性）**：
   - 用 `GetAxisRaw("Horizontal")` / `Vertical`（死区 0.01，与现网一致）组成输入向量 `n`。
   - **双轴都有输入**：`n.Normalize()`，`moveSpeedX` 与 `depthVelocity` 直接接到 `n * villagePlanarMoveSpeed`（符号跟输入）。这样斜向欧氏速度 = 目标走速，且不依赖「先灌 11.2 再打折」的次序。
   - **只有横轴**：不改 Combat 灌的 `SetRunSpeed` 方向；把 `|moveSpeedX|` 夹到目标走速（初值 11.2 时等于现网）。纵深走现网摩擦衰减。
   - **只有纵轴**：保持 0513（X 已为 0）；把纵深满速改接到 **目标走速**（不要再被 5.5 卡住，否则纯 W 永远慢于纯 D）。无输入时仍用现网 `depthFriction`。
   - 写回：`move.moveSpeedX = 缩放后的 vx`；`depthVelocity = 缩放后的 vy`；随后积分 Y；`WriteRoot` 时 `rb.velocity = (缩放后的 vx, 0)`，因为 Move 本帧已经把未缩放的 11.2 写进刚体。
5. **不要**在 `CombatRunState.Enter` / `SetRunSpeed` / `MoveComponent.OnFixedUpdate` 再打一次折。0818 的 `ApplyVillageCombatRunEnterHorizontalFromInput` 只负责朝向，合速度缩放必须在它 **之后** 的 Town FixedUpdate。
6. **不要**改 `verticalInputScale` 当限速。它只影响加速快慢。目标走速提到 11.2 后，纯 W 加速到满约 `11.2 / (0.6*28) ≈ 0.67s`（现网约 0.33s）。验收必须按住够久；若体感起步肉，另开任务调 `depthAcceleration`，本期不必动。
7. Animator：`SyncWalkAnimatorParameter` 用 `|vx|+|vy|` 不是欧氏，斜向归一后仍远大于 `walkAnimatorDeadZone`，**本期不必改**。禁止在 Town 里抢写 Combat 的 `Run`。

**惯性期望（写进注释）**：

- 松一轴、另一轴仍按住 → 剩下那轴回到 **单轴满速**（等于目标走速），不能停在斜向分量 0.707 上。
- 双轴都松 → Run 退 Idle 时现网 `StopMove`；纵深摩擦滑行保持现网。
- 斜向贴障被 `HorizontalVelocityClamp` 截 X 后，合速度可以小于目标，这是挡墙不是 Bug。

**方案 A 的替代（若施工时归一和摩擦打架）**：每帧对已积分的 `(moveSpeedX, depthVelocity)` 做 `Vector2.ClampMagnitude(..., villagePlanarMoveSpeed)`，但必须 **先把单轴满速都接到同一目标**（纵深 Clamp 上限改为目标走速，横向在村里不超过目标走速）。否则又退化成方案 B，纯 W 仍 5.5。
