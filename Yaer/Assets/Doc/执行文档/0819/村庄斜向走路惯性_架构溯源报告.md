## ① 结论一句话

**斜着滑的根因没变：Town 双手空不清横向，Combat 又因纵深还在滑而不退 Idle、不踩刹车，vx≈7.92 叠着没磨完的 `depthVelocity`。** 开发者已拍板 **全部立刻停**，所以不能只卸横向：无纵深意图时还要把 `depthVelocity` 当场写成 0，否则纯 W 和「斜着松 W 仍按 D」还会往前后飘。推荐 **方案 A′**（刹车仍只放 Town）。

---

## ② 原因（生活类比）

村里左右本来像卡丁车：松油门立刻停。前后却像溜冰：松 W 还要滑一段（0512 故意留的摩擦）。斜着走时 0818 把油门拆成约 0.707，松手后 **方向盘上的横向没人卸**，再叠上前后还在滑，人就斜着漂。

v1.0 只准备踩横向刹车、前后继续滑。开发者改口：**油门、方向盘松开都立刻停，不要任何滑行。** 所以前后那套摩擦在村街走路里不再当设计，松键就要卸掉。

注意：只让 Combat 退回 Idle（旧方案 C）等于只踩卡丁车的手刹；纵深那台车由 Town 自己积分权威 Y，手刹管不到，人照样往前后滑。必须在 Town 把 `depthVelocity` 清掉。

产品口径已拍死，不用再问「要不要留一点滑」。施工按方案 A′。你这边只验收（村街、能走之后）：

| # | 操作 | 期望 |
|---|------|------|
| 1 | 只按 D，松手 | **立刻停**，无滑步 |

| 5 | **D+W 双手松开** | **立刻停**；不能斜着滑，也不能只剩前后滑 |
| 6 | 斜着走时松 W、仍按 D | 横向回到满速（不能停在 0.707）；**纵深立刻没**，不能再往上/下飘 |

- 只松 W 仍按 D：`HORIZ_ONLY`，vx≈±11.2，**depthVel=0**

## ④ 给程序看的补充

### 4.1 根因时序（钉死，与 v1.0 相同）

`Player.prefab` 的 `componentsList`：**Move（fileID `8492089656308942601`）在前，Town（`7600110044002200003`）在最后**。同一物理帧：Move 先把 `rg.velocity = Velocity`（即 `moveSpeedX`），Town 再归一 / 写权威 Y。

Unity 默认同一帧 **FixedUpdate 早于 Update**。CombatRun 的刹车在 `Update`，Town 写速在 `FixedUpdate`。

#### 斜向按住一帧（D+W，已稳态）—— 按住手感禁止改

| 量 | 值 | 谁写的 |
|----|----|--------|
| `hasH` / `hasV` | true / true | `HasVillageExploreHorizontalMoveIntent` + `HasVillageExploreVerticalMoveIntent` |
| `branch` | **DIAGONAL** | Town `ApplyVillagePlanarMoveSpeedNormalization` |
| `moveSpeedX` / `rb.velocity.x` | **≈ ±7.92** | Town `WriteVillagePlanarHorizontalSpeed`（覆盖 Combat 灌的 11.2） |
| `depthVelocity` | **≈ ±7.92** | 斜向**当场赋值** `n.y * planarSpeed`，跳过加速曲线 |
| 状态 | 仍在 **CombatRun** | Idle 进 Run 后未退 |

`WriteRootTransformWithAuthoritativeDepthY`：只把 `velocity.y` 清 0，**保留 `velocity.x`**。这是通道，不是根因。

#### 双手松开后第一物理帧

输入：`GetKey(D/W)` 已假；纵深意图 `hasV` **当帧即假**（只认轴 / 物理键，不走队列）。横向意图 `hasH` 可能因指令队列还没在 `PlayerInputComponent.OnUpdate` 里 `KeyUp` 清掉，**晚 1 帧仍为真**（见 §4.3）。

队列已空的那一帧：

| 量 | 修前 | 方案 A（v1.0，已作废） | **方案 A′（本期）** |
|----|------|------------------------|----------------------|
| `hasH` / `hasV` | false / false | 同左 | 同左 |
| `branch` | **NONE** | NONE | NONE |
| Town 对 X | **不写** | 写 0 | **写 0** |
| `moveSpeedX` / vx | **仍 ≈ 7.92** | 0 | **0** |
| `depthVelocity` | 摩擦：`7.92 - 18×dt` | 仍摩擦 | **0（无 V 意图当场清）** |
| CombatRun | 因 `|depthVelocity|>0.12` 不退 | 同左 | 本物理帧可能仍在 Run；**同帧 Update** 因 depthVel=0 且无横 → 退 Idle |
| `StopMoveInX` | **不跑**（要还按着 Vertical） | 不需要 | 不需要；横纵已由 Town 清 |
| `Exit` → `StopMove` | **走不到**（修前） | 走不到 | 随后 Update 走得到；双清无害 |

修前：Move 每帧把旧 `moveSpeedX` 灌回刚体 → Town `NONE` 不碰 X → `WriteRoot` 保 vx。直到 `depthVelocity` 磨到 ≤0.12 才退 Idle。斜滑约 **0.43～0.44 秒**，横向约 `7.92 × 0.44 ≈ 3.5` 世界单位。

#### Combat 何时才刹横向（现网，A′ 尽量不改这里）

`CombatRunState.Update`：

1. `StopMoveInX`：**仅当** `Village2_5D && !hasHorizontalIntent && |Vertical Raw| > 0.01`。注释写明：**禁止**用含惯性的 `HasVillageExploreDepthMoveIntent` 当条件（0513）。
2. 退 Idle：`!hasHorizontalIntent && !HasVillageExploreDepthMoveIntent()`。后者：竖轴按着 **或** `|depthVelocity| > walkAnimatorDeadZone`。
3. `Exit` 才 `StopMove()`。修前斜向双手松时纵深惯性把 Run 留住，Exit 走不到。

0513 与本案切开：

| | 0513（禁止） | 本案 A′（要做） |
|--|-------------|-----------------|
| 场景 | 还按着 W/S，A/D 被误判成「没横」 | 对应轴**确实没按** |
| 若每帧用「含惯性的 DepthIntent」清 X | 惯性滑行期间误杀刚按下的左右 | A′ **先把惯性速度清掉**，不要用惯性意图去清 X |
| 刹车放哪 | Combat 仅「无横且还按着 Vertical」 | **Town**：无横意图写 vx=0；无纵深意图写 `depthVelocity=0` |

### 4.2 四分支谁留 vx（修前 → A′）

`ApplyVillagePlanarMoveSpeedNormalization` 现网 vs 施工后：

| 分支 | 条件 | 修前写 X | 修前写 depth | A′ 写 X | A′ 写 depth |
|------|------|----------|--------------|---------|-------------|
| **DIAGONAL** | hasH && hasV | `n.x * 11.2`（≈7.92） | 当场 `n.y * 11.2` | **不变**（按住仍 0.707） | **不变** |
| **HORIZ_ONLY** | 仅 hasH | 写满 ±11.2 | **不碰**（前面已在摩擦） | 写满 ±11.2 | 前方无 V 已 **depthVelocity=0** |
| **DEPTH_ONLY** | 仅 hasV | **不写**（0513） | Clamp | **写 0**（无横意图立刻没横） | Clamp（还按着 W/S） |
| **NONE** | 双手空 | **不写 ← 斜滑主洞** | 不写（前面在摩擦） | **写 0** | 前方已 **depthVelocity=0** |

`DEPTH_ONLY` 写 0 与 0513 不打架：0818 后 `hasH` 已对齐队列/`GetKey`，**按着 D 不会进这个分支**。0513 现场是「有横却被当成没横」。A′ 只在确认没横时写 0。

纵深清零不要放在 `NONE` 里才做：只松 W、仍按 D 走的是 `HORIZ_ONLY`，必须在 **「无 Vertical 意图」那一段**（`OnFixedUpdate` 里现在做摩擦的 `else`）把 `depthVelocity=0`。

### 4.3 三种松键对照

修前（同一套 Prefab 数字，`dt=0.02`，摩擦 18）。vx 在 `NONE` 期间 **不随时间变**。

| 松前 | 松后 | 修前 | **A′ 之后（拍板）** |
|------|------|------|---------------------|
| 只 D | 双手空 | 立刻停 | 立刻停（保持） |
| 只 W | 双手空 | 纵深滑 ≈0.62s | **立刻停** |
| D+W | 双手空 | 斜滑 ≈0.44s（vx 不衰减） | **立刻停**（vx=0 且 depthVel=0） |
| D+W | 只留 D | 横回满速 + 纵深再飘 | 横回满速，**纵深立刻 0** |
| D+W | 只留 W | 横靠 Combat 晚最多 1 物理帧 | **Town 当帧 vx=0**，纵深继续走 |

分时刻（**仅修前**，说明为什么像滑冰）：

| 时刻 | 只 D 松 | 只 W 松（满速后） | D+W 双手松 | D+W→只留 D |
|------|---------|-------------------|------------|------------|
| 松键后 ≈0 | vx=0，dv=0 | vx=0，dv≈11.2 | **vx≈7.92**，dv≈7.92 | vx≈11.2，dv≈7.92 |
| 0.1s | 停 | dv≈**9.4** | **vx≈7.92**，dv≈**6.12** | vx=11.2，dv≈6.12 |
| 0.3s | 停 | dv≈**5.8** | **vx≈7.92**，dv≈**2.52** | vx=11.2，dv≈2.52 |
| 滑停 | 当帧 | 约 **0.62s** | 约 **0.44s** 后才 Idle 清 vx | 纵深约 0.44s |

A′ 之后上表除「按住的轴」外，松掉的轴在 **当物理帧** 即为 0。0.1s / 0.3s 不应再看到残留速度。

次要：双手松开的**第一**个 FixedUpdate 若早于 Input `KeyUp` 清队列，`hasH` 仍真、`hasV` 已假 → 进 **HORIZ_ONLY 一帧**（vx 写成满 11.2）。A′ 下这一帧纵深已是 0，下一帧 `NONE` 再把 vx 写成 0。1 帧 × 0.02s 不是「惯性」；若体感仍嫌那一帧横移，可再让 `hasH` 在 Town 侧同时认 `GetKey`（现网归一已经认意图，队列晚清才是缝）。

### 4.4 次要嫌疑（已排除为主因）

| 嫌疑 | 为何像惯性 | 为何不是主因 |
|------|-----------|-------------|
| 斜向瞬接 `depthVelocity=7.92` | 纯 W 要加速；斜向一脚满 | 解释「按住时前后起步冲」，解释不了松键后 **vx 不衰减** |
| `HORIZ_ONLY` 不衰减纵深 | 松 W 仍按 D 往上飘 | 只解释松一轴；双手空走 `NONE` |
| 指令队列松键晚 1～2 帧 | `hasH` 还真一会儿 | 通常 1 物理帧，不像滑出 3～4 个身位 |
| `WriteRoot` 保 vx | 刚体还在横移 | 通道。根因是没人把 `moveSpeedX` / `depthVelocity` 写成 0 |
| Move 在 Town 之后灌回 | 会挡刹车 | **现网 Town 在列表最后** |

旧方案 D（斜向不要瞬接纵深）治不了松键残留，**不要当主修**。按住斜向仍须 0.707。

### 4.5 推荐方案（只选一个）：A′

目标（拍板后）：**任何一个没按的轴，速度当帧为 0**；按住斜向仍 0.707；0513 不得用惯性意图每帧清 X。

| 方案 | 摘要 | 斜向松双手 | 纯 W | 松 W 仍按 D | 0513 | 选用 |
|------|------|-----------|------|-------------|------|------|
| A 只 NONE 清横向 | vx=0，纵深仍摩擦 | 只剩前后滑 | 仍滑 | 仍往上飘 | 不碰 Combat | **否（v1.0，已作废）** |
| **A′ Town 无意图轴清零** | 无 V → `depthVelocity=0`；无 H → 写 vx=0（NONE + DEPTH_ONLY） | **立刻停** | **立刻停** | 横满速、纵立刻 0 | 不改 Combat 清 X 的 Vertical 门；hasH 已对齐意图 | **推荐** |
| B Combat 无横就清 X | 去掉「必须按着 Vertical」 | 横能刹，纵仍滑 | 仍滑 | 仍往上飘 | 若误用惯性 DepthIntent 会回归 0513 | 否 |
| C 无键就退 Idle | 不等纵深惯性 | Exit `StopMove` 清刚体 | 刚体停，**权威 Y 仍滑** | 同左 | 小 | **否**：刹不住 Town 积分 |
| D 斜向不瞬接纵深 | 按住时 Y 仍加速 | 松键仍斜滑 | 几乎不变 | 仍飘 | 不相关 | 否 |

**为什么 C 不够（重要）：**

`CombatIdleState.Enter` / `CombatRunState.Exit` 的 `StopMove()` 只清 `MoveComponent.Velocity` 和 `rg.velocity`。村庄纵深位移来自 `TownPlayerLocomotion` 的 `_villageWorldY += depthVelocity * dt`，与刚体 `velocity.y` 解耦（`WriteRoot` 还把 vy 强制清 0）。**不把 `depthVelocity` 置 0，退 Idle 也会继续往前后挪。**

**A′ 松键后：**

- 双手空：`vx=0`，`depthVelocity=0`，随后 Update 退 Idle  
- 只松 W 仍按 D：`vx=±11.2`，`depthVelocity=0`  
- 只松 D 仍按 W：`vx=0`，`depthVelocity` 按住继续（加速/Clamp）  
- 按住 D+W：仍走 DIAGONAL，约 ±7.92 / ±7.92，**禁止回退**

施工要点（仍只改 `TownPlayerLocomotion.cs`）：

```csharp
// 1) OnFixedUpdate：无纵深输入时不要再走 depthFriction。
//    产品 2026-08-19：村街松键全部立刻停；0512 AC-02 的摩擦滑行本期覆盖。
//    替代：把 depthFriction 调极大冒充刹车——按住时手感也会怪，禁止。
if (Mathf.Abs(inputDepth) > VillagePlanarInputDeadZone)
{
    depthVelocity += inputDepth * depthAcceleration * dt;
    depthVelocity = Mathf.Clamp(depthVelocity, -planarSpeed, planarSpeed);
}
else
{
    depthVelocity = 0f;
}

// 2) ApplyVillagePlanarMoveSpeedNormalization
//    DEPTH_ONLY：无横意图，写横向 0（不要再等 Combat Update 的 StopMoveInX）。
//    原因：FixedUpdate 早于 Update，只靠 Combat 会晚 1 物理帧；斜向松 D 仍按 W 会先飘一下。
//    0513 不回归：hasH 为真时根本不会进本分支。
if (hasV) // 仅 hasV，hasH 已假
{
    WriteVillagePlanarHorizontalSpeed(move, 0f);
    depthVelocity = Mathf.Clamp(depthVelocity, -planarSpeed, planarSpeed);
    return "DEPTH_ONLY";
}

//    NONE：双手空，写横向 0（纵深已在步骤 1 清掉）。
WriteVillagePlanarHorizontalSpeed(move, 0f);
return "NONE";
```

`DIAGONAL` / `HORIZ_ONLY` 公式保持 0818 现网。不要改 `CombatRunState` 退态条件（depth 清零后 `HasVillageExploreDepthMoveIntent` 自然为假）。不要用含 `|depthVelocity|` 的判定去每帧 `StopMoveInX`。

### 4.7 不要误伤 / 严禁

1. **禁止回退** 斜向按住时的 0.707；合速度不得再变快。
