## 3. UI 结构拆解（对照策划长图）

### 3.1 主界面分区

```
┌─────────────────────────────────────────────┐
│  [背景] 老板娘立绘 / 柜台 / 货架（装饰层）      │
├─────────────────────────────────────────────┤
│  [购买]  [出售]     ← Tab，当前页「亮起」       │
├─────────────────────────────────────────────┤
│  图标 │ 名称 │ 单价 │ 数量/库存    │ ▲       │
│  ────┼──────┼──────┼───────────  │ █  ← 滚动条
│  ... │ ...  │ ...  │ ...          │ ▼       │
├─────────────────────────────────────────────┤
│  数量输入框    │  合计：XXX 金币  │ [确认]    │
│               │  （实时刷新）     │ 悬停高亮   │
└─────────────────────────────────────────────┘
```

### 3.2 列表单行四列（左 → 右）

| 列 | 购买页含义 | 出售页含义 |
|----|------------|------------|
| 图标 | 商品图标 | 背包道具图标 |
| 名称 | 商品中文名 | 道具中文名 |
| 价格 | **单价**（买价） | **单价**（卖价） |
| 数量 | 商店**库存**（当前版药水可视为无限或固定大数；见 §5.3） | 玩家**持有数量** |

### 3.3 交互细则（策划图 2）

| 元素 | 行为 |
|------|------|
| Tab「购买 / 出售」 | 切换页面；**当前 Tab 视觉高亮**（亮起） |
| 列表行 | **点选一行** = 当前交易对象；选中态需有反馈（高亮框等，美术定） |
| 数量输入框 | **必须手动点击** 后输入整数；变更时 **实时重算** 底部合计 |
| 底部合计区 | 显示 `单价 × 数量`；购买显示「将花费」，出售显示「将获得」（文案可后定） |
| 确认区 | **鼠标悬停高亮**；**仅点击时** 才真正结算；未选中商品或数量为 0 时应不可确认或给出提示 |

### 3.4 滚动

- 列表区域支持 **鼠标滚轮** 纵向滚动。
- 列表框 **右侧滚动条** 可拖拽。
- 实现上优先复用 Unity `ScrollRect`（与现有 UI 习惯一致）。

### 3.5 阶段一 · 列表 Prefab 节点建议（制作预制体用）

│       │   ├── TxtName   ← 「生命之珠」

│       │   └── TxtStock  ← TMP_InputField，默认「1」

│           ├── …

### 3.7 阶段二 · `TxtStock` 输入框（Prefab + 程序）

**当前 Hierarchy（阶段一成果）**：`Row_HpBall` 下已有 `TxtStock`（原为纯 Text）。阶段二**保留节点名**，把组件换成可输入控件。

**推荐 Prefab 结构（TMP，与工程其它 UI 一致）**

```
TxtStock                    ← 根：挂 TMP_InputField + Image（底框，Raycast 可点）
├── Text Area               ← TMP 默认子节点（RectMask2D）
│   └── Placeholder         ← TMP_Text，可选，如「数量」
└── Text                    ← TMP_Text，显示当前输入的数字
```

**制作步骤（Unity 编辑器）**

1. 选中 `Row_HpBall/TxtStock`（`Row_MpBall` 同样操作一份）。
2. 若当前是 **Text / TextMeshProUGUI**：Remove 该组件，**Add Component → TextMeshPro - Input Field**；或删除旧节点，右键 UI → **Input Field - TextMeshPro** 并仍命名为 `TxtStock`。
3. **Content Type** → **Integer Number**（只允许整数）。
4. **Character Limit** → 建议 `2`（单种最多买 10，与背包堆叠一致；阶段三交易时再校验）。
5. **Text** 子物体：对齐居中；**Placeholder** 可留空或写「0」。
6. 底框 **Image** 需勾选 **Raycast Target**，否则点不到。

**程序侧（阶段二最小逻辑，可选）**

- `ShopFormLogic`（或行内小脚本）可读 `TMP_InputField.text` 得到 `int` 数量；失焦时若为空则回退为 `0` 或 `1`。
- **本阶段不要求**把数量传给合计区或存档。

**与策划长图「底部数量输入框」的关系**

| 位置 | 阶段 | 说明 |
|------|------|------|
| 列表行内 **`TxtStock`（第四列）** | **阶段二** | 每行独立填购买数量 |
| 界面底部 **`TxtTotal`（合计）** | **阶段三** | 只读，绑生命珠数量 × 200 |
| 界面底部 **`BtnConfirm`（决定）** | **阶段四 · 当前** | 点击 → `[ShopDebug]` 成功 Log |
| **真实扣金币 / 入背包** | 阶段五及以后 | `PlayerGoldData`、`AddMainItem` |

> **说明**：阶段二数量在行内 `TxtStock`；阶段三在底部加 **`TxtTotal`** 做实时合计，**不是**再加一个数量输入框。

### 3.8 阶段三 · 底部总价 `TxtTotal`（Prefab + 程序）

**Prefab**

1. 在 `ShopPanel` 购买区**下方**（与列表同级或 `BottomBar` 子节点）新建 **`TxtTotal`**。
2. 组件：**TextMeshPro - Text**（不要用 InputField）。
3. 初始文案可写 **`0`** 或 **`200`**（与默认数量 1 一致）。
4. 同步把 **`Row_HpBall/TxtPrice`** 文案改为 **`200`**。

**计算逻辑（阶段三最小实现）**

```
数量 = 解析 Row_HpBall/TxtStock（TMP_InputField.text），失败或空 → 0
总价 = 数量 × 200
TxtTotal.text = 总价.ToString()   // 或 $"合计：{总价}"
```

**监听**

- 在 `ShopFormLogic`（或等价脚本）中，对 **`Row_HpBall` 的 `TMP_InputField`** 注册 **`onValueChanged`**，每次回调执行上式并刷新 `TxtTotal`。
- 商店打开 / 切到购买 Tab 时 **主动算一次**，避免初始不同步。

**阶段三明确不做**

- 不把 `Row_MpBall` 数量算进总价（体力珠单价未定时先不算）。
- 不校验金币是否够、不写入背包。

**阶段四扩展预留** — 见 **§3.9**（决定按钮 + Debug.Log）。

### 3.9 阶段四 · 「决定」按钮与 Debug 日志（Prefab + 程序）

**Prefab**

1. 在 **`BottomBar`** 下新建 **`BtnConfirm`**（UI → Button - TextMeshPro）。
2. 按钮上 Text 文案：**「决定」**（与策划口径一致；节点名仍用 `BtnConfirm` 便于脚本）。
3. 与 **`TxtTotal`** 并排或右侧，布局随美术；本阶段不要求悬停高亮。

**程序（`ShopFormLogic` 或等价脚本）**

```csharp
// 伪代码 — 点击「决定」
void OnConfirmClick()
{
    int total = GetCurrentTotal(); // 与 RefreshTotal() / TxtTotal 同源
    if (total <= 0) return;        // 或 LogWarning，见 §1.4
    Debug.Log($"[ShopDebug] 成功购买生命球，扣除金币 {total}");
}
```

**要点**

- **`GetCurrentTotal()`** 必须与阶段三 **`RefreshTotal()`** 同一套逻辑（`qty × 200`），避免 Log 与界面显示不一致。
- 本阶段 **禁止** 调用 `PlayerGoldData`、`PlayerBagData`（假购买）。
- 验证方式：Play Mode → 购买 Tab → 改数量 → 点「决定」 → 看 **Console** 过滤 `ShopDebug`。

**阶段五扩展预留**

- 同一点击处改为：`TrySpendGold(total)` + `AddMainItem(HpBall, qty)`；Log 可保留或改为正式 Tips。

## 5. 数据与交易规则（策划向）

### 5.1 货币

- 使用现有 **`PlayerGoldData.gold`**（任务奖励已在用；商店 UI 需展示当前持有金币）。
- 购买：金币不足 → **拒绝交易** + 提示（Toast / 系统提示，方式待选）。
- 出售：增加金币（`AddGold`；若后续需要扣款保护，施工时补 `TrySpendGold` 一类 API）。

### 5.2 道具来源

| 方向 | 数据来源 | 现有工程 |
|------|----------|----------|
| 0 购买入包 | `PlayerBagData.AddMainItem` | ✅ 已有；堆叠上限 **10** / 种 |
| 出售出包 | `PlayerBagData` 扣减 | ✅ 需确认是否有公开 `RemoveMainItem` / 等价 API |
| 商品名 / 图标 | `MainItemConfig.json` + `EMainItemName` | ✅ 已有 |
| 中文名 | 配置表 `cnName` | ✅ 已有 |

### 5.3 当前版本商品范围（策划图 1 · 右栏）

| 页 | 当前内容 | 备注 |
|----|----------|------|
| **购买** | **仅药水**（生命之珠 `HpBall`、体力之珠 `MpBall` 等消耗品） | 货单建议独立 **`ShopConfig.json`**，不要写死在 UI 脚本里 |
| **出售** | 玩家背包中 **可出售** 的掉落物（素材类 `MaterialItem`，如虫喙、藤蔓果、史莱姆核） | 切换至出售 Tab 时 **自动刷新列表**；无货则空列表 + 提示 |

### 5.4 预留：限量商品（策划图 1 · 未来）

- 购买页未来支持「**有限库存**」商品（每店 / 每存档限购 N 个）。
- **首版可不实现**，但 `ShopConfig` 建议预留字段：`stock` 或 `maxBuyPerSave`，避免以后改表结构。

### 5.5 单价配置

- 工程内 **尚无** 道具买卖单价表；**阶段三**在脚本 / Prefab **写死**：
  - **`HpBall`（生命之珠）买价 = `200`**
  - **`MpBall` 买价**：待定
- **阶段四**仅 Log「扣除金币 {总价}」，**不写入** `PlayerGoldData`
- **阶段五**起：`TrySpendGold` + `AddMainItem`；可选 `ShopConfig.json` 替换写死 `200`
