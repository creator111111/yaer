# 商店系统整修 · 按钮高亮与数量总价 · 架构溯源报告

> 日期：2026-09-23  
> 角色：架构侦探（**只读**，未改代码 / 场景 / Prefab）  
> Unity：2020.3.48f1  
> 现象：乱改后 **按钮高亮面目全非**；数量 **要点两次才改**；**Total2 仍会超过钱包金币**  
> 场景：`Village_Shop` · `Shop_Bar` / 买·卖 Tab / 决定  
> 提示词：`Assets/Doc/提示词/0923/商店系统整修_按钮高亮与数量总价_架构侦探提示词.md`

## ① 结论一句话（三病各自主因）

**不要再叠第五套钩子。** 现网 `ShopBuyRowQuantityInput` 已把行按钮、焦点、覆盖、钳制拧成一团；三病同源都在这一文件的「交互层」，0922 公式本身仍在 Form 里。

| 病 | 产品 | 主因（现网） |
|----|------|----------------|
| **B1 高亮** | SpriteSwap 按下/选中应对 | `transition=None` + 手搓 `selectedSprite` 顶掉按钮状态机；数量框抢 EventSystem 焦点后按钮永远画不对 |
| **Q1 首击无效** | 点一次就能改数 | 整行 `IPointerDown` + Relay **Down/Up 各激活一次** + **两帧** `FocusAfterPointerRoutine` 与 Button/ScrollRect 抢第一次点击 |
| **Q2 覆盖** | `5` 再按 `3` → `3` | 现网是「onValueChanged 收成末位」（K2 变种），可留思想、须删 Validate/`\0` 残骸；Helper 仍 `onFocusSelectAll=false` |
| **M1/M2 总价超余额** | Total2 **永不** \> 金币；超限立刻钳；决定不因超钱包失败 | ① `maxQty<=0` **故意不钳**（注释写「输得进」）→ 数量可任意大、合计超金币；② `OverCapSnapDelay=0.18s` 窗口内 TMP 仍是超限值，决定按 `QuantityForTotal` 会失败；③ 延迟期间 DigitStrip 已超限，体感总价/数量超钱包 |

**整修蓝图 = R0：回滚行交互到 0922 钳制 + 0830 隐形 caret，再加唯一覆盖刀 K1。** 覆盖金样钉死 **K1**（逻辑全选 + 正常 `onValueChanged` 刷图）。**禁止**再 Delay 一帧、禁止 Validate+`\0`、禁止关联合钳制。

## ② 残骸保留 / 删除表

| 机制 | 文件/符号 | 保留？ | 理由 |
|------|-----------|--------|------|
| `ResolveBuyMaxQuantity` / `ReclampAllBuyRowsForJointGold` | `ShopFormLogic` | **保留** | 0922 金样：买 `min((gold−其它行)/price, stackRoom)`；卖=持有 |
| `bypassGoldCheckForBagJoint` 默认 false | Form | **保留关** | 旁路开会让总价/决定绕过金币 |
| 决定预检 `TrySpendPlayerGold` / 堆叠预检 | Form | **保留** | 结算语义不动 |
| `ApplyInvisibleInputTextStyle` caret/selection 透明 | Helper | **保留** | 0830 无闪烁 caret |
| Sync 失败日志 + `EnsureOn` DigitStrip | Helper | **保留** | 0923 刷图加固，无害 |
| `MakeQuantityClicksHitInput`（DigitStrip `raycastTarget=false`） | Row | **保留** | 图挡住射线会导致点不到框 |
| `_overwriteOnNextDigit` + `CollapseOverwriteToLastDigit` + Validate+`\0` | Row | **删除**（整段覆盖交互） | 多轮互打；Validate 已清但仍注释混用。覆盖改走 **K1 唯一路径** |
| `Button.transition=None` + `_selectedVisualRow` 手搓选中图 | Row | **删除** | **B1 根因**；Prefab 已是 `m_Transition: 2`（SpriteSwap） |
| 整行 `IPointerDown` / `IInitializePotentialDrag` 抢焦点 | Row | **删除** | **Q1 根因之一**；行按钮应走原 SpriteSwap，数量只点 Number 框 |
| `ShopQuantityOverwritePointerRelay` Down+Up 双激活 + `Use()` 拦拖 | Row | **删除或缩到可选** | Up 再 `Notify` 等于二次进覆盖；与延帧 Focus 叠成双击感 |
| `FocusAfterPointerRoutine` 等两帧再 Select | Row | **删除** | 「再 Delay 说不定就好」已乱；产品禁再叠 Delay |
| `OverCapSnapDelay` / `ScheduleSnapBack` | Row | **删除** | **M1/M2**：窗口内合计/决定口径仍读超限 `text`；产品要立刻钳 |
| `TryClamp` 里 `maxQty<=0` 直接 return | Row | **删除（恢复立刻钳到 0）** | **M1 主因**：金币不够 1 件时仍可敲 9，Total2 爆炸 |
| 立刻 `TryClamp` + `RefreshDigitDisplay` + `OnQuantityValueChanged` | Row | **恢复为 0922 语义** | 边输边钳、回扫、Total2 同口径 |
| `onFocusSelectAll=false` | Helper | **改为 true（K1）** | 与隐形 selection 可并存；选区透明不影响覆盖 |
| 改货单价 / 加减钮 / 闪烁 caret / 重做 Prefab | — | **否** | 提示词排除 |

**Shop_Bar.prefab（未乱改前金样）**：`m_Transition: 2`（SpriteSwap）；Highlighted/Selected 用高亮图，Pressed/Disabled 用按下图。施工**不要改 YAML**，只停运行时把 Transition 改成 None。

## ③ 复现矩阵（代码推演；Play 对拍）

| 操作 | 高亮 | 首击改数？ | Total2 vs 金币 |
|------|------|------------|----------------|
| 点买/卖 Tab | Tab 本身多半仍 SpriteSwap；货栏可能已 None | — | — |
| 点货栏行 | 手搓选中图，移开/聚焦数量后 **错图或卡死** | 整行抢焦点，数量框常要 **第二次** 才吃键 | — |
| 点数量框一次，按键 | 按钮失焦 + None → 高亮乱 | 延帧 Focus + Relay Up 再进覆盖 → **双击感** | — |
| 钱不够 1 件仍输入 | — | 能敲进去（max≤0 不钳） | **Total2 可 \> 金币** |
| 钱够 2 件输入 3 | DigitStrip 先 3 | 0.18s 后变 2 | 延迟内决定按 3 计可能 **整单失败** |
| 多行填满 | — | — | 回扫因 max≤0 跳过则 **合计超钱包** |
| 决定 | — | — | 超限未钳完 → `TrySpend` 失败播 No |

## ④ 整修步骤（先回滚后加一刀）

### 步骤 0 — 删交互残骸（只动 Row；Form 公式不动）

从 `ShopBuyRowQuantityInput.cs` **整段删掉**：

- `_selectedVisualRow` / `CacheRowButtonVisual` / `ShowSelectedBarVisual` / `ClearSelectedBarVisual`
- 类上 `IPointerDownHandler`、`IInitializePotentialDragHandler` 及对应方法
- `_focusRoutine` / `FocusAfterPointerRoutine` / `FocusQuantityFieldNow`（K1 只保留「点到 TMP 时 EventSystem 自然选中」）
- `_snapBackRoutine` / `OverCapSnapDelay` / `ScheduleSnapBack*`
- `ShopQuantityOverwritePointerRelay` 整类（或仅留 DigitStrip 已关射线时不再需要）
- `_overwriteOnNextDigit` / `CollapseOverwriteToLastDigit`
- `TryClamp` 的 `maxQty<=0` 早退

恢复 Pipeline 为 0922 形态：

```
onValueChanged → Clamp（含 max=0→写 0）→ RefreshDigitDisplay → OnQuantityValueChanged
  →（买）ReclampAllBuyRows → RefreshTotal2
失焦 EndEdit：sanitize + Clamp + 刷图 + 通知
```

`ShopFormLogic`：**不改** `ResolveBuyMaxQuantity` / `Reclamp` / 决定扣款。

### 步骤 1 — 唯一覆盖刀 **K1**（勿混 K2）

| K1 | 做法 |
|----|------|
| Helper | `onFocusSelectAll = true`（selectionColor 仍 a=0） |
| 行 | `onSelect` → `SelectAllQuantityText`（**当帧、无 yield**） |
| 输入 | TMP **正常插入** → `onValueChanged` → Clamp + `RefreshDigitDisplay` |
| 首击 | 只保证 Number 上 TMP 能收到第一次 Pointer（保留 DigitStrip 关射线）；**不要**整行抢焦点、不要两帧再 Activate |

点框后全文逻辑选中 → 按 `3` 替换为 `3`（不是 `53`）；不点再按则追加多位（`3`→`34`），超限立刻钳。

**不采用 K2**（Validate 清空+`\0` / 收成末位）：已两轮伤刷图与双击。

### 步骤 2 — 总价金样（立刻钳，永不展示超金币）

- 买：`QuantityForTotal` 任何时刻 ≤ 联合 max；`GetCurrentBuyTotal() ≤ gold`
- `max=0` 时输入必须写回 **0**（宁可「敲了变 0」也不能超钱包）
- **禁止** snapBack 窗口；DigitStrip 与 Total2 只显示钳后值
- 决定：钳后数量成交，不因超钱包失败（堆叠等其它预检另论）

### 高亮金样

- 运行时 **永不** 改 `Button.transition`
- 货栏 / 买卖 Tab / 决定：Prefab SpriteSwap 自管 Highlighted / Pressed / Selected
- 数量聚焦导致行 Button 失焦是 Unity 默认，**接受**；不要手搓选中图去「按住」

## ⑦ 风险与回滚

| 风险 | 处置 |
|------|------|
| 删整行点击后「点图标不能改数」 | 产品验收是数量框一击；图标点选走按钮原高亮即可 |
| K1 全选又伤 DigitStrip | 禁止延帧 SelectAll；全选后仍走 onValueChanged Sync（0923 伤点是 Validate+`\0` 与延帧） |
| max=0 写 0 被说「输不进」 | 那是没钱；Total2 必须正确。勿再为「好输入」关钳 |
| 只修高亮或只修钳制 | 否决 R1/R2；三病并发必须 R0+K1 |

**回滚整修本身**：本报告就是回到 0922+0830 再加 K1；不要回到现网第 4 轮手搓高亮/snapBack。
