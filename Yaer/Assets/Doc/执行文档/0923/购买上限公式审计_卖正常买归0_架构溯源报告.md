## ① 结论一句话

**现网买端在 `onValueChanged` 里立刻 `TryClamp`（T1），max=0 时边输边写回 0——体感「输入坏了」。**  
公式本身仍是 B1：`stackRoom=0` → max=0（有金也买不进）；应改成 **编辑自由 + 提交再钳 + Tips**，禁止关 `ResolveBuyMaxQuantity`。

卖端共用同一套 `ShopBuyRowQuantityInput`，也边输边钳；因卖 max=持有，常 >0，故「能敲」体感好。产品要求买卖统一「编辑锁 / 提交保险」。

## ② A. 调用图（现网）

### 编辑中按键（买 · 现网 = 立刻钳写回）

```
键盘 Insert
  → TMP_InputField.SendOnValueChanged
  → OnQuantityValueChangedInternal
  → ApplyValueChangedPipeline
       ├─ 聚焦空串？ → 只刷 DigitStrip + OnQuantityClearedForEdit（不钳）✓
       └─ 有内容？ → TryClampQuantityToBusinessMax   ← ★ T1 边输边钳
                    → ResolveBuyMaxQuantity / ResolveSellMaxQuantity
                    → Clamp → ApplyQuantityText 写回 TMP+DigitStrip
                    → OnQuantityValueChanged
                         └─【仅买】OnBuyQuantityChangedForJointCart
                              → ReclampAllBuyRowsForJointGold
                                   → 每行 ApplyBusinessMaxClampSilent  ← ★ T2
```

**Play 栈（本档，键入瞬间，非失焦）**：

`TMP_InputField.KeyPressed` → `Insert` → `SendOnValueChanged` → `ApplyValueChangedPipeline` L353 → `TryClamp` → `ResolveBuyMaxQuantity` → `[ShopBuyMax]`

### 失焦 / Enter

```
onEndEdit (TMP：失焦与 Enter 都会到)
  → Parse 合法化 → ApplyQuantityText
  → TryClampQuantityToBusinessMax     ← 已有提交钳（保留，应收口到 CommitQuantity）
  → OnQuantityValueChanged →（买）联合 Reclamp
```

### 切其他商品行

```
点他行长条 / 数字框 → 他行 BeginQuantityEdit（清空+Activate）
  → 旧行 TMP 失焦 → 通常触发 onEndEdit（有钳）
  → ★ 无显式「旧行 Commit」入口；依赖失焦副作用（T3 缺口）
```

无独立 `onSubmit` / 取消回调；取消≈失焦或再 Begin 清空。

## ③ 事件对照表（产品 vs 现网）

| 事件 | 现网是否钳写回 | 产品要求 |
|------|----------------|----------|
| `onValueChanged`（有内容） | **是**（`TryClamp`） | **不钳**；只 Sync DigitStrip / 可选静默刷合计 |
| `onEndEdit` / 失焦 | **是** | **钳**（Commit） |
| Enter | **是**（走 `onEndEdit`） | **钳**（Commit） |
| 切其他商品行 | 依赖旧行失焦 `onEndEdit`；无显式 Commit | **旧行先 Commit**，再新行 Begin |
| 联合 Reclamp（他行变化） | **是**，含正在编辑行 | **编辑中行跳过**；未编辑行可即时或仅决定前 |
| Begin 清空后 | 不 Reclamp（仅 `OnQuantityClearedForEdit`） | 保持 |

## ④ B. 提交瞬间公式（本档 Play · `[ShopBuyMax]`）

现网在**键入**时已打出（边输边钳路径）；数值与失焦提交瞬间公式相同（B1，非 B2）：

```
[ShopBuyMax] item=HpBall gold=800 price=200 held=10 stackRoom=0 otherCost=0 max=0 bypassGoldCheck=0
```

同源会话还打出全表满堆叠（键入一次触发 T2 全表 Reclamp）：

| item | gold | price | held | stackRoom | max |
|------|------|-------|------|-----------|-----|
| HpBall | 800 | 200 | 10 | 0 | **0** |
| MpBall | 800 | 200 | 10 | 0 | 0 |
| …CostItem 行 | 800 | … | 10 | 0 | 0 |

并伴随：

```
[ShopDebug] 堆叠已满无法再买：HpBall 持有 10/10（stackRoom=0）；当前金币 800、单价 200 仍够买，但空位为 0 → 输入钳 0 属业务预期…
```

| 裁定 | 说明 |
|------|------|
| **T1** | **主因（时序）** — 编辑中 `ApplyValueChangedPipeline` 调 `TryClamp`；栈已钉死 |
| **T2** | **坐实** — 买侧 `OnQuantityValueChanged` → 全表 `Reclamp`；一次键入刷出全部 `[ShopBuyMax]` |
| **T3** | **部分缺口** — Enter/失焦有钳；切行无显式旧行 Commit |
| **B1** | **提交公式** — `stackRoom=0` → max=0；有金；**不是**读金错 |
| **B2** | **证伪（本档）** — gold=800、price=200、otherCost=0，算式正确 |

贩卖对照：同一 `TryClamp` 链，max=`ResolveSellMaxQuantity`=持有；持有>0 时编辑中不易「一律归 0」，故体感「正常」。施工须卖端同步「编辑不钳、提交再钳」，避免买卖分裂。

## ⑤ 「编辑锁定期 + 提交节点」最小改（给施工）

### 行组件 `ShopBuyRowQuantityInput`

| 回调 | 改法 |
|------|------|
| `ApplyValueChangedPipeline` | 聚焦编辑中：**禁止** `TryClamp`；只 `RefreshDigitDisplay`；通知改为「软」合计（买侧勿立刻全表 Reclamp 写回本行） |
| 新增 `CommitQuantity()` | Parse → `TryClamp` → DigitStrip → `OnQuantityValueChanged`（正式提交） |
| `OnQuantityEndEdit` | 改调 `CommitQuantity`（覆盖失焦 + Enter） |
| `BeginQuantityEdit` | 若他行正聚焦：先让 Form/`EventSystem` 触发旧行 Commit（或 Form 登记「当前编辑行」时显式 Commit） |
| 取消 | 无独立取消键时 = 失焦 Commit；再 Begin 清空仍走现网 Clear |

### Form `ShopFormLogic`

| 点 | 改法 |
|----|------|
| `OnBuyQuantityChangedForJointCart` / `ReclampAllBuyRows` | **跳过** `quantityInput.isFocused`（或标记 `_isEditingQuantity`）的行 |
| 决定购买 | 结算前对所有买行（含仍聚焦）先 `CommitQuantity` |
| `[ShopBuyMax]` | **仅 Commit / 决定前**打（或 Verbose 关编辑路径），验收贴提交一行 |
| max=0 Tips | Commit 时按字段分支：`stackRoom==0` →「该道具已满」；`afford==0` →「金币不足」；现网仅有 Console Warning，Tips 键未齐可用 `ShopDebugLogger` / 临时 `OpenTipsForm` 文案键，**禁止静默变 0 无反馈** |

### 方案对比

| 方案 | 做法 | 裁决 |
|------|------|------|
| **A** | 编辑跳过钳 + Commit 四节点 + 编辑行跳过 Reclamp + max=0 Tips | **主推** |
| **B** | 关 `ResolveBuyMaxQuantity` | **否决** |
| **C** | 只加 Warning、仍边输边钳 | **否决**（产品已拍板时序） |
| **D** | 只改买、卖仍边输边钳 | **否决**（体验分裂） |
