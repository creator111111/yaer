# 购买数量皆变 0 与再点不清空 · 架构溯源报告

> 日期：2026-09-23  
> 角色：架构侦探（**只读**，未改代码 / 场景 / Prefab）  
> Unity：2020.3.48f1  
> 现象：① 购买端输入**皆变 0**；② **再点**数量框不清空（先点别处再点则正常）  
> 背景：刚落「长条/数字框进输入并清空」；本票只修回归  
> 提示词：`Assets/Doc/提示词/0923/购买数量皆变0与再点不清空_架构侦探提示词.md`

## ① 结论一句话（两病分裁）

| 病 | 结论 |
|----|------|
| **P1 皆变 0** | **优先 Z1**：`TryClamp` 把任意键入钳到 `ResolveBuyMaxQuantity()==0`。买端看金币÷单价∩堆叠；卖端只看持有——故常表现为**仅购买坏、贩卖正常**。须 Play 打 `max`/`gold`/`price`/`stackRoom`。次因 **Z2**：清空后 `BeginQuantityEdit` 仍 `OnQuantityValueChanged` → 买侧 `ReclampAllBuyRows`；若焦点尚未就绪，空串钳写可能搅局（现网已有聚焦空串跳过，但 Invoke+回扫仍吵）。 |
| **P2 再点不清空** | **R1 坐实**：已聚焦时再点数字框，**`onSelect` 不二次触发**；点击落在 TMP 上，**行 `Button.onClick` 也吃不到** → `BeginQuantityEdit`/`ClearForEdit` 不跑。先点别处失焦后再点，才会再次 `onSelect`/Begin，与产品描述一致。 |

**最小修（可同 PR）**：  
1）钉死/修购买 max 误 0（金币读档、单价、堆叠）；有购买力时键入不得一律变 0；**保留**联合上限。  
2）数字框（及长条）**每次 PointerClick/Click 都调 `BeginQuantityEdit`**，不依赖二次 `onSelect`。  

禁止关全部购买钳制；禁止要求先点别处。

## ③ 病1 · 皆变 0（调用链与假说）

```
键入 → onValueChanged → ApplyValueChangedPipeline
  → TryClampQuantityToBusinessMax
       parsed = Parse(text)
       max    = ResolveBuyMaxQuantity(row)   // 买：金币联合 ∩ 堆叠
       Clamp(parsed, max) → 写回 TMP + DigitStrip
```

```975:1014:Assets/Scripts/Game/GameRuntime/UI/FormLogic/Shop/ShopFormLogic.cs
        // remainingGold = gold − Σ其它行；afford = remaining/price；return min(afford, stackRoom)
        // price≤0 → 0；goldData null → gold=0
```

```351:400:Assets/Scripts/Game/GameRuntime/UI/FormLogic/Shop/ShopBuyRowQuantityInput.cs
        // max=0 时 Clamp 任意正数 → 0（「不管输入什么都变 0」的直接写手）
```

| ID | 假说 | 裁定 |
|----|------|------|
| **Z1** | max 恒 0（金未读到 / 价≤0 / 堆叠满 / 其它行已占满钱包） | **主嫌疑**；贩卖对照可证伪「仅买坏」 |
| **Z2** | 清空后 Pipeline/Invoke 立刻写 0，键入也被打掉 | **次**；聚焦空串已 skip 写回，但 `Begin` 末尾仍 `OnQuantityValueChanged`→买侧全表 Reclamp |
| **Z3** | `_isClearingForEdit` 未挡住 | **弱**；Clear 用 WithoutNotify + flag，键入时 flag 已 false |

现网已有 `ResolveBuyUnitPrice`（Bake 价 0 回退表价）——若仍皆 0，更偏向 **gold/stackRoom**，而非单纯 Bake 价。

`SumBuyRowsCostExcluding` 仍用 `rowView.Price`（非 `ResolveBuyUnitPrice`）：单价口径不一致时可能扭曲联合剩余金（次要，Play 时顺带看）。

### 病1 最小修方向

- Play：若 `max==0` 且 `gold>0`、`price>0`、`stackRoom>0` → 查回扫/排除行逻辑。  
- 若 `goldData==null` 或 `gold==0` → 修商店内读档，**不是**关钳制。  
- 可选：`BeginQuantityEdit` 清空后 **不要**立刻 `OnQuantityValueChanged`（或只 `RefreshTotal2` 静默），减少空串态全表 Reclamp；键入后再通知。  
- **禁止**为「能输入」而 `max<=0` 跳过钳制（整修刚否决，总价会超钱包）。

## ④ 病2 · 再点不清空（调用链与假说）

```
首次点数字框 → 聚焦 → onSelect / Begin → Clear ✓
已聚焦时再点数字框
  → TMP 已是 selected → onSelect **不触发**
  → 射线命中 Number/Input（子级）→ 行 Button.onClick **不触发**
  → BeginQuantityEdit **不跑** → 数字仍在 ✗

先点别处 → 失焦 EndEdit（空→0 或保留）
再点数字框 → 再次 onSelect/Begin → Clear ✓
```

| ID | 假说 | 裁定 |
|----|------|------|
| **R1** | 已聚焦缺二次 Begin | **主因** |
| **R2** | Button 第二次 onClick 被吞 | 次要；点数字框本就不走 Button |

### 病2 最小修方向

- 在数量 Input（或 Number）上挂 **`IPointerClickHandler`**：每次 Click → `BeginQuantityEdit()`（已聚焦也清空重激活）。  
- 长条保持 `Button.onClick` → `BeginQuantityEdit()`（点长条时通常会先失焦再 Click，一般已能清空；与数字框同一入口）。  
- **不要**依赖「再等 onSelect」；**不要**要求用户先点别处。

## ⑤ 方案对比

| 方案 | 做法 | 裁决 |
|------|------|------|
| **A** | 修 max 误 0 + 减少清空后误 Reclamp；PointerClick 每次 Begin | **主推（两病）** |
| **B** | 关购买联合钳制 | **否决** |
| **C** | 仅文档要求「先失焦再点」 | **否决** |
| **D** | Validate+`\0` 大翻修 | **否决** |

### 必答

1. 皆变 0：先证 **Z1 max**；Z2 为清空通知链次因。  
2. 再点不清空：**缺二次 Begin（R1）**，非产品要先点别处。  
3. 文件：`ShopBuyRowQuantityInput.cs`（Click→Begin；Begin 通知策略）；必要时 `ShopFormLogic.cs` 只修读金/单价口径，**不删**联合公式。  
4. 聚焦空串：保持「不显示写回 0」；有内容时仍立刻联合钳制。

| 风险 | 处置 |
|------|------|
