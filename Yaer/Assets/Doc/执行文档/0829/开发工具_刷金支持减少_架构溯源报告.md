**产品目标**：同一金额 IntField 下 **既能加也能减**，便于测商店钱不够 / ShopNo、菜单个位与 0、扣款成败  
**关联**：`0829/开发工具_刷金自定义金额_架构溯源报告.md` · Menu Money C1 显示钳制 · 商店 `TrySpendPlayerGold`

## ① 结论一句话

**现窗/Util 仅 `TryAddPlayerGold`；扣款 API 已齐。拍板 U1：并排「累加 AddGold」+「减少 Spend」；减少走 `QuestManager.TrySpendPlayerGold(amount)`（门面已 Save，Util 勿再 Save）；不足整笔失败、不钳 0；成功/失败后刷新只读余额与已开 Menu Money；文案去掉「仅累加」。**

---

## ② 原因（通俗）

测「钱不够买不成」得先把钱包抽瘦，不能只会灌钱。  
商店扣款已经有「够才扣、不够不动」的规矩，调试减钱应走同一条路，别手改 `gold -= n` 或减到负数伪装成功。

---

## ③ 用户怎么减钱（施工后）

| # | 操作 | 通过 |
|---|------|------|
| 1 | Play → `Tools / Debug / Player Gold Tool…` | 窗写明可累加/减少 |
| 2 | 余额充足，金额填 `100` → **减少 Spend** | gold−100；Save；Menu 若开则刷新 |
| 3 | 余额 &lt; 金额 → 减少 | **不变**；Dialog/Log 含 need/have |
| 4 | **累加**仍点 | 与现网一致 |
| 5 | 未 Play | 按钮灰 / 不能改档 |
| 6 | 减到 0 后再减 | 失败不改档 |

配合商店：减到少于 Total2 → 关旁路点决定 → 应失败 / ShopNo。

## ④ 给程序

### A. 现窗能力与缺口（已核实）

| 层 | 现状 |
|----|------|
| Window | HelpBox/标题「仅 Play · **累加**」；IntField「金额（累加）」；仅按钮「累加 AddGold」；快捷填 100/9999/999999（只改 `_amount`，不立即执行） |
| Util | `TryAddPlayerGold` · `TryGetCurrentGold` · `RefreshOpenMenuMoney` — **无 Spend** |
| 快捷 MenuItem | `Add 9999 Player Gold` → `TryAddPlayerGold(9999)`；减少 **不必**再写死 MenuItem |
| `PlayerGoldData.TrySpendGold` | ✅ amount≤0 或不足 → false、不改 gold |
| `QuestManager.TrySpendPlayerGold` | ✅ Get → TrySpendGold → **成功才** `SavePlayerGold`；失败不落盘 |

**缺口**：只有加没有减；文案写死「仅累加」。

### B. UI 方案拍板

| 方案 | 裁定 |
|------|------|
| **U1 · 双按钮并排** | **✅ 推荐**（误触清晰：加/减分开） |
| U2 · 负数当减少 | ❌ 易误操作；Add 本拒 ≤0 |
| U3 · 下拉模式 | 次选，本期不做 |

**窗改动（白话）**

| 控件 | 决议 |
|------|------|
| 标题 | 「刷金工具（仅 Play · **累加或减少**）」 |
| HelpBox | 写明 AddGold / TrySpendPlayerGold；不足整笔失败；Menu 最多 6 位显示 |
| IntField 标签 | 「金额」或「金额（正整数）」——**勿再写「仅累加」** |
| 按钮行 | 「累加 AddGold」\|「减少 Spend」；未 Play 整组 `BeginDisabledGroup` |
| 快捷填额 | 保留，**共用**同一 `_amount` |
| 当前余额 | 成功/失败后 `Repaint`；继续用 `OnInspectorUpdate` 轻刷 |

### C. 减少链路（钉死）

```
Util.TrySpendPlayerGoldForDebug(amount, showDialogOnFail)
  → 未 Play / amount≤0 / GM·Quest·GoldData 空 → 拒绝（与 Add 对称）
  → before = gold
  → ok = QuestManager.TrySpendPlayerGold(amount)   // 内部已 Save；禁止再 Save 一次
  → 失败：Dialog/Log「需要 amount，当前 before」；不 Refresh 也可 Refresh（余额未变）
  → 成功：Log before→after；RefreshOpenMenuMoney；return true
```

| 问 | 决议 |
|----|------|
| 不够扣钳到 0？ | ❌ **禁止**（与商店一致） |
| 走哪条 API？ | ✅ **优先** `TrySpendPlayerGold`（与商店同门面） |
| 双 Save？ | ❌ 门面成功已 Save；Util **勿**再 `SavePlayerGold` |
| 裸写 `gold -=`？ | ❌ 禁止 |
| 返回值 | 与 Add 对称：`bool` 是否扣成功并已落盘 |
| 命名建议 | `TrySpendPlayerGoldForDebug` 或 `TrySpendDebugGold`（避免与运行时方法名完全撞车却放 Editor 类也可接受） |

**可选小重构（P1）**：抽 `ResolveQuestGoldContext` 减少 Add/Spend 重复门禁——非必须，最小 diff 可复制门禁块。
