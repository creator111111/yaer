# 游戏金币 · 数据上限 999999 — 架构溯源报告

**文档版本**：v1.0（2026-08-29）  
**文档性质**：【架构侦探】只读核实 + **产品改口拍板**（**本阶段未改代码**）  
**Unity**：2020.3.48f1  
**产品钉死（新口径）**：金钱 **`gold ∈ [0, 999999]`** —— **存档/逻辑硬顶**，不是「存档无限、菜单只显示 6 位」  
**错误现态**：刷金窗曾见余额 **21100219** = **非法**，须钳回并禁止再超  

**改口声明**：废止 `0829/MenuPanel_Money显示上限6位数_架构溯源报告.md` 中 **C1「仅显示钳制、存档/刷金不钳」** 及 OPEN 中对应 Q2/Q3「存档不软顶」旧决议；改为 **数据层 MaxGold=999999**。

---

## ① 结论一句话

**在 `PlayerGoldData` 收口：`public const int MaxGold = 999999`；`AddGold` 内 `gold = Min(gold+amount, MaxGold)`（多余丢弃）；`ParseInternal` 读档后 F1 钳回合法区间（修 21100219）；任务发奖与 Debug 累加一律吃中枢。Menu `MenuMoneyMaxDisplayValue` 改为引用/等于 `MaxGold` 作防御；Spend 整笔失败语义不变。禁止只改显示或只改刷金窗。**

---

## ② 原因（通俗）

产品说钱最多六位数，钱包里就不该出现两千多万——那是旧「只挡菜单、存档随便加」口径 + 刷金猛点造出来的脏数据。  
以后加钱（任务奖励、调试工具）加到 999999 就停；一进游戏若档里已经超标，读档时直接掰回上限。

---

## ③ 用户怎么把余额弄回合法

| # | 操作 | 通过 |
|---|------|------|
| 1 | 施工后从 InitScene 正规进游戏（读已有超标档） | 刷金窗/存档余额 **≤999999**（F1 读档钳回） |
| 2 | 猛点累加 / 输入大额累加 | **永不超过** 999999；可有「触顶」Log/提示 |
| 3 | ESC 开菜单 | 显示 ≤6 位，且与存档一致（数据合法后不再「藏超额」） |
| 4 | 减少 Spend | 不足仍整笔失败（与商店一致） |

（可选 F2：刷金窗若仍见超标，点「钳回上限」或打开即警告——双保险，非唯一手段。）

### C. 中枢方案（伪代码）

```csharp
// PlayerGoldData
public const int MaxGold = 999999;

public override void ParseInternal(MasterGameData masterData)
{
    gold = masterData.GetValue(GoldKey, 0);
    ClampGoldToLegalRange(); // F1：修 21100219 等脏档
}

/// <summary>gold ∈ [0, MaxGold]；超标钳回。可读档后或工具调用。</summary>
public bool ClampGoldToLegalRange()
{
    var before = gold;
    if (gold < 0) gold = 0;
    if (gold > MaxGold) gold = MaxGold;
    return gold != before;
}

public void AddGold(int amount)
{
    if (amount <= 0) return;
    // 触顶：多余丢弃。例 999990+100 → 999999（实加 9）
    // 注意用 long 防 int 溢出再钳（可选）：Min((long)gold + amount, MaxGold)
    var next = gold + amount;
    if (next < gold || next > MaxGold) // 溢出或超顶
        gold = MaxGold;
    else
        gold = next;
}
```

| 触顶例 | 结果 |
|--------|------|
| 999990 + 100 | **999999**（可 Log「触顶，实加 9」） |
| 999999 + 任意正 | 仍 **999999**（Soft warn 即可） |
| Spend 超过余额 | 仍整笔失败 |
| 刷金输入 999999 叠在已有余额上 | 结果 ≤ Max |

**读档钳回是否立刻 Save**：内存已合法即可；**下次** `SavePlayerGold` / 正常存档会写回。若希望一进游戏磁盘也立刻合法：Parse 后若 `Clamp` 返回 true，可由 Archive 加载路径或 Debug 打开时再 Save 一次（P1）；P0 以内存合法 + 下次存档为准亦可，但刷金窗打开后建议 **若曾钳回则 Save 一次**，避免用户只看内存、关游戏又读回脏 JSON。

推荐 P0：**Parse 钳内存**；若 `ClampGoldToLegalRange()==true` 打 Warning；Debug 窗发现超标时调 Clamp + `SavePlayerGold`（F1+F2 轻量）。
