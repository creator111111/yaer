# 开发工具 · 刷金改为可自定义金额 — 架构溯源报告

**文档版本**：v1.0（2026-08-29）  
**文档性质**：【架构侦探】只读核实 + 入口/语义拍板（**本阶段未改代码**）  
**Unity**：2020.3.48f1  
**现成工具**：`Assets/Editor/Tool/Debug/AddPlayerGoldDebugMenu.cs`  
**产品目标**：开发者可 **自填正整数金额** 再累加金币（测 0 位边界 / 个位 / 4 位 / 6 位顶格 999999 / 超显示上限）  
**货币 API 不变**：`GetPlayerGoldData` → `AddGold` → `SavePlayerGold` →（可选）`RefreshMoneyFromArchive`  
**关联**：`0829/开发工具_一键加9999金币_架构溯源报告.md` · `MenuMoneyMaxDisplayValue=999999`（C1 仅显示钳制）

---

## ① 结论一句话

**现网只能 MenuItem 写死 +9999，链路/门禁/刷新已齐；缺口是「自定义金额」。拍板 W1：独立小 EditorWindow `Tools/Debug/Player Gold Tool…`（当前余额只读 + IntField + 主按钮累加）；旧 `Add 9999 Player Gold` 保留为快捷；主路径仅 `AddGold(input>0)`；「设为」P1（用 `delta=target−gold` 再 Add，禁止裸写 `gold=`）；输入不强制 ≤999999，菜单仍靠现网 C1 顶格显示。**

---

## ② 原因（通俗）

验收要测「余额刚好 100」「顶格 999999」「再加一把看菜单是否还只显示 6 位」——写死 9999 不够用。  
Unity 2020 没有官方「弹窗填数字」对话框，所以开一个小调试窗填金额最合适；钱包加减仍走原来的 AddGold + Save，不另起第三套钱。

---

## ③ 用户怎么填金额（施工后）

| # | 操作 | 通过 |
|---|------|------|
| 1 | Play（InitScene 正规进有存档）→ **`Tools / Debug / Player Gold Tool…`** | 弹出小窗 |
| 2 | 看「当前余额」→ **金额** 填 `100` → 点 **累加** | Console：加前→加后；已 Save；已开菜单则 Money 同步 |
| 3 | 金额填 `999999` 或多次累加使 gold>999999 | 存档继续涨；菜单最多显示 **999999** |
| 4 | 金额填 `0` / 负数 | 拒绝，不改档 |
| 5 | 未 Play | Validate 灰掉 / 点开窗也不能改档 |
| 6 | （若保留）旧项 **`Add 9999 Player Gold`** | 仍一键 +9999 |

## ④ 给程序

### A. 现网能力与缺口（已核实）

| 项 | 现状 |
|----|------|
| 文件 | `AddPlayerGoldDebugMenu.cs`（`#if UNITY_EDITOR`，命名空间 `EditorC.Tool.DebugTools`） |
| 菜单 | `Tools/Debug/Add 9999 Player Gold` |
| 金额 | **写死** `const int AddAmount = 9999` |
| 语义 | **累加** `AddGold`，非设为 9999 |
| 门禁 | `Application.isPlaying`；`[MenuItem(..., true)]` 未 Play 灰掉；Dialog 提示 |
| 链路 | `QuestManager.getInstance()` → `GetPlayerGoldData()` → `AddGold` → `SavePlayerGold` |
| 刷新 | `FindObjectOfType<MenuFormLogic>()?.RefreshMoneyFromArchive()`（已 public） |
| 输入框 | ❌ **无** |
| `SetGold` API | ❌ **无**（仅 `AddGold` / `TrySpendGold`） |

**缺口**：无法自填金额；只能反复点 +9999。API/刷新 **不必重造**，本期升级入口即可。

### B. 入口方案拍板（W1～W4）

| 方案 | 裁定 |
|------|------|
| **W1 · 小 EditorWindow** | **✅ 推荐（主路径）** |
| W2 · DisplayDialog 输入 | ❌ Unity 2020 无标准输入 Dialog |
| W3 · 多个写死 MenuItem | ❌ 不满足自定义；仅可作窗内快捷 |
| W4 · 并入 `PlayerStatsEditorWindow` | ❌ 本期不并：Stats 管血/体/无敌，Gold 独立更清晰；风格可仿其 `GetWindow` + Play 内读状态 |

**窗体 UI（白话）**

| 控件 | 优先级 | 说明 |
|------|--------|------|
| 当前余额（只读 Label） | **P0** | Play 时读 `goldData.gold`；加金后刷新；未 Play 显示「请先 Play」 |

| 按钮 **「累加 AddGold」** | **P0** | 主按钮 |
| 快捷：填/加 100、9999、999999 | P1 | 填入 IntField 或直接累加该值 |
| 按钮「设为该值」 | P1（见 C） | |
| 热键 | P2 | 本期不做 |

**菜单整理**

| 项 | 决议 |
|----|------|
| 新 | **`Tools/Debug/Player Gold Tool…`** → 开窗（主入口） |
| 旧 | **保留** `Tools/Debug/Add 9999 Player Gold` 作一键快捷（内部调同一套 `TryAddPlayerGold(9999)`） |
| 文件 | **推荐最小 diff**：同目录新建 `PlayerGoldDebugWindow.cs`（窗体）+ 把 `AddPlayerGoldDebugMenu` 里加金逻辑抽成 **共享 static**（如 `PlayerGoldDebugUtil.TryAdd…`），旧 MenuItem / 窗按钮共用。亦可只扩写单文件为 Window+MenuItem——二选一，优先可读性。 |

样板：`PlayerStatsEditorWindow`（`Tools/人物状态调试工具`）——`GetWindow`、Play 内取状态；Gold 窗独立，勿塞进 Stats。

### C. 累加 vs 设为

| 操作 | 决议 |
|------|------|
| **主操作** | **累加** `AddGold(input)`；`input ≤ 0` **拒绝**（Dialog/Log，不调 Add/Save） |
| 「设为」 | **P1 可做，非本期硬门槛** |
| 设为安全实现 | 优先：`delta = target - gold`；`delta>0` → `AddGold(delta)`；`delta<0` → `TrySpendGold(-delta)`（或等价扣款）；`delta==0` 无操作；然后 **必** `SavePlayerGold` + 刷新 Menu。**禁止** `goldData.gold = target` 无 Save。 |
| 是否补 `SetGold` 正式 API | 默认 **否**（避免运行时误用）；若多处需要再开放问题升格 |

### D. 与 6 位显示关系（勿改 C1）

| 输入 / 结果 | 存档 | 菜单 Money（已开并 Refresh） |
|-------------|------|------------------------------|
| +100 等小额 | 如实累加 | 如实显示（自然位数） |
| 累加至 `gold == 999999` | 999999 | **999999** |
| 累加至 `gold ≥ 1000000` | **允许更大** | **仍显示 999999**（`MenuMoneyMaxDisplayValue`） |
| 工具侧 | **不**把输入钳到 999999 | **不**改 `RefreshMoneyFromArchive` |
