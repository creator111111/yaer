## 沟通摘要

### ① 结论一句话

**高低错落就是死的时候没把高度拉回跑道**：活着已经贴 `−6.61`，死后故意冻在「致死瞬间」的 Y。打飞、跳着死、树上掉到一半被砍，高度本来就歪，一冻就成错落的尸堆。权威已经是场景常量、不再抄玩家跳起高度，所以 **Dead 必须 Snap 到 −6.61，再 FreezeAll**。旧禁令要推翻。

### ② 原因（通俗）

上次为了不掉出屏幕，死后把刚体冻死。当时怕 Snap 会把空中死的尸拽到「雅儿正在跳的高度」，所以禁止 Snap，尸体停在死那一帧的位置。后来同轴改成固定跑道高度了，这条禁令过时了。现在空中死冻在半空、打飞死冻在抛物线顶点，多杀几只看起来就高一截低一截。掉落挂在尸体上，看起来也跟着错落。

另外：跳攻/掉树时若没先退出子状态机，`Dead.Enter` 可能根本跑不到（主状态机还在走子机），只 Snap 写在 Dead 里会漏掉这两类。施工必须先退出子机（或在 `OnDead` 里也能 Snap）。击飞组件死后若还 `MovePosition`，会把刚贴好的轴再顶歪，必须先停击飞。

### ③ 用户需要做什么（检查清单）

| # | 操作 | 现网预期（未修） |
|---|------|------------------|
| 1 | 走廊/东城郊：站桩普攻连杀 ≥3，暂停看根节点 `position.y` | 多数 ≈ **−6.61**（Idle 已贴轴；致死当刀不走击飞） |
| 2 | **先打飞再补刀**连杀 ≥5 | 尸 Y 带 `bounceHeight`（普攻约 +1、Dash 约 +3），彼此错落 |
| 3 | JumpAtk 升空中打死 ≥3 | 尸停在抛物线途中（顶点约 **−3.61**），明显偏高 |
| 4 | 树上掉落未落地就打死 | 尸停在下落途中（或仍被 `SetVelocity` 带着走） |
| 5 | Hierarchy 看根节点 Y，不要只看 Sprite | 错落应是 **本体 World Y**；`dropItem` 本地 y=0.36 是常数，不是彼此错落的根因 |
| 6 | 拍板：Dead **先 Snap 常量轴再冻**；停击飞；跳/树死要让 Dead.Enter 真正跑到 | 推荐方案 **A** |

## 2. 调用链（击飞 / 跳杀 → OnDead → Dead.Enter → 定格）

### 2.1 活体（对照：已贴轴）

```
Idle / Move / BornDown / JumpAtkDown.Enter
  → SnapToCombatAxisY()          // 权威 CombatAxisY = -6.61
  Idle 另：FreezePositionX|Y
JumpAtk 升空：UpBefore 解冻 Y；顶点 = CombatAxisY + 3
BornFall：SetVelocity(FallSpeed)，落地才 Snap
```

### 2.2 致死

```
Health.onHpIsZero → Slime.OnDead
  base.OnDead()                  // GroundCld.enabled=false；脚/身 Trigger
  canGravity = false             // 0913 留尸双保险
  ★ 不 StopKnockBackEffect
  if (isJumpAttacking && isFallDownAtk)   // ★ isFallDownAtk 是掉树 BornFall，不是 JumpAtk
      ExitCurrentSubStateMachine()
      ChangeState<SlimeDeadState>()
  else
      csAnimator.ChangeState<SlimeDeadState>()
      // JumpAtk / 多数 BornFall：子 SM 仍在 → 见 §2.4

致死当刀 OnApplyStatusEffects：
  TakeDamage → 若 isDead 则 return
  ★ 致死当刀不发起新击飞；上一刀击飞若没落地仍在跑
```

`OnGroundedEvent` 才会 `StopKnockBackEffect`。空中被补刀时击飞曲线还在。

### 2.3 `SlimeDeadState.Enter`（现网）

```
isProtect=false；Cld 全开（可砍尸）
StopMove；canGravity=false
velocity=0；FreezeAll；isKinematic=true
★ 故意不 SnapToCombatAxisY
→ 冻在「此时」的 transform/rg.y
```

`Idle.Exit` 会先把 constraints 解回 `FreezeRotation`，再进 Dead 冻死。顺序对留尸仍必要。

### 2.4 子状态机坑（JumpAtk / 掉树）

`BaseCsRuntimeController.ChangeState<T>()` 只改 **主** SM。主 SM `Update`：

```
if (sub != null) sub.Update();          // 不跑 main.currentState.Enter
else { … Dead.Enter(); Dead.Update(); }
```

`ApplyChange` 只 `SetAnimatorEnter()`（拨 Animator Bool），**不直接 Enter()**。  
`Dead.Enter` 要等主 SM 的 `sub == null` 且 Animator 已到 Dead。

现网 `isJumpAttacking && isFallDownAtk` 几乎只覆盖「跳攻中且正在掉树」这种交叉，**普通 JumpAtk 空中死、普通树上下落死都走 else，子机不退**。

| 情境 | 子机？ | Dead.Enter？ | 现网尸体 Y |
|------|--------|--------------|------------|
| Idle/Move/Wound/Attack 死 | 无 | **会跑**（下一拍 Animator 切到 Dead） | 冻致死点；站桩≈−6.61；击飞中则偏 |
| JumpAtk 空中死 | 仍在 | **很可能不跑** | 抛物线停在空中（Up/Fall 见 `IsDead` 则 return）；无 FreezeAll |
| BornFall 掉树死 | 仍在 | **很可能不跑** | Fall 的 `SetVelocity` **不看 IsDead**，仍可能带下落；无 FreezeAll |

因此：产品要「任意致死都贴轴」，**不能只在 Dead.Enter 加一行 Snap**；必须先退出子机（或把 Snap 放到 `OnDead`，不依赖 Enter）。

### 2.5 击飞如何写 Y（嫌疑 B）

`KnockBackComponent.FixedUpdate`：

```
newPos = startPos + 水平位移 + (0, Sin(...) * bounceHeight * (1-t))
rg.MovePosition(newPos)
```

玩家普攻 `breakHight≈1`，Dash `≈3`。`MovePosition` 对 kinematic 仍有效。死后若不 `StopKnockBackEffect`，即使 Snap+FreezeAll 也会被下一拍顶离轴。

**不改** `bounceHeight` / 技能表；死亡时停掉即可。

## 5. 修复方案对比

### 方案 A（推荐）

**目标顺序（钉死）**：停击飞 → 退出子状态机 → 进 Dead → **先 Snap 常量轴** → 再 StopMove / 清速度 / FreezeAll / kinematic / `canGravity=false`。

1. **`Slime.OnDead`**  
   - `knockBackComponent.StopKnockBackEffect()`（ChangeState 之前，避免 Idle.Exit 解冻后还被 MovePosition）。  
   - 只要还在子 SM（JumpAtk / Born）：`ExitCurrentSubStateMachine()`，**不要**再要求 `isFallDownAtk`。  
   - 再 `ChangeState<SlimeDeadState>()`。  
   - 已有的 `canGravity=false` 保留。

2. **`SlimeDeadState.Enter`**  
   - **第一件**：`SnapToCombatAxisY()`（权威已是 −6.61；`alsoClearVerticalVelocity` 默认 true）。  
   - 然后现网留尸：StopMove / `canGravity=false` / `velocity=0` / FreezeAll / kinematic。  
   - 注释改为：禁止 Snap **玩家实时 Y**；常量轴 **必须** Snap。

3. **不要**：改 `breakHight`；`Update` 每帧追轴；去掉 FreezeAll；改 0723 GroundCld。

| 利 | 弊 |
|----|-----|
| 站桩 / 击飞 / 跳杀 / 掉树同一出口贴轴 | 空中死会「瞬移落地」——产品要的就是回跑道 |
| 停击飞防止 Snap 被下一拍顶掉 | 须抽测：尸体不掉屏、掉落可捡、活体仍不跟玩家跳 |
| 退出子机让 Dead.Enter / Dead.Update（砍尸无敌、引导回调）真正跑到 | 留尸案 Q3 从「本期否」改为**本期要做**（范围仍只 OnDead 几行） |

可选加强：`OnDead` 在 ChangeState 之后若仍担心一帧窗口，把 Snap 抽到 `Slime` 上公开方法，OnDead 也调一次。优先仍以 Dead.Enter 为权威贴轴点，避免两处公式分叉。

### 方案 B（仅击飞/空中才 Snap）

`if (|y−axis|>ε)` 或 `if (isJumpAttacking || knockback)` 才 Snap。

| 利 | 弊 |
|----|-----|
| 站桩少一次写 Transform | 分支多；漏一种致死就再错落 |
| | 站桩本来 ε 内会 early-return，**没必要分支** |

**不推荐**。

### 方案 C（禁止）

继续冻致死点 Y。产品已否决。

### 推荐与不要动

| 项 | 内容 |
|----|------|
| **推荐** | **A**：停击飞 + 退出子机 + Dead.Enter **先 Snap 再冻** |
| **不要动** | 活体 Snap 调用点与常量权威；击飞手感数值；`MoveComponent` 重力公式；0723 GroundCld；村庄 Town；TenWan/WoodWorm（除非同病） |
| **回归** | 不掉屏；不跟玩家跳；`dropItem` 可捡；引导关 Dead 播完仍能推进 |

### 验收标准

1. 击飞流连杀 ≥5：各尸根节点 World Y ≈ −6.61，`max(y)-min(y) ≤ 0.2`，目视一条线。  
2. JumpAtk 空中杀 ≥3：尸回轴，不停半空。  
3. 站桩杀仍正常贴轴。  
4. 树上掉落途中杀：尸回轴，不掉屏。  
5. 尸体不掉屏；`dropItem` 可捡。  
6. 玩家跳时**活体**史莱姆仍不跟飞（常量同轴回归）。  
7. 抽测 0723：人踩壳不卡。

## 7. 给施工员的一句话

**死后先停击飞、退出跳/树子状态机，再进 Dead：先 Snap 到 −6.61，再 FreezeAll；不要冻在半空，也不要去掉定格。**
