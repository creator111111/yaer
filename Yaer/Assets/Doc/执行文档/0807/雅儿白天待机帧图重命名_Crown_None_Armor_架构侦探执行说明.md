## ① 结论一句话

**每个编号帧文件夹里固定 3 张图 = 头饰三态（Crown / None / Armor），不是 IdleSubState 的第四种动作。**  
开发者示例「图层 1337→Crown、图层拷贝→None、曲线→Armor」在现网 **15 个未改帧文件夹上可稳定套用**（须 **先匹配「曲线」再匹配拷贝/副本**，否则曲线名里也带「副本/拷贝」会误判成 None）。  
帧文件夹 `1` **已改好**（`Armor1/Crown1/None1`），施工只处理其余帧；重命名须连同 `.meta` 一起（或经 Unity 内改名）以免丢 guid。

## ② 原因（生活类比）

美术从 PS 导出时，每帧叠了三层「戴冠 / 不戴 / 铠甲系」人偶零件，文件名还停留在「图层 1337」「曲线 1 副本…」。  
动画机要的是同一帧号下能认出三套衣服零件，所以要把贴纸背面的乱码标签换成 **Crown / None / Armor + 帧号**。

### 4.2 开发者分类口径（示例名 → 语义）

| 开发者说法 | 语义 | 目标前缀 |
|------------|------|----------|
| 「图层 1337」这类 **纯图层编号**（无拷贝/副本） | 戴冠 | **Crown** |
| 「图层拷贝」/ 带 **拷贝、副本** 的图层名 | 无头饰 | **None** |
| 「曲线…」 | 铠甲系 | **Armor** |

> 注意：Crown 的图层编号 **每帧会变**（1337、1294、1260…），**禁止**写死「只认 1337」。

### 4.3 推荐匹配规则（施工算法 · 顺序强制）

对文件夹 `N` 内每个 `*.png`（已是 `Armor|Crown|None`+数字则 **跳过**）：

1. 若文件名（无扩展名）以 **`曲线`** 开头 → 重命名为 **`Armor{N}.png`**  
2. 否则若含 **`拷贝`** 或 **`副本`** → **`None{N}.png`**  
3. 否则若以 **`图层`** 开头 → **`Crown{N}.png`**  
4. 否则若为 **`铠`** / `铠*` → **`Armor{N}.png`**（兜底；现网乱名帧未出现，帧 1 手工阶段曾见）  
5. 否则 → **记入开放问题，禁止瞎改**

**为何曲线必须最先判**：现网曲线文件形如 `曲线 1 副本 2 拷贝 4.png`，若先按「含拷贝/副本」会误判成 None。
