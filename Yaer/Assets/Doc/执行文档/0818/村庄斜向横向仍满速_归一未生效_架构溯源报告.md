# 村庄斜向横向仍满速（归一未进斜向分支）— 架构溯源报告

**文档版本**：v1.0（2026-08-18）  
**文档性质**：【架构侦探】只读溯源；**本文件不施工**  
**Unity**：2020.3.48f1 / C#  
**前序**：`0818/村庄斜向移动速度叠加` 已施工方案 A（`ApplyVillagePlanarMoveSpeedNormalization`），验收 **仍不对**  
**已拍板（开发者）**：**斜向时横向不能和纯左右一样快**。合速度与单轴一样；斜向要把左右/前后拆成约 **0.707** 分量，禁止两轴满速相加  
**范围**：仅 `Village_KenMuNi1` 的 `Village2_5D`。不改龙宫、不改 Forest 战斗跑跳、不推翻 0513/0514、**不回退**进村点 A 的 Enter 补丁

## ① 结论一句话

**斜向横向仍和只按 D 一样快，是因为归一函数的「有没有左右」只看 Unity 的 `GetAxisRaw("Horizontal")`，村里真正左右走认的是指令队列 / `GetKey(A/D)`；轴对不上就进不了 `hasH && hasV`，横向 11.2 原样留下，纵深再加一台，斜着更快。** 不是公式写成 1.0、也不是进了斜向分支后又被 `SetRunSpeed` 灌回（Town 在 Move 之后，灌满发生在进分支之前）。

---

## ② 原因（生活类比）

施工已经写了：「方向盘打斜，就把油门拆成 0.707」。可交警认的是仪表盘上那根 **Horizontal 轴**，司机踩的是村里自己的 **A/D 本**（队列 + 物理键）。两套眼睛对不上时，交警以为你没打方向盘，只给你走「纯前后」那条：纵深照常给满，**横向一眼都不敢碰**（生怕误伤 0513）。于是 Combat 灌进去的 ±11.2 原封不动，再叠上纵深 → 斜着横向和只按 D 一样快，整体还更快。

村里为什么早就不用单看 Horizontal：`HasVillageExploreHorizontalMoveIntent` 注释写明 **「部分工程 Horizontal 未绑或双机位下 Raw 恒为 0，但物理键仍有效」**。本工程 `InputManager` 里 **两套同名 Horizontal**（键盘 a/d + 空按钮的手柄轴），`activeInputHandler=2`（新旧输入并存）。纵深用 Vertical Raw 能走，左右却靠队列/`GetKey` 走路——归一却退回只认轴，等于把 0513 已经补过的洞又踩了一遍。

## ③ 用户需要做什么

产品口径 **已经拍死**，不用再问「斜向要不要把横向打折」。施工按方案 A 改判定即可。你这边只验收：

| # | 操作（村街，能走之后，按住 ≥2 秒） | 期望 |
|---|--------------------------------------|------|
| 1 | 只按 D | 横向满速（约 11.2），纵深 0 |
| 2 | 只按 W | 无横向抽动（0513）；纵深满速 |
| 3 | **同时 D+W** | **横向明显慢于只按 D**（约 0.707×11.2≈7.9，不是 11.2）；斜向地面路程 **不比只按 D 更快** |
| 4 | 同时 A+W / D+S | 同 3，方向对 |
| 5 | 斜着走时松 W、仍按 D | 横向回到满速，不能停在 0.707 上 |
| 6 | 斜着走时松 D、仍按 W | 横向清掉，只剩纵深 |
| 7 | 先 W/S 再同向 D | 仍能横移（0514） |
| 8 | 对话后点一下 A | 往左，不能往右滑（0818） |
| 9 | Forest 跑跳、龙宫走路 | 现网不变 |

可选：把 Town 上现成的 `acceptanceDebugLog` 打开，看日志里斜向帧是 `DIAGONAL` 还是 `DEPTH_ONLY`。若按着 D+W 仍打 `DEPTH_ONLY`，就是本案未修或修错。

## ④ 给程序看的补充

### 4.1 失效分支（现网代码）

`TownPlayerLocomotion.OnFixedUpdate` 把 `Input.GetAxisRaw("Horizontal")` / `"Vertical"` 传进归一：

```csharp
bool hasH = Mathf.Abs(axisH) > VillagePlanarInputDeadZone; // 只认 Horizontal 轴
bool hasV = Mathf.Abs(axisV) > VillagePlanarInputDeadZone;
if (hasH && hasV) { /* 唯一会把 X 写成 0.707×planarSpeed 的路径 */ }
else if (hasH) { 横轴满速; }
else if (hasV) { /* 不写 X */ depthVelocity = Clamp(..., planarSpeed); }
```

按住 D+W、但 `axisH==0`、`axisV≠0` 时：

| 量 | 值 | 谁写的 |
|----|----|--------|
| `hasH && hasV` | **false** | 归一只看轴 |
| `moveSpeedX` / `rb.velocity.x` | **±11.2** | Combat `SetRunSpeed`，本分支不改 X |
| `depthVelocity` | 加速到 **11.2** | 纵深已接到 `villagePlanarMoveSpeed` |
| 地面合速度 | \(\sqrt{11.2^2+11.2^2}\approx\mathbf{15.8}\) | 比只按 D 快约 **41%** |

体感完全对上开发者：「斜向横向不是一样快」的反面——**横向一样快，再叠上下**。

对比：村里判定「有没有左右」用的是另一套：

```csharp
// HasVillageExploreHorizontalMoveIntent（Village2_5D）
HasMoveInput()                          // 队首 Left/Right
|| HasHorizontalMoveCommandInQueue()    // 整队
|| Abs(GetAxisRaw("Horizontal")) > 0.01
|| GetKey(A/D/←/→)                    // 注释：轴可能恒 0
```

归一 **没有** 后三层里除轴以外的部分。Combat 能左右跑，归一却说「没有横」。

### 4.2 不是「进了斜向又被灌回」（时序）

同一物理帧（`PlayerLogic.FixedUpdate` → `componentsList` 顺序）：

1. **Update（更早）**：Input 入队 + `ParseMoveCmd` → `MoveLeft`/`MoveRight` → 可能 `SetRunSpeed()`（11.2）。0818 Enter 补丁只影响进跑朝向，不负责合速度。
2. **FixedUpdate**：`PlayerMoveComponent`（列表第 4）把 `rb.velocity.x = moveSpeedX`（11.2）。
3. **FixedUpdate**：`TownPlayerLocomotion`（列表 **最后**）积分纵深 → `ApplyVillagePlanarMoveSpeedNormalization` → 写权威 Y。`WriteRoot` **保留** `velocity.x`。

因此：

- 若进了 `hasH && hasV`，Town **有权**把 X 改成 0.707×11.2，Move 不会在本帧再写回来。
- `EnsureVillageCombatRunHorizontalSpeedIfStale` 只在 `|moveSpeedX|≤0.12` 时补满速；斜向若写成 ≈7.9，**不会**被当成零速补票。
- 同向已朝右时 `TurnRight` 早退，也不会每帧 `SetRunSpeed`。

所以验收「横向仍满 11.2」**不是**灌回，是 **根本没进斜向分支、X 从未被打折**。

次要：转向当帧仍可能先 `SetRunSpeed` 满 X，只要随后 Town 用 **键位/队列符号** 再写一遍 0.707 即可。不要为此去改 Combat。

### 4.3 按住 D+W 时各数据源（推理）

| 数据源 | 按住 D+W 时期望 | 归一现网是否用 |
|--------|-----------------|----------------|
| `GetAxisRaw("Horizontal")` | 应为 ±1；**本工程可能为 0**（双机位同名轴 / 键位表不是 a/d） | **唯一 hasH** |
| `GetAxisRaw("Vertical")` | ±1（纵深能走说明这根多半有效） | hasV、纵深加速 |
| 队列 Left/Right | 有（长按留队） | Combat 用；归一 **不用** |
| `GetKey(D)` / `GetKey(A)` | true | Combat 0818 兜底；归一 **不用** |
| `moveSpeedX` | ±11.2 | 斜向失败时就是这个 |
| `depthVelocity` | 爬向 11.2 | 斜向失败时仍满给 |

施工后建议 `acceptanceDebugLog` 打一行：`axisH`、`intentH`、`axisV`、`branch`、`vx`、`depthVel`。不作为本期必改，有则验收更快。

### 4.4 方案对比与推荐

斜向（双轴都有意图）公式必须钉死：

\[
\hat{n} = \mathrm{normalize}(s_x,\; s_y),\quad
v_x = \hat{n}_x \cdot v_{\mathrm{planar}},\quad
v_y = \hat{n}_y \cdot v_{\mathrm{planar}}
\]

45°（\|s_x\|=\|s_y\|=1）时 \(\hat{n}_x=\hat{n}_y\approx 0.707\)，\(v_x\approx\pm 7.92\)（`villagePlanarMoveSpeed=11.2`），合速度仍 11.2。

| 方案 | 摘要 | 斜向横向立刻变慢 | 风险 | 选用 |
|------|------|------------------|------|------|
| **A 斜向判定对齐村里意图** | `hasH` = `HasVillageExploreHorizontalMoveIntent()`；`hasV` 对齐纵深（Raw Vertical + `GetKey(W/S/↑/↓)`）；符号用轴，轴为 0 再用键/队列，**禁止**用默认 `DirectionSign` 当第一数据源 | 高 | 最小 | **推荐** |
| B 不看输入，看速度 | `\|vx\|` 与 `\|depthVelocity\|` 都超死区再 `ClampMagnitude` | 中：纵深还在加速时横向仍接近满速 | 惯性/撞墙清轴误判 | 仅作 A 的注释备选 |
| C Town 末尾若 WASD 都按着无条件写 0.707 | 高 | 和 0818 转向符号冲突，若用 DirectionSign 会点 A 再反 | 否 |

**推荐 A**。缩放仍只放 `ApplyVillagePlanarMoveSpeedNormalization` 这一处。禁止再写一套只认 `GetAxisRaw("Horizontal")` 的斜向分支。

符号解析（施工默认，写进注释）：

1. `sx`：`GetAxisRaw("Horizontal")` 超死区则用它；否则 `GetKey(D/→)=+1`、`GetKey(A/←)=-1`；再否则队列里第一条 Left/Right（可复用 Combat 的 `FindFirstHorizontalCommandInQueue` 思路，但代码放 Town / 输入组件，**不要改 Enter**）。左右同时按下跟队列先后，不另定优先级。
2. `sy`：`GetAxisRaw("Vertical")` 超死区则用它；否则 `GetKey(W/↑)=+1`、`GetKey(S/↓)=-1`。
3. **禁止** `sx = DirectionSign` 作为第一手（0818：Idle 默认朝右）。仅当 `hasH==true` 且上面全是 0 的极端帧，才允许用当前 `moveSpeedX` 的符号，再没有才 `DirectionSign`。
4. `hasH && hasV`：`WriteVillagePlanarHorizontalSpeed(n.x * planarSpeed)`，`depthVelocity = n.y * planarSpeed`（与现网斜向体一致，只是进得去）。
5. 仅 `hasH`：横向满 `planarSpeed`（现网）。
6. 仅 `hasV`：**仍不写 X**（0513）。纵深 Clamp 到 `planarSpeed`。

不要把 `hasH==false && hasV` 理解成「可以砍 X」——那会让纯 W 或「轴看不见的 D」被清横。对齐意图之后，真斜向会走第 4 步，不会误清。

### 4.5 最小文件

| 文件 | 是否改 | 原因 |
|------|--------|------|
| `TownPlayerLocomotion.cs` | **是，主改** | 只改 `hasH`/`hasV`/符号数据源；斜向公式已存在 |
| `PlayerInputComponent.cs` | **可选** | 若不想在 Town 里堆 `GetKey`，可抽出 `GetVillageExploreHorizontalSign()`；非必须 |
| `CombatRunState.cs` | **否** | 保留 0513/0514/0818；不要在 Enter 里打折 |
| `MoveComponent` / Prefab / 场景 | **否** | 不要改 `runSpeed` 冒充；不要全局 Clamp |

### 4.6 不要误伤

- 纯 W/S：`hasH` 必须仍为 false（队列无 Left/Right、没按 A/D）→ 不写 X。
- 斜向横向变慢 **不等于** 把 X 清零。
- 不回退 `ApplyVillageCombatRunEnterHorizontalFromInput`。
- 不改默认朝向 Left。
- 不在 `MoveComponent.OnFixedUpdate` 全局限速。
