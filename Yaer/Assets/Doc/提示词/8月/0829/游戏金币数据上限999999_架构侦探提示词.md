## 提示词助手预梳理（侦探须核实，勿当唯一真相）

### 产品需求（新口径 · 钉死）

| 项 | 期望 |
|----|------|
| 金钱上限 | **`gold ∈ [0, 999999]`**（含 0；最大 **999999**） |
| 层 | **存档字段 + 所有加金入口** 均不可超过；显示自然与数据一致 |
| 现状 | 刷金工具余额 **21100219** 已超标 → **非法** |
| 加金触顶 | `AddGold` 加满到 999999 即停；多余部分丢弃或不再增加（须写清） |
| 减金 | `TrySpend` 逻辑不变；不能减到负 |
| 刷金窗 | 累加不得把余额加过 999999；可提示「已达上限」 |
| 菜单显示 | 仍最多 6 位；数据合法后 **不必**再「藏真实超额」 |

### 与旧 0829「仅显示钳制」的关系（必写改口）

| 旧（作废） | 新（生效） |
|------------|------------|
| C1：显示 `Min(gold,999999)`，存档可更大 | **C2/硬顶**：`gold` 本身 ≤999999 |
| 刷金可测「显示顶格但存档更大」 | **禁止**再制造 >999999 的存档 |
| Debug HelpBox「存档可不钳」 | **改文案**：存档也钳 |

侦探报告须显式写：**废止旧 C1 存档不钳条款**；Menu 侧 `MenuMoneyMaxDisplayValue` 可保留作防御，但真源改为数据常量（建议单一常量两边共用）。

### 加金入口清单（须扫全，防漏网）

| 入口 | 预扫 | 施工要求 |
|------|------|----------|
| `PlayerGoldData.AddGold` | `gold += amount` 无顶 | **中枢钳制**（推荐一处收口） |
| `QuestManager` 任务发奖 Gold | 调 AddGold | 跟随中枢 |
| `PlayerGoldDebugUtil.TryAdd…` | 累加无顶 | 跟随中枢；可额外提示触顶 |
| 商店购买 | 只 Spend | 不增加；无需改顶（验不超过即可） |
| 其它 `gold =` / `AddGold` | 侦探搜全工程 | 表列；漏网必写 |

**推荐收口**：在 `PlayerGoldData` 增加  
`public const int MaxGold = 999999;`  
`AddGold` 内 `gold = Min(gold + amount, MaxGold)`；  
可选 `ClampGoldToMax()` 供读档/工具一次性修正。

### 已超标存档怎么处理（必拍板）

| 方案 | 行为 | 倾向 |
|------|------|------|
| **F1 · 读档时钳制** | `ParseInternal` 后若 gold>Max → 钳到 Max（下次 Save 写回） | **✅ 推荐**（用户现档 21100219 一进游戏即合法） |
| **F2 · 仅工具「一键钳回」** | 刷金窗按钮 Clamp | 可作补充；单靠它用户易忘 |
| **F3 · 手动改 JSON** | — | ❌ 不当主方案 |

刷金窗打开时若发现 >Max：显示警告 + 自动/按钮钳回（与 F1 双保险）。

### 触顶语义

| 操作 | 期望 |
|------|------|
| gold=999990，AddGold(100) | → **999999**；Log 可写「触顶，实际只加了 9」 |
| gold=999999，再 Add | → 仍 999999；不报错也可 Soft warn |
| Spend 超过余额 | 仍整笔失败（现网） |
| 刷金输入 999999 累加到已有余额 | 不得超过 Max |
