### 产品口径

| 操作 | 现网体感（开发者） | 期望（预扫，侦探对照后写入 OPEN） |
|------|-------------------|----------------------------------|
| 只按 D / A，松手 | 基本立刻停（Combat 退 Idle `StopMove`） | 保持立刻停 |
| 只按 W / S，松手 | 纵深本来就有摩擦滑行（0512 设计） | **本期默认保留**纯纵深惯性；若侦探发现斜向惯性其实就是这条，要写清楚「为何斜向更明显」 |

开发者原话：「村庄里面走路的斜方向走路不知道为什么会有惯性。」  
不是卡死、不是斜向又变快、不是点 A 走反。那些另案。

### 生活类比

纯左右像踩刹车的卡丁车：松油门立刻停。纯前后像故意留了点滑行（DNF 纵深摩擦）。斜着走却像两台发动机拆成 0.707 之后，**刹车只踩了油门、没踩方向盘**：前后还在滑，左右那截 0.707 也没卸掉，人就斜着漂出去。

### 现网已有补丁（预扫：惯性从哪来）

`TownPlayerLocomotion.OnFixedUpdate` 顺序：

1. 有 Vertical 轴 → 加速 `depthVelocity`；没有 → `depthFriction` 衰减。  
2. **`ApplyVillagePlanarMoveSpeedNormalization`**（0818 后）：
   - `DIAGONAL`（hasH && hasV）：**当场**把 `moveSpeedX` 和 `depthVelocity` 写成 `normalized * villagePlanarMoveSpeed`（约 ±7.9 / ±7.9）。纵深**跳过加速曲线**，一脚踩满。
   - `HORIZ_ONLY`：只写满横向，**不碰** `depthVelocity`。
   - `DEPTH_ONLY`：只夹纵深，**不写**横向（0513）。
   - `NONE`：什么速度都不写。
3. 用（可能还在滑的）`depthVelocity` 积分权威 Y。  
4. `WriteRootTransformWithAuthoritativeDepthY` **保留** `velocity.x`。

Combat 侧（村街是 Combat 轨）：

- `CombatRunState.Update`：**只有「还按着 Vertical」且没有横向意图时**才 `StopMoveInX`。  
- 退 Idle 条件：`!hasHorizontalIntent && !HasVillageExploreDepthMoveIntent()`。  
- `HasVillageExploreDepthMoveIntent` → `HasVillageDepthMoveForHomeStateMachine`：**松键后 `|depthVelocity| > walkAnimatorDeadZone` 仍算「在走」**。  
- `CombatRunState.Exit` 才会 `StopMove()` 清横向。

**预扫推论（必须用代码/时序打假）**：斜向松双手后 `hasH=false`、`hasV=false` → 走 `NONE`，Town **不清 X**；纵深还在摩擦滑 → `HasVillageExploreDepthMoveIntent` 仍为真 → **不退 Idle、不走 Exit 的 StopMove**；`StopMoveInX` 又因为 Vertical 已经松开而不跑。于是上一帧斜向写下的 **vx≈7.9 一直留着**，再叠上还没磨完的 `depthVelocity` → **斜着滑**。纯 D 松手没有纵深惯性，能退 Idle，所以感觉不到惯性。

次要嫌疑（侦探并列排除）：

| 嫌疑 | 为何像惯性 | 为何可能不是主因 |
|------|-----------|------------------|
| 斜向把 `depthVelocity` 瞬接到 7.9，松键摩擦更长更猛 | 纯 W 要加速才满；斜向一脚满再滑 | 纯 W 松手也该滑，开发者却点名「斜方向」 |
| `HORIZ_ONLY` 不衰减纵深 | 松 W 仍按 D 时人还往上飘 | 只解释「松一轴」，不解释「双手都松仍斜滑」 |
| 指令队列松键晚几帧 | 松手后 hasH 还真一会儿 | 通常只有 1～2 帧，不像「惯性」 |
| 刚体 `velocity.x` 与 `moveSpeedX` 双写 | WriteRoot 保 vx | 是通道不是根因 |

### 严禁的施工方向（预判）

1. 回退 `ApplyVillagePlanarMoveSpeedNormalization` 或把斜向再改回两轴满加。  
2. 用 `HasVillageExploreDepthMoveIntent`（含惯性）在 CombatRun 里每帧 `StopMoveInX`（0513 已踩过：贴台沿能上下不能左右）。  
3. 把 `depthFriction` 调极大 / `depthVelocity` 全局每帧清零冒充「没惯性」（纯 W 手感一起死）。  
4. 在 `MoveComponent.OnFixedUpdate` 全局限速或全局摩擦。  
5. 回退点 A 补丁；改龙宫 / Forest 战斗。

## 必读

### A. 松键后谁还在写速度
- `ApplyVillagePlanarMoveSpeedNormalization` 四个分支：DIAGONAL / HORIZ_ONLY / DEPTH_ONLY / NONE 各写不写 X、写不写 depthVelocity
- 斜向当场 `depthVelocity = n.y * planarSpeed` 是否跳过加速
- `WriteRootTransformWithAuthoritativeDepthY` 是否保留 vx
- componentsList：Move 与 Town 谁先谁后；NONE 帧 Move 会不会把旧 vx 再灌进刚体

### B. Combat 何时才刹横向
- `CombatRunState.Update` 的 `StopMoveInX` 条件（Vertical Raw + 无横向意图）
- 退 Idle 是否等 `HasVillageExploreDepthMoveIntent`（含 `|depthVelocity|` 惯性）
- `Exit` 的 `StopMove` 在斜向双手松时会不会根本走不到
- 注释里「禁止用含惯性的 DepthIntent 清 X」的 0513 现场，和本案「清斜向残留 X」如何切开

### C. 三种松键对照（报告必须给表）
