# Cursor Agent Prompt · 商店数量框：点击全选后覆盖输入（保留购买上限钳制）

> **角色**：【架构侦探】短扫现网 → 【施工员】最小改交互  
> **日期**：2026-09-23  
> **产品原话**：鼠标点数量后是隐形光标，想要**点击后全选**；再输入数字就变成新数字，**不要在旧数字上累加**；**购买金额上限计算还是一样**，这样玩家永远不会（因超钱包）购买失败  
> **场景 / UI**：`Village_Shop` · 买卖行右侧数量（隐形 TMP + DigitStrip）  
> **不是**：改货单价；改「决定」结算公式语义；取消联合购买力钳制；改回可见闪烁 caret 当主交付；改加减按钮方案  

先复制「侦探」确认聚焦/全选现状；拍板后复制「施工员」。钳制逻辑（0922）**必须保留**。

---

## 提示词助手预梳理（须证伪）

### 产品钉死

| 项 | 要求 |
|----|------|
| 点击数量框 | **全选**当前数量（含 0） |
| 再按数字键 | **覆盖**为新数字，不是末尾追加（例：已是 `5`，按 `3` → `3`，不是 `53`） |
| 购买上限 | **保持** 0922 联合总价钳制：`min((gold−其它行)/price, stackRoom)`；卖=持有；边输边钳仍可 |
| 失败感 | 超购买力仍立刻调回上限，点「决定」不因超钱包整单失败（堆叠等其它预检另论） |

### 现网预扫（对照）

| 项 | 线索 |
|----|------|
| 框 | `ShopBuyRowQuantityInput` + `ShopQuantityInputHelper.ApplyInvisibleInputTextStyle` |
| 隐形 | caret 透明/宽 0；**selection 也透明**（0830 为消闪，易导致「点了像没全选、在末尾累加」） |
| 钳制 | `SetMaxQuantityResolver` + `TryClampQuantityToBusinessMax`；买联合回扫 `ReclampAllBuyRowsForJointGold` |
| TMP | 有 `onFocusSelectAll`；现网是否已开、点选是否稳，侦探须 Play 证伪 |

假说：

1. **主假说**：未可靠全选（或 selection 被关死后体感无选中）→ 光标在末尾 → 输入变成累加  
2. 全选开了但 `onValueChanged` 钳制写回打乱选区，首键仍像追加  
3. DigitStrip 只显示、不反馈聚焦，玩家以为没点上又点一次导致怪态  

### 强制排除

| 勿当主因 | 理由 |
|----------|------|
| 取消购买联合钳制 | 与「不会购买失败」矛盾 |
| 只加大 `characterLimit` | 不解决累加 |
| 改成加减钮 | 产品要键盘覆盖输入 |
