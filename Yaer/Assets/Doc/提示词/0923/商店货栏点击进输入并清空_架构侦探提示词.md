# Cursor Agent Prompt · 商店货栏：点长条或数字框都进入输入，并先清空（含 0）

> **角色**：【架构侦探】短扫命中链 → 【施工员】**只改本交互**  
> **日期**：2026-09-23  
> **产品原话**：点击长条（货栏前段）有响应，点右边**数字框没响应**；希望**这两处点了都算要输入购买数量**；一旦要输入，**先清空里面的数字（连 0 都不要）**，再输入。**先改这么个操作逻辑，别的以后再说**  
> **UI 锚点（用户截图）**：购买 Tab · 货栏行 = 左侧长条（图标+名+单价）+ 右侧数量框（DigitStrip/`0`）  
> **不是**：整修按钮高亮全案；改联合总价公式；改决定结算；再叠 Validate+\0 第四轮；改贩卖以外无关 UI  

纪律：本期只交付「点哪进输入 + 进输入先清空」。总价超余额、Tab 高亮等**另票**，本提示词禁止顺手大改。

## 提示词助手预梳理（须证伪）

### 产品钉死（本期）

| 项 | 要求 |
|----|------|
| 点**长条**（行主体 / Bar） | 进入本行数量输入（聚焦数量框） |
| 点**数字框**（右侧 Number/TxtStock） | **同样**进入本行数量输入（现网无响应须修好） |
| 进入输入时 | **立刻清空**当前数量显示与 TMP 文本（**含清空 `0`**，框内为空 / DigitStrip 空） |
| 再按键 | 输入新数字；失焦后再规整/钳制可沿用现网（本期不争论联合公式） |

### 现网可疑（预扫）

| 项 | 线索 |
|----|------|
| 行 | `Shop_Bar` 上常有 `Button` → 点长条走 Button 按下/高亮「有响应」 |
| 数量 | `ShopBuyRowQuantityInput` + 隐形 `TMP_InputField` + DigitStrip |
| 射线 | `MakeQuantityClicksHitInput`：Number 子树里**只留** Input 根 `raycastTarget`——若 Input 可点区域过小/被挡，点数字框会「没反应」或点到行 Button 边缘行为不一致 |
| 聚焦 | 现有 `onSelect` → `SelectAll`（仍显示 0）；产品改口为**清空**而非全选留 0 |

假说：

1. **数字框无响应**：DigitStrip/装饰仍挡射线，或 Input Image 面积不对，或行 Button 抢事件但 Number 区 raycast 全关导致死区  
2. **长条有响应**：点到行 Button，但**未** `ActivateInputField` / 未清空  
3. 清空：`onSelect`/点选入口应 `SetText("")` + Sync DigitStrip 空，失焦空串再按现网 Parse→0 或保持 0（侦探写清失焦空串规则，默认空→失焦变 0 可接受）

### 强制排除（本期）

| 勿做 | 理由 |
|------|------|
| 改 `ResolveBuyMaxQuantity` / Reclamp | 用户说别的以后再说 |
| 重做整行手搓 transition=None 高亮 | 易回潮面目全非 |
| 只修长条不修数字框 | 产品两点都要 |
