# Cursor Agent Prompt · 购买端仍一律变 0（有 800 金仍无法买）· 复验热修

> **角色**：【架构侦探】必须 **Play + 打日志** 钉死 max=0 原因 → 【施工员】按证据热修  
> **日期**：2026-09-23  
> **产品原话**：购买端**还是**无法输入其他数字，输入任何数都会变成 0；**明明有 800 元**还是无法购买  
> **状态**：上一轮 `购买数量皆变0与再点不清空` **验收失败**（施工说明已写「修好」，现网用户仍复现）——本票按**复验失败热修**，禁止再写「已修好」却无 Console 证据  
> **场景**：`Village_Shop` 购买 Tab（生命球等，单价常见 200 → 800 金应至少能买 4）  
> **不是**：关联合钳制交差；改货单价表；只改贩卖；再整页翻修按钮高亮  

**硬纪律**：没打出一行  
`[ShopBuyMax] gold=… price=… stackRoom=… otherCost=… max=…`  
就**不许**声称根因或完工。

## 提示词助手预梳理

### 产品钉死

| 项 | 要求 |
|----|------|
| 持有约 800 金、生命球单价 200 | 输入 1～4 应稳定显示，**不得变 0** |
| 超过可买（如 5） | 可钳到 4，不是变 0 后无法买 |
| 与菜单金币 | 菜单若显示 ~800，商店上限必须读**同一笔** `PlayerGoldData` |

### 上一轮已做但仍失败（须证伪是否未进包 / 未跑到）

| 改动 | 文档声称 |
|------|----------|
| 清空不立刻联合 Reclamp | `OnQuantityClearedForEdit` |
| 再点 Click→Begin | `QuantityPointerClickRelay` |
| 单价 `ResolveBuyUnitPrice` | 统一合计/max |

用户现诉**仍皆变 0 + 有 800 无法买** → 优先查 **`ResolveBuyMaxQuantity` 运行时仍返回 0`**（金币未读到 / 堆叠空位 0 / 价异常），不是再猜清空时序。

### 假说（按优先级 Play 证伪）

| ID | 假说 | 怎么证 |
|----|------|--------|
| **G1** | `GetPlayerGoldData()` null 或 `gold==0`（商店场景读档与菜单不一致） | 日志 gold；对照菜单 `[MenuMoney]` |
| **G2** | `stackRoom==0`（该道具已满堆叠 MaxStack）→ max 恒 0，**与金币无关** | 日志 held / MaxStack / stackRoom |
| **G3** | `price<=0` 仍漏 | 日志 ResolveBuyUnitPrice |
| **G4** | otherRowsCost 异常吃光 remaining（其它行幽灵数量） | 日志 otherCost |
| **C1** | max>0 但仍被写 0（Pipeline/回扫 bug） | 日志 max 与钳后 text |
