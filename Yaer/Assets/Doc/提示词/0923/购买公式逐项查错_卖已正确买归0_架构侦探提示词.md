## 提示词助手预梳理

### 公式（现网，提交瞬间）

```
held      = ResolvePlayerBagData().GetMainItemCount(ItemId)
stackRoom = max(0, MaxStackPerItem(10) - held)
price     = ResolveBuyUnitPrice(row)   // Bake>0 ? Bake : 表买价；≤0 → max=0
gold      = QuestManager.GetPlayerGoldData().gold
otherCost = Σ(其它买行 QuantityForTotal × 单价)
afford    = max(0, gold - otherCost) / price
max       = min(afford, stackRoom)
```

卖端只用 `held`，**不读** gold/price/stackRoom → 卖正确**不能**证明买公式各项都对，只能证明：背包 `GetMainItemCount`、行绑定、Commit 写回链大体可用。

### 逐项怀疑表（侦探必须逐行填实测）

| 项 | 若异常 → max | 怎么证伪 |
|----|--------------|----------|
| **held 虚高** | stackRoom=0 | 对照背包 UI / Inventory；同 ItemId 贩卖行 held 是否一致 |
| **MaxStackPerItem 误用** | 空位假 0 | 常量是否 10；是否读成别的上限 |
| **ItemId 错绑** | 读到满堆叠的别的道具 | Bake 的 ItemId vs 行显示名 |
| **price≤0** | 直接 max=0 | Bake 价、表买价、日志 `price=` |
| **gold 读 0 / 错源** | afford=0 | 对照菜单金币；是否非 `PlayerGoldData` |
| **otherCost 虚高** | remaining=0 | 其它行是否幽灵数量；QuantityForTotal 是否含本行/编辑脏值 |
| **min 写反 / 提前 return** | 恒 0 | 跟读 `ComputeBuyMaxBreakdown` 分支（bypass / price≤0） |
| **max>0 仍显示 0** | 非公式 | Commit 后二次写 0（本票次要；先证 max） |

### 假说 ID

| ID | 假说 |
|----|------|
| **F1** | `stackRoom=0`（held≥MaxStack）→ max=0；用户有金也归 0（若属实：须说清是读 held 错，还是设计门 + 产品要改策略） |
| **F2** | `price≤0` → 早退 max=0 |
| **F3** | `gold` 读错/为 0（与菜单不一致） |
| **F4** | `otherCost` 异常吃光 remaining |
| **F5** | `ItemId`/Bag 实例错，held 读错道具或空 Bag |
| **F6** | 公式算出 max>0，Commit 仍写 0（钳制链，非公式） |
