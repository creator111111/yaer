# Cursor Agent Prompt · 购买数量：编辑中不钳、提交节点再保险

> **角色**：【架构侦探】钉死「何时钳制」+ 买上限公式 → 【施工员】按产品节点改  
> **日期**：2026-09-23  
> **产品拍板（本票主目标）**：  
> - **选中/正在输入时**：框里数字**原样显示**，输入多少就是多少，**禁止**边输边强制归 0 / 边输边改成上限  
> - **提交节点**再跑保险（上限钳制 + 合法化）：失焦（点其他位置）、取消输入、按 **Enter**、点**其他商品行**  
> **对照**：卖出输入交互已正确，作金样；买端同样改为「编辑自由、提交再钳」  
> **场景**：`Village_Shop` 购买 Tab（卖 Tab 同步同一套时序，避免买卖体验分裂）  
> **不是**：关掉上限公式；边输边钳；空口「堆叠满是预期」却无反馈；只改点击清空不改钳制时序  

**纪律**：必须 **Play** 验证「编辑中不改数、提交才变」；买上限仍打现档 `[ShopBuyMax]`（提交瞬间），禁止复读旧 held=10。

## 提示词助手预梳理

### 产品时序（必须按此实现）

| 阶段 | 行为 |
|------|------|
| **编辑中**（聚焦 / `BeginQuantityEdit` 之后到提交前） | 键盘输入多少显示多少；**不**调用 `TryClamp` / 联合 `Reclamp` 写回本行；空串可保持空 |
| **提交节点**（失焦 / Enter / 取消编辑 / 切到其他商品行） | 再 `Parse` → `ResolveBuyMaxQuantity`（或卖 max）→ 超限钳到 max；非法/空按现网约定回 0 或空→0；必要时 Tips |
| **决定购买** | 仍保证总价 ≤ 金、堆叠不超；提交节点已钳过则决定不应再因超钱包失败 |

### 为何比「边输边钳」更好

- 边输边钳：用户敲 `1` 若 max=0 立刻变 `0`，体感「输入坏了」；中间态（先敲 2 再敲 0 想输 20）也会被打断  
- 提交再钳：编辑过程与卖端「能敲」一致；保险仍在**明确节点**生效，玩家能理解「松手后被调回」  

### 买卖上限公式（提交时仍用，编辑中不算写回）

| | 卖 `ResolveSellMaxQuantity` | 买 `ResolveBuyMaxQuantity` |
|--|------------------------------|----------------------------|
| 上限 | **持有件数** | `min(剩余金/单价, 堆叠空位)` |
| 堆叠空位 | 不参与 | `MaxStackPerItem(10) - held` |

提交瞬间若买 max=0：须**显式 Tips**（如「金币不足」或「该道具已满」），禁止无提示静默变 0 却像输入坏了。

### 假说（时序 + 公式）

| ID | 假说 |
|----|------|
| **T1** | `onValueChanged` / `ApplyValueChangedPipeline` 编辑中仍 `TryClamp` → 边输边归 0（主修） |
| **T2** | 联合回扫 `ReclampAllBuyRowsForJointGold` 在他行编辑时误写本行 |
| **T3** | 提交节点未挂齐（仅 EndEdit 有，切商品行/Enter 漏）→ 部分路径仍边输边钳或永不钳 |
| **B1** | 提交时 `stackRoom=0` → max=0（设计门，须 Tips） |
| **B2** | 提交时金/价/otherCost 误算 → max=0（真算错） |

## 施工员（侦探表 + 裁定后再复制）

```
@Assets/Doc/执行文档/0923/购买上限公式审计_卖正常买归0_架构溯源报告.md

你是【施工员】。按产品拍板改数量保险时序；卖对照保持正确。

### 必须实现

1. **编辑中**：聚焦行 onValueChanged 只同步 DigitStrip/显示，**禁止** TryClamp / 把本行改成 max 或 0  
2. **提交节点**统一走一处 CommitQuantity（或等价）：  
   - Input 失焦（点其他位置）  
   - Enter  
   - 取消输入（若有明确取消）  
   - 切换到其他商品行（旧行先 Commit）

- 禁止为省事关掉 ResolveBuyMaxQuantity  
- 禁止偷偷取消堆叠校验导致决定后超堆叠坏档  
- 不要破坏卖出已正确的输入手感；卖端同步「编辑自由、提交再钳」  
- 写入：`Assets/Doc/施工说明/0923/购买上限公式审计_卖正常买归0_施工说明.md`

### 验收

- [ ] 购买：选中后输入 1、2、5… 编辑中显示与键入一致，不强制归 0  
- [ ] 失焦 / Enter / 点其他商品：超限才被调回上限；合法数保持  
- [ ] 买 max=0 档：提交后变 0（或清空）且有 Tips，不是编辑中就跳  
- [ ] 有金有空位：Commit 后 1～可买上限可留下；决定可买成功
```
