# Cursor Agent Prompt · 商店买卖数量输入：超持有/超购买力自动钳回上限

> **角色**：【架构侦探】只读；查商店买卖右侧数量框「超限不自动调回」  
> **日期**：2026-09-22  
> **现象（用户 + 截图）**：红圈列为数量输入（现为 `0`）；中间列为持有（如 `5`）。**卖**：包里有 6 输入 7 → **自动调回 6**。**买**：同理，按当前金币（及必要堆叠上限）**够买几个就调成最大能买几个**  
> **场景 / UI**：`Village_Shop` · Shop 列表行（截图：虫喙 / 藤蔓果 / 史莱姆核 = 贩卖页素材）  
> **不是**：改货单价表；改「决定」整单失败对白；改数量框取消闪烁光标案；关货币旁路验收开关业务语义以外的大改  

把下面「侦探」整段交给 Agent。没对拍卖/买两 Tab 的上限公式、没查清现网只在「决定」时拒单之前，不要施工。

## 提示词助手预梳理（须证伪）

### 产品钉死

| 模式 | 输入超过上限时 | 期望 |
|------|----------------|------|
| **贩卖** | qty &gt; 当前持有 | **立刻（或失焦/提交时）把输入改成持有数**；DigitStrip / Total2 跟着变 |
| **购买** | qty &gt; 当前金币能买的最大件数（及若有堆叠空位上限则取更严） | **自动调成最大能买件数**（可为 0） |
| 合法输入 | qty ≤ 上限 | 不误砍 |

时机倾向：**输入过程中或 onEndEdit/提交时钳**，不要只靠点「决定」后再 Warning（0920 贩卖「背包不足整单取消」可留作双保险，但产品要的是框内先调回）。

### 现网预扫（对照，勿当终裁）

| 项 | 线索 |
|----|------|
| 解析 | `ShopQuantityInputHelper.ParseAndClampQuantity` 仅 `≥0`，**无**持有/购买力上限 |
| 位数 | `MaxQuantityDigits=2` → 视觉上最多 99，仍可大于持有 6 |
| 贩卖结算 | `ShopFormLogic` 预检 `held ≥ qty`，不够 → Warning「背包不足」整单取消——**框不回调** |
| 购买结算 | 金币不足 / 堆叠将超 → 整单失败——**框不回调** |
| 行组件 | `ShopBuyRowQuantityInput`（买卖行可能共用或分叉——侦探钉死） |

假说：

1. **主假说**：输入层从未接「按模式算 maxQty」；只有结算拒单  
2. 买卖共用同一 Input，钳制未读当前 Tab / 行价 / 持有  
3. 钳了 TMP text 但未 `SyncNumberDigitDisplay` → 图数字仍显示越界  
4. 购买 max 公式漏堆叠空位或旁路 `bypassGoldCheck` 时行为未定义  

### 强制排除

| 勿当主因 | 理由 |
|----------|------|
| 货单价配错 | 用户要的是输入钳制 |
| 只改 Warning 文案 | 不满足「自动调回」 |
| 取消数量输入改加减钮 | 过大；非本期 |
| 全局改 `MaxQuantityDigits` 当唯一修 | 治不了「持有 6 输 7」 |
