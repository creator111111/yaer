## 提示词助手预梳理（侦探须核实）

### 产品口径（不要再问「要不要打折横向」）

| 操作 | 横向快慢 | 纵深快慢 | 地面合速度 |
|------|----------|----------|------------|
| 只按 D | 满速（约 11.2） | 0 | 满速 |
| 只按 W | 0 | 满速 | 满速 |
| **D+W 斜向** | **必须比只按 D 慢**（约 0.707×满速） | **必须比只按 W 慢** | **仍是满速，不能更快** |

开发者原话：「对就是要这个意思，应该斜向移动的时候横向移动不是一样快的。」

### 生活类比

一辆车、一个时速。方向盘打斜，左右分量必须比「只往右开」慢，否则就是两台发动机叠满。现在施工写了「斜着就把油门拆成 0.707」，但交警认的是 Unity 的 Horizontal 轴，司机按的是村里自己的 A/D 本。轴对不上，交警以为你没打方向盘，横向继续满油，纵深再加一台 → 斜着更快。

### 现网已有补丁（预扫：失效点）

`TownPlayerLocomotion.ApplyVillagePlanarMoveSpeedNormalization`：

```csharp
bool hasH = Mathf.Abs(axisH) > 0.01f;  // axisH = Input.GetAxisRaw("Horizontal")
bool hasV = Mathf.Abs(axisV) > 0.01f;  // axisV = Input.GetAxisRaw("Vertical")
if (hasH && hasV) { 单位向量 * planarSpeed; 写 X 和 depthVelocity; }
else if (hasV) { 只夹纵深，不砍 X; }   // ← 按着 D 但 Horizontal=0 时走这里
```

村里真正左右走认的是 `PlayerInputComponent` 指令队列 / `GetKey(A/D)`（`HasVillageExploreHorizontalMoveIntent` 已有这套兜底，因为「部分工程 Horizontal 未绑、Raw 恒为 0」）。

**归一只看 Raw Horizontal，和村里走路不是同一套眼睛。** 斜向时 `hasH==false`、`hasV==true` → **不写横向** → Combat 的 `SetRunSpeed()` 仍是 ±11.2，纵深仍可到 `planarSpeed` 11.2 → 合速度 ≈ 15.8。体感：斜着走，**横向和只按 D 一样快**，再叠上下。

次要：`CombatRunState.MoveLeft/Right` 转向时仍 `SetRunSpeed()` 灌满横向；Town 若本帧没进 `hasH&&hasV`，灌满的 X 会保住（`WriteRoot` 保留 `velocity.x`）。

### 严禁

1. 再写一套只认 `GetAxisRaw("Horizontal")` 的斜向分支。  
2. 斜向走回 `villageDepthOnly` 把 X 清掉（斜着不能左右）。  
3. 改 `runSpeed` 数字冒充（斜向仍相加）。  
4. 回退点 A 补丁；在 `MoveComponent.OnFixedUpdate` 全局限速。  
5. 把默认朝向改成 Left。

### 侦探须比较（只推荐一个）

| 方案 | 摘要 | 斜向横向变慢 | 风险 |
|------|------|----------------|------|
| A 斜向判定对齐村里意图 | `hasH` 用 `HasVillageExploreHorizontalMoveIntent` 或 `GetKey(A/D/←/→)`；`hasV` 对齐纵深那套（Raw Vertical + GetKey W/S）。符号用轴或键，再 `normalized * planarSpeed` | 高 | 最小，接着现有函数 |
| B 不看输入，看速度 | `abs(moveSpeedX)` 与 `abs(depthVelocity)` 都超死区则 ClampMagnitude / 按当前符号缩到 planarSpeed | 中 | 惯性、撞墙清轴时误判 |
| C 每帧强制按键位拆分 | Town FixedUpdate 末尾若 W/S 且 A/D 都按着，无条件写 0.707 | 高 | 和 0818 转向符号冲突，须用键位符号不是 DirectionSign |

预扫建议 **A**，门控仍只在 Town 这一处缩放。转向后 `SetRunSpeed` 灌满：要么斜向帧不再让 Combat 灌满 X，要么 Town 在 Move 之后（现网列表 Town 已在 Move 后）**用键位而不是轴**再写一遍 X。

## 背景

1. 斜向合速度要和单轴一样；**斜向时横向必须比纯左右慢**（约 0.707），不能两轴满速相加。
2. 方案 A 已经写在 Town 里，验收仍是斜着横向一样快、整体更快。
3. 目标：钉死为何 `hasH&&hasV` 进不去（或进去后 X 被灌回 11.2）；给出最小改法，让斜向真正拆分横向。

## 侦探任务

1. **结论一句话**：斜向横向仍满速，是没进 `hasH&&hasV`，还是进了又被 SetRunSpeed 灌回。
2. **时序**：同一物理帧 Input 轴 / 键 / 队列 / moveSpeedX / depthVelocity。
3. **推荐方案**（A/B/C）+ 斜向 vx、vy 公式（须写出 0.707×planarSpeed）。
4. **最小文件列表**；缩放仍只放 Town 一处为佳。
5. **验收**：
   - 只 D：横向满速
   - D+W：横向明显慢于只 D，斜向路程不比只 D 更快
   - 只 W：无横向抽动
   - 0514 / 点 A 不回归
6. OPEN 只记技术例外（例如 Horizontal 在本工程确实恒 0）。
7. **禁止**：改资产；再只认 GetAxisRaw Horizontal。
