### 预扫（助手已量像素，侦探抽查）

**元数据**

- 白天 Idle 16×3 张、Walk 8×3 张：全部 `alignment: 0`，`spritePivot: {x: 0.5, y: 0.5}`，`spritePixelsToUnits: 100`。  
- 参考战斗服：`alignment: 9`（Custom），待机 pivot 大约 `x≈0.53~0.67`，`y≈0.03`（贴脚底）。走路 pivot `x` 更大、`y` 接近 0；部分走路参考还有 `spriteBorder`（护头走路 `1.png` 的 `x:234` 等）——**默认不要拷贝 border**（角色 Sprite 走 Simple，border 会搅乱九宫；侦探若发现不用 border 脚对不齐再写入 OPEN）。

**画布宽高（同一帧号）**

| 套 | 结论 |
|----|------|
| Idle Crown ↔ 战斗服皇冠 | 抽查 **全部同尺寸** → 可 **逐帧原样拷贝** pivot |
| Walk Crown ↔ 铠甲皇冠走路 | 抽查 **1～8 全部同尺寸** → 可 **逐帧原样拷贝** |
| Idle Armor / Idle None ↔ 对应战斗服 | **部分同、部分高不同**（宽多半相同）。例：Armor1 `353×563` 相同；Armor20 `325×562` vs `325×581` |
| Walk Armor / Walk None ↔ 对应铠甲走路 | **1～8 高度几乎全不同**（宽相同）。例：`1护头` `277×546` vs `277×542` |

**同宽不同高时的默认换算（侦探确认后施工用）**

脚在图底部、多出来的像素在头顶（头盔/裁切）时：

- `destPivot.x = srcPivot.x`（宽相同）  
- `destPivot.y = srcPivot.y * srcHeight / destHeight`（保持距底边像素不变）  
- `alignment` 仍写 `9`

若侦探发现是左右裁切或脚不在底边，禁止用此公式，改写入 OPEN。

Clip `ArmorIdle_DayLight.anim` 已引用 ArtRes 白天 png 的 guid（例 `Armor1` guid `2dd39777…`）。**改 meta 锚点即可生效，不要改 anim。**
