# 搭建新场景手册

面向关卡与场景搭建：说明**玩法场景里必须具备的对象与配置**、**如何从零接入一条可运行的加载链**，以及与 `README.md` / `project_context.md` 的分工。

---

## 1. 先回答常见疑问

| 疑问 | 结论 |
|------|------|
| 每个场景**必须**有什么？ | 见下文 [§3 场景内必备清单](#3-场景内必备清单)。核心是：根节点上挂**继承 `BaseGameSceneManager` 的场景管理器**、**`GameSceneManagerConfig` 资源**；若可走跑关卡，还需 **`Map` + `MapControlComponentGSM` 约定层级**。 |
| 有没有**模板场景**？ | **没有**单独的「空模板」工程菜单；推荐在 `Assets/GameRes/Scenes` 中**复制**与目标最接近的现有 `.unity`（例如纯 UI 向复制 `SelectClothesScene`，横版探索向复制 `ForestScene`），再改命名与引用。 |
| 有没有**场景生成器**？ | 当前仓库**未发现**一键生成关卡场景的 Editor 工具；`BaseGameSceneManager` 仅在运行时**按需创建缺失的 GSM 子模块**（见 `AddModule`），不会替你摆地图或生成 prefab。 |
| 关卡不知道怎么摆？ | 横版地图依赖 `Map` 组件约定的子物体命名（`Map.FindObject` 自动查找）；交互物、怪物等多通过 **`SceneEntityComponentGSM`** 与场景内实体脚本配合。建议先打开现有场景对照 Hierarchy。 |

**与文档的关系**：打包、AB、Resource Editor、Scenes in Build 菜单步骤见仓库根目录 [`README.md`](Packages/ExcelDataReader.3.7.0/README.md)；整体架构见 [`Assets/project_context.md`](Project_context.md)。

## 2. 运行时如何「认出」你的场景

1. **场景文件路径**由 `SceneAssetPath` 固定为：  
   `Assets/GameRes/Scenes/{场景名}.unity`  
   即：磁盘上的 `.unity` 文件名（不含扩展名）必须与代码里使用的**场景名字符串一致**。

2. **`SceneName` 常量**：在 `Assets/Scripts/Game/Static/Name/Res/SceneName.cs` 中为该场景增加 `public const string`，全项目统一引用，避免魔法字符串。

3. **加载入口**：`ChangeSceneComponentGM.LoadScene(LoadSceneArgs)` 内部使用  
   `GameFramework` 的 `SceneComponent.LoadScene(SceneAssetPath.GetSceneAssetPath(sceneName), ...)`。  
   新场景需按 `README.md` 加入 **Resource Editor / AB** 与 **Build Settings**（开发期可用菜单 `Game Framework/Scenes in Build Settings/All Scenes`）。

4. **场景管理器就绪**：场景加载后，根对象上的 `BaseGameSceneManager` 子类在 `Awake` → `Update` 中完成异步初始化，随后调用 `GameManager.Instance.OnGameSceneManagerReady(this)`。若根上**没有**合法的管理器脚本，全局 `GetGameSceneManager()` 会一直为空，玩法与 UI 中大量逻辑会失效。

## 3. 场景内必备清单

### 3.1 根节点：`*SceneManager`（继承 `BaseGameSceneManager`）

- **脚本**：新建类 `YourSceneManager : BaseGameSceneManager`，放在 `Assets/Scripts/Game/GameRuntime/GameSceneManager/Scene/...` 下与现有场景一致的分区中。
- **典型重写**（按需，非全部必填）：
  - `OnInit()`：里务必 `base.OnInit()`；常在此设置 `nowSceneName = SceneName.YourScene;`，并做存档数据、场景实体显隐等初始化（参考 `ForestSceneManager`）。
  - `OnInitAddModules()`：需要**额外** GSM 模块时 `base.OnInitAddModules()` 后再 `AddModule<T>()`（参考 `SelectClothesSceneManager` 增加 `SelectClothesComponentGSM`）。
  - `OnEnterScene()` / `OnExitScene()` / `OnShutDown()`：进出场音效、UI、剧情触发等。
  - `initAllSceneMonster()`：无怪物可空实现（如 `NewGameSceneManager`）。
- **配置引用**：在 Inspector 中为基类序列化字段挂载 **`GameSceneManagerConfig`**（`CreateAssetMenu`：`Assets/Create/Config/GameSceneManagerConfig`）。各字段含义见下表。

| `GameSceneManagerConfig` 字段 | 含义（与玩法强相关） |
|------------------------------|----------------------|
| `canMove` | 是否允许玩家移动类逻辑 |
| `canCreatePlayer` | 是否在本场景生成玩家；为 `false` 时跳过 `InitPlayer`（如纯 UI 或特殊演出场景） |
| `isPlayingScene` | 是否视为「游戏进行中」场景（部分系统会依赖） |
| `isFightingScene` | 为 `true` 时基类会尝试打开 `FightingPanel`；非战斗场景通常为 `false` 以关闭战斗 HUD |
| `canRaycast` | 是否允许场景射线交互 |
| `canSave` | 是否允许保存非默认位置等（与存档策略相关） |

### 3.2 `GameSceneManagerConfig` 资源

- 不同场景可使用不同 config 资产，便于在 Inspector 中调参而无需改代码。

### 3.3 可走跑关卡：`Map` + `MapControlComponentGSM`

基类 `OnInitAddModules` 会注册 `MapControlComponentGSM`，其依赖子物体上的 **`Map`** 组件。

- **`MapControlComponentGSM`**：作为 `BaseGameSceneManager` 的子物体存在（若不存在，`AddModule` 会创建空物体并挂上组件）；Inspector 中需指定 **`Map`** 引用。
- **`Map`**：负责边界、门、出生点等。`OnValidate` / `FindObject` 会按**固定子物体名称**查找（见 `Map.cs`），搭建时应保证 Hierarchy 名称一致，或在 Inspector 手动赋值。

**约定子物体名称（与 `Map.FindObject` 一致）**：

| 路径（相对挂 `Map` 的物体） | 用途 |
|----------------------------|------|
| `MapLeft` / `MapRight` | 地图左右半区根 |
| `MapLeft/LeftWall`、`MapRight/RightWall` | 墙体 |
| `MapLeft/LeftDoor`、`MapRight/RightDoor` | 带 `SceneChangeDoor` 的切场景门 |
| `DefaultBornPos` | 默认出生点 |
| `LeftBorn` / `RightBorn` | 从邻接场景进入时的左右出生点 |

若某一项缺失，`Map` 在 `Start` 中会 `Debug.LogWarning`，运行期可能出现玩家位置或门逻辑异常。

**可选**：`Map` 上可指定 `sceneEntityComponentGSM`，用于在门 `OnInit` 时注入场景实体管理（见 `Map.OnInit`）。

### 3.4 从上一场景进入的位置：`EnterPosConfig`

在 `BaseGameSceneManager` 的 Inspector 中配置 **`EnterPos`** 列表：

- `lastScene`：与 `ChangeSceneComponentGM.LastSceneName` 一致时表示「从该场景切过来」。
- `pos`：玩家落点。
- `DatePass`：经过该入口时推进的日期（`DateData.ThroughDate`）。

未匹配任何项时，回退到 **`MapControlComponentGSM.DefaultBornTsf`**。

### 3.5 其他对象与系统

- **摄像机、输入、剧情、实体**：由基类注册的多个 `*ComponentGSM` 驱动；一般**无需**在新场景里重复造轮子，除非该场景要新增子管理器（再 `AddModule`）。
- **怪物 / 场景 NPC**：通常由 `initAllSceneMonster` 与 `SceneEntityComponentGSM`、具体 `*Logic` 协作；新战斗场景需对照现有场景配置实体与数据类（如 `ForestSceneData`）。

## 4. 推荐搭建流程（复制改造法）

以下顺序可减少漏配。

1. **复制场景**  
   在 `Assets/GameRes/Scenes` 复制最接近的 `.unity`，重命名为目标场景名（与最终 `SceneName` 常量一致）。

2. **复制/新建 `GameSceneManagerConfig`**  
   按玩法勾选 `canCreatePlayer`、`isFightingScene` 等。

3. **替换根管理器脚本**  
   Hierarchy 根上原 `XxxSceneManager` 换成你的类，或改序列化引用；赋好 config。

4. **调整 `Map` 与美术布局**  
   保持 §3.3 命名约定，或手动拖拽引用补齐。

5. **代码登记**  
   - 新建 `YourSceneManager.cs` 并设置 `nowSceneName`。  
   - 在 `SceneName.cs` 增加常量。  
   - 在需要切入该场景的逻辑里调用 `LoadScene(new LoadSceneArgs { sceneName = SceneName.YourScene, ... })`。

6. **资源与构建**  
   按 [`README.md`](Packages/ExcelDataReader.3.7.0/README.md) 将场景与依赖资源纳入 AB / Resource Editor；用 **Scenes in Build** 菜单维护构建列表。

7. **进游戏验证**  
   - 能否加载且无报错。  
   - `GameManager.GetGameSceneManager()` 非空。  
   - 玩家出生点、门切场景、`FightingPanel` 显隐是否符合 `GameSceneManagerConfig`。

## 5. 替代方案说明

| 做法 | 适用 | 注意 |
|------|------|------|
| **复制现有场景改**（推荐） | 绝大多数新关卡 | 记得改掉旧场景的专属引用（剧情 ID、存档类型、仅本图有效的物体）。 |
| **从空场景手搓** | 极简演出、实验 | 必须手动补齐 §3 全部链条，工作量大，易漏 `Map` 层级与 config。 |
| **`canCreatePlayer = false`** | 无玩家控制的界面场景 | 仍需 `BaseGameSceneManager` 以便系统统一生命周期；视情况精简 `Map`。 |
