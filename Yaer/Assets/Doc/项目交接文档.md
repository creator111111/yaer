### 1.3 项目启动方式

**Build Settings 里正式打包只挂一个场景：**

- `Assets/GameRes/Scenes/InitScene.unity`（`EditorBuildSettings.asset` 当前仅此一条）

启动链（Game Framework Procedure）：

1. 打开工程 → 用 Unity 2020.3.48f1 打开 `Yaer` 文件夹。
2. **编辑器日常开发**：菜单 `Game Framework / Scenes in Build Settings / All Scenes`，把 `Assets/GameRes/Scenes` 下全部场景写进 Build Settings（否则 `LoadScene` 会失败）。
3. Play：**必须从 InitScene 启动**（不要直接 Play 关卡场景当正式流程）。
4. `ProcedureLaunch` → `ProcedurePreload`（打开 Init 界面）→ 切 **`StartScene`** → `ProcedureMenu`（主菜单）→ 真正进局 `ProcedureGame`。

| 角色 | 场景路径 | 常量 |
|------|----------|------|
| 首场景 / 启动 | `Assets/GameRes/Scenes/InitScene.unity` | `SceneName.InitScene` |
| 主菜单场景 | `Assets/GameRes/Scenes/StartScene.unity` | `SceneName.StartScene` |
| 新游戏开场 | `Assets/GameRes/Scenes/NewGameScene.unity` | `SceneName.NewGameScene` |
| 当前主推可玩村 | `Assets/GameRes/Scenes/Village_KenMuNi1.unity` | `SceneName.Village_KenMuNi1` |

代码锚点：

- `Assets/Scripts/Game/GameRuntime/Procedure/ProcedureLaunch.cs`
- `Assets/Scripts/Game/GameRuntime/Procedure/ProcedurePreload.cs`（硬编码切 `StartScene`）
- `Assets/Scripts/Game/Static/Name/Res/SceneName.cs`

编辑器可按 ESC 跳过 Init 展示（`InitFormLogic`）。开发工具「跳过开头」：`Editor / GameManagerTool`（快捷键 Ctrl+G）。

### 1.4 Windows 打包方法

**有自定义构建脚本，不是纯手动 File → Build。** 以工程根 `README.md` 为准：

1. **先构建 AssetBundle**（见第 2.3 节）。
2. 菜单 **`Game Framework / Scenes in Build Settings / Default Scenes`**  
   → 只保留 `InitScene`（与 `BuildSettings.xml` 一致）。其它可玩场景走 AB，不进 Player Build。
3. `File / Build Settings` → 平台 **PC, Mac & Linux Standalone** → Target **Windows** → Architecture **x86_64** → **Build**。
4. 打完后若要继续开发：菜单 **`Game Framework / Scenes in Build Settings / All Scenes`**。

脚本位置：

| 用途 | 路径 |
|------|------|
| Default / All Scenes 菜单 | `Assets/Scripts/GameFramework/Editor/GF/Misc/BuildSettings.cs` |
| Default 场景配置 | `Assets/Scripts/GameFramework/Configs/BuildSettings.xml` |
| AB 路径配置类 | `Assets/Editor/GFAssetBundleSettings/GFAssetBundlesSettings.cs` |

当前 `EditorBuildSettings` 已是 Default 状态（仅 InitScene）。打包前请确认 StreamingAssets 里已放入对应平台 AB。

**没有**独立的 Jenkins / 命令行构建脚本；也**没有**命令行参数解析（业务代码未使用 `GetCommandLineArgs`）。

### 2.3 资源管理（AssetBundle）

**运行时动态资源走 Game Framework AB，不是 Addressables 主路径**（工程虽有 Addressables 配置对象引用，主流程是 GF Resource）。

编辑器默认 **`EditorResourceMode = true`**（`GameFramework.prefab`），Play 时直接从 AssetDatabase 加载，**不必每次打 AB**。出包必须关编辑器资源模式并打 AB。

#### 制作流程（与 README 一致）

1. 资源放到 `Assets/GameRes/`。
2. 菜单 **`Game Framework / Resource Tools / Resource Editor`**：把新资源勾进 AB。
3. 未识别类型：改 `Assets/Editor/GFAssetBundleSettings/xml/ResourceEditor.xml` 的 TypeFilter。
4. 菜单 **`Game Framework / Resource Tools / Resource Builder`** 构建。
5. 把导出目录里 **目标平台** 的包 **复制到 `StreamingAssets`**。

#### 配置与脚本位置

| 文件 | 作用 |
|------|------|
| `Assets/Editor/GFAssetBundleSettings/xml/ResourceCollection.xml` | AB 资源集合 |
| `Assets/Editor/GFAssetBundleSettings/xml/ResourceEditor.xml` | 扫描根 = `Assets/GameRes` |
| `Assets/Editor/GFAssetBundleSettings/xml/ResourceBuilder.xml` | 构建参数 |
| `Assets/Editor/GFAssetBundleSettings/GFAssetBundlesSettings.cs` | 上述 XML 路径 Attribute |

`ResourceBuilder.xml` 现网要点：

- `Platforms = 2` → **Windows64**（`1 << 1`）
- `InternalResourceVersion = 2`
- 压缩：LZ4 类（`AssetBundleCompression=1`）
- **`OutputDirectory` 仍写死为旧机路径 `F:/Yaer/yaer/Yaer/Assetbundles`** —— 接手后必须在 Resource Builder 窗口改成本机路径
- `ForceRebuildAssetBundleSelected = True`

#### 加载方式

```
ResComponentGM.LoadAsset<T>(assetName)
  → ResourceComponent.LoadAsset
  → 编辑器：EditorResourceHelper
  → 真机：StreamingAssets 中的 Package 模式 AB
```

失败日志：`Log.Error("加载资源失败:{0}", assetname)`。对话 Prefab 加载失败常见原因是 **Prefab 未落盘 / guid 断链**，不是 ResMgr 本身（见 0831 门口对白报告）。

**本项目没有完整热更新管线。** `ResourceMode` 支持 Updatable，但 Builder 当前是 Package 输出，没有版本服务器。
