## 沟通摘要

### ① 结论一句话

**编辑中数字跟手显示；失焦 / Enter / 切商品 / 决定后再按上限钳回。买卖同一套时序。**

### ② 原因（通俗）

以前每按一个键就立刻按上限改数字，满堆叠时上限是 0，所以边输边变 0，像坏了。现改成打字随便打，提交时再保险。

### ③ 用户检查清单

| # | 步骤 | 期望 |
|---|------|------|
| 1 | 买：输入 1、2、5… | **编辑中显示与键入一致**，不强制归 0 |
| 2 | 失焦 / Enter / 点其他商品 | 超限才调回 max；合法数保留 |
| 3 | held=10 生命球 | 编辑中可暂显示 1；**提交后**变 0 + Console「该道具已满」；`[ShopBuyMax] … stackRoom=0 max=0` |
| 4 | held&lt;10 且钱够 | Commit 后留下 1～可买上限；决定可买 |
| 5 | 卖 | 编辑中不误钳；提交 ≤ 持有 |
| 6 | 贴提交瞬间 | `[ShopBuyMax]` 一行（勿用编辑刷屏冒充） |

### ④ 程序补充

| 路径 | 改动 |
|------|------|
| `ShopBuyRowQuantityInput.cs` | 编辑锁：`ApplyValueChangedPipeline` 聚焦中不 `TryClamp`；`CommitQuantity`；Begin 前 Commit 他行 |
| `ShopFormLogic.cs` | Reclamp 跳过编辑行；决定前 Commit 全部；Commit 时 `[ShopBuyMax]` + 钳回 Warning |
| `ShopDebugLogger.cs` | Commit 钳回文案（堆叠满 / 金币不足 / 超上限 / 卖超持有） |

**保留**：`ResolveBuyMaxQuantity` 公式（B1）。  
**禁做**：关联合钳制；只改买不改卖；编辑路径打满 `[ShopBuyMax]`。
